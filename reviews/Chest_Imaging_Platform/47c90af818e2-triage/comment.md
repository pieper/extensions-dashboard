- [`LICENSE:14-16`](https://github.com/acil-bwh/SlicerCIP/blob/47c90af818e2ef4bdd4420d9a7b2fec7307afe23/LICENSE#L14-L16): The BSD-3 text does grant redistribution, so distribution permission exists; however the clause is left as a template placeholder, which weakens the no-endorsement clause and looks unfinished to downstream redistributors. Separately, the committed WinSCP binaries are GPL-licensed third-party tools whose license/notice is not included in the repo. Replace {organization} with 'Brigham and Women's Hospital' (or the copyright holder) and remove the GPL binaries or add their notices.
- [`Scripted/CIP_/CIP/logic/Util.py:101-102`](https://github.com/acil-bwh/SlicerCIP/blob/47c90af818e2ef4bdd4420d9a7b2fec7307afe23/Scripted/CIP_/CIP/logic/Util.py#L101-L102): create_directory gives 0777 to every directory it makes (e.g. the Slicer settings/CIP data folder via SlicerUtil.getSettingsDataFolder), and AutoUpdateWidget.py:85 does the same for its clone target under the temp path. On multi-user machines this lets other local users place or replace files that CIP later reads or (in the auto-update path) copies into the extension. Create directories with default 0700/0755 permissions instead of chmod 0777.
- [`Scripted/CIP_/CIP/ui/Resources/SSH/WinSCP.ini:4`](https://github.com/acil-bwh/SlicerCIP/blob/47c90af818e2ef4bdd4420d9a7b2fec7307afe23/Scripted/CIP_/CIP/ui/Resources/SSH/WinSCP.ini#L4): Scripted/CIP_/CIP/ui/Resources/SSH/ contains WinSCP.com (293 KB) and Scripted/attic/CIP_GetImage/CIP_GetImage_Resources/WinSCP.exe (~10 MB), third-party binaries of unknown version/provenance, plus an SSH config template inviting users to paste a private key. They are not listed in any built CMakeLists (Scripted/CMakeLists.txt does not add attic modules and Scripted/CIP_/CMakeLists.txt's resource list has no SSH entry), so they are not installed with the extension, but they bloat the source and normalise transferring credentials/patient data to remote SSH servers. Remove the committed binaries and the SSH template from the repository; if remote transfer is ever needed, depend on a documented tool and keep keys in the user's own store.
- [`SuperBuild/External_CIP.cmake:33-34`](https://github.com/acil-bwh/SlicerCIP/blob/47c90af818e2ef4bdd4420d9a7b2fec7307afe23/SuperBuild/External_CIP.cmake#L33-L34): The superbuild clones Slicer/ChestImagingPlatform at the moving branch 'develop' and the catalog also tracks 'develop'. Builds are not reproducible, and the CIP code that users run is not the code reviewed at commit 47c90af. The catalog's scm_url points to acil-bwh/SlicerCIP, but the CIP source repository is separate. Pin GIT_TAG to a specific commit hash and record the reviewed CIP revision. Consider noting the CIP repository in the catalog description.
- [`Scripted/attic/CIP_GetImage/CMakeLists.txt:9-13`](https://github.com/acil-bwh/SlicerCIP/blob/47c90af818e2ef4bdd4420d9a7b2fec7307afe23/Scripted/attic/CIP_GetImage/CMakeLists.txt#L9-L13): A 10 MB Windows executable is committed under the attic folder. Its GPL terms are not stated alongside it, and binaries in the repo are a distribution and maintenance concern. The attic module is not in Scripted/CMakeLists.txt, so it is not packaged. Its CMake file still lists the binary. Remove the binary from the repository or document its license. Keep binary tools out of the source tree and download them on demand instead.
- [`Scripted/CIP_/CIP_.py:14-23`](https://github.com/acil-bwh/SlicerCIP/blob/47c90af818e2ef4bdd4420d9a7b2fec7307afe23/Scripted/CIP_/CIP_.py#L14-L23): CIP_ does not inherit ScriptedLoadableModule/ScriptedLoadableModuleWidget, so it does not follow Slicer conventions and its hidden status depends on how the loader interprets a non-standard class; the widget also prints "ok" on setup. Every other CIP module depends on 'CIP' importable as a top-level package, which relies on Slicer putting the CIP_ module folder on sys.path rather than on anything this file does. Make CIP_ a normal ScriptedLoadableModule with parent.hidden = True, or move the CIP package to a location added explicitly and document the dependency.
- [`Scripted/CIP_LesionModel/CMakeLists.txt:7-19`](https://github.com/acil-bwh/SlicerCIP/blob/47c90af818e2ef4bdd4420d9a7b2fec7307afe23/Scripted/CIP_LesionModel/CMakeLists.txt#L7-L19): MODULE_PYTHON_SCRIPTS lists 'FeatureExtractionLib/__init__' and 'FeatureWidgetHelperLib/__init__' while the files on disk are __init__.py; ctkMacroCompilePythonScript will not find those paths, so the package inits may be omitted from the install tree and 'from FeatureWidgetHelperLib import *' fails at module load. This does not affect the catalog entry itself but can make one shipped module unusable. Use 'FeatureExtractionLib/__init__.py' and 'FeatureWidgetHelperLib/__init__.py' in MODULE_PYTHON_SCRIPTS.
