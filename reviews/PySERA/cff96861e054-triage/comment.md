- [`PySERA/PySeraCLI/PySeraCLIModule.py:130-132`](https://github.com/radiuma-com/SlicerPySERA/blob/cff96861e0541080592bc2be99cba02d8d72f837/PySERA/PySeraCLI/PySeraCLIModule.py#L130-L132): _load_default_params() returns the whole parameters.yaml, which contains a 'report' entry (PySERA/parameters.yaml:202-206) plus the top-level 'radiomics' and 'radiomics_meta' blocks. main() therefore builds params containing 'report' and passes it together with report=True, and also passes radiomics/radiomics_meta as unexpected keywords, so pysera.process_batch raises TypeError. Currently masked because the CLI module is not built. Only forward keys from the radiomics_meta block, and drop 'report' from params (or stop passing report=True explicitly).
- [`PySERA/PySera.py:312-315`](https://github.com/radiuma-com/SlicerPySERA/blob/cff96861e0541080592bc2be99cba02d8d72f837/PySERA/PySera.py#L312-L315): If no output folder is set, _make_output_csv creates ~/Desktop/output_result; the UI default is the relative path './output_result' (PySera.py:888), which resolves against Slicer's working directory. Files are then written to locations the user did not choose, which is contrary to the Slicer convention of writing to a user-selected or temporary folder. Default to a user-selected folder or slicer.app.temporaryPath, and refuse to run when the output folder is empty.
- [`CMakeLists.txt:12`](https://github.com/radiuma-com/SlicerPySERA/blob/cff96861e0541080592bc2be99cba02d8d72f837/CMakeLists.txt#L12): The PySERA extension installs 'pysera' (and potentially other deep learning packages or requirements) via pip at runtime, but declares NO extension dependencies (EXTENSION_DEPENDS "NA"). In particular, if deep features or models (such as ResNet/VGG/DenseNet) are used, PyTorch or other required packages might be pulled in without ensuring PyTorchUtils is declared as a build/extension dependency or handling PyTorch installation properly per Slicer guidelines. Declare appropriate extension dependencies (such as PyTorchUtils if deep learning features require PyTorch) and ensure dependencies are correctly configured.
- [`PySERA/PySera.py:867-872`](https://github.com/radiuma-com/SlicerPySERA/blob/cff96861e0541080592bc2be99cba02d8d72f837/PySERA/PySera.py#L867-L872): Inputs are file paths on disk rather than MRML volume/segmentation node selectors, and no parameter node is used, so the module state is not saved with the scene and users must export images and masks to NIfTI before running. This is a usability deviation from Slicer conventions rather than a defect. Offer node selectors (with an option to save to a temporary NIfTI) and store settings in a parameter node.
- [`PySERA/PySera.py:139-142`](https://github.com/radiuma-com/SlicerPySERA/blob/cff96861e0541080592bc2be99cba02d8d72f837/PySERA/PySera.py#L139-L142): If parameters.yaml is malformed or PyYAML is missing, the loader returns an empty dict with no logged reason.
