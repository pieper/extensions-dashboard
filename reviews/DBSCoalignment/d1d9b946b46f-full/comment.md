Please fix these before the extension can be merged:

- [`STNSegmenter/STNSegmenter.py:19`](https://github.com/IVarha/SlicerDBSCoalignment/blob/d1d9b946b46f05f6f40fd53305c84ac9e0e7c240/STNSegmenter/STNSegmenter.py#L19): Both `STNSegmenter/STNSegmenter.py` (lines 67-71) and `DBS_STN/DBSShiftPrediction.py` (lines 17-25 and 1742-1746) install PyTorch directly via `slicer.util.pip_install('torch')` (and also pull `torch` as a dependency of `dbs-pure-lib`, `torchio`, and `ANTsTorch`). Direct `pip_install('torch')` in Slicer's Python environment bypasses `PyTorchUtils` from the `SlicerPyTorch` extension, can install CPU-only or incompatible CUDA wheels, and can break other PyTorch-based extensions in Slicer. Add `PyTorch` to `EXTENSION_DEPENDS` in `CMakeLists.txt` and `build_dependencies` in the catalog entry, and use `PyTorchUtils.PyTorchUtilsLogic()` to check for and install PyTorch on demand rather than calling `slicer.util.pip_install('torch')`.
- [`CMakeLists.txt:12`](https://github.com/IVarha/SlicerDBSCoalignment/blob/d1d9b946b46f05f6f40fd53305c84ac9e0e7c240/CMakeLists.txt#L12): CMakeLists declares SlicerElastix and SlicerNetstim as dependencies, but the catalog entry has `build_dependencies: []`. The index will not build or ship the intended dependencies. The code also needs PyTorchUtils. Make `build_dependencies` in the catalog entry identical to `EXTENSION_DEPENDS`, and add PyTorchUtils.
- [`STNSegmenter/STNSegmenter.py:19`](https://github.com/IVarha/SlicerDBSCoalignment/blob/d1d9b946b46f05f6f40fd53305c84ac9e0e7c240/STNSegmenter/STNSegmenter.py#L19): When Slicer loads the module (even if the user never opens it), a missing `torch` is installed from PyPI instead of through PyTorchUtils. A missing `antspyx` is installed in the same way. This can alter or break the shared Slicer Python environment, and the downloads are large. PyTorchUtils is not declared as a dependency. Declare PyTorchUtils in `build_dependencies` and `EXTENSION_DEPENDS` and install torch through it. Move all pip installs into the module logic behind an explicit user confirmation. Do not run them at import time.
- [`STNSegmenter/STNSegmenter.py:35-40`](https://github.com/IVarha/SlicerDBSCoalignment/blob/d1d9b946b46f05f6f40fd53305c84ac9e0e7c240/STNSegmenter/STNSegmenter.py#L35-L40): On Linux x86_64 with Python 3.12 (Slicer 5.9/5.10), `_install_antspyx()`—which is called automatically at Slicer startup if `ants` is not yet installed—downloads a binary wheel (`antspyx-0.6.2-cp312-cp312-linux_x86_64.whl`) from an unverified personal/shared Box URL (`https://app.box.com/shared/static/mu1gy26t80oopbtv3mndl5yveb6s4431.whl`) into the shared system temp directory without any cryptographic hash verification or user consent, and immediately executes/installs it via `pip_install`. Downloading and executing unverified binary wheels from opaque file-sharing links without checksum validation poses a severe supply-chain and code-execution risk. Install official releases from PyPI (`slicer.util.pip_install("antspyx")`) or, if a custom wheel is strictly required, host it on a controlled release page with mandatory SHA-256 checksum verification before installation and only after explicit user consent.
