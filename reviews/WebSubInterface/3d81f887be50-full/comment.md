Please fix these before the extension can be merged:

- [`WebSubInterface/hub/Lib/routes/conference.py:61-72`](https://github.com/mbellehumeur/SlicerWebSub/blob/3d81f887be5063a6154bda396124983c31eb66d2/WebSubInterface/hub/Lib/routes/conference.py#L61-L72): The authenticated identity is discarded and host/attendee topics are accepted without ownership checks or participant consent. hub_request.py:45-59 expands a request to every conference participant, so an authenticated attacker can create a conference involving a victim and request the victim's local DICOM worklist or studies; the client returns patient names and publishes DICOM bytes to the request topic. Conference publish fan-out similarly forwards payloads to all listed attendees (publish.py:219-248). This bypasses OIDC topic isolation. Bind conference operations to the authenticated identity, require recipient authorization or consent before adding topics, and enforce per-request and per-payload access checks.
- [`WebSubInterface/python_client/src/hub_client/client.py:167-169`](https://github.com/mbellehumeur/SlicerWebSub/blob/3d81f887be5063a6154bda396124983c31eb66d2/WebSubInterface/python_client/src/hub_client/client.py#L167-L169): WebSubInterface.py imports ImageDisplayClient at module import; that imports hub_client, whose __init__ immediately imports this file. If aiohttp is absent in Slicer's Python, the entire module fails to load before the user can reach HubServer's Start button and its dependency confirmation. The separately installed python_client tree does not install its pip dependencies. Defer the client import until after a user-confirmed dependency check, or provide a supported dependency mechanism that makes aiohttp available before module import.
- [`WebSubInterface/hub/hub.py:261-264`](https://github.com/mbellehumeur/SlicerWebSub/blob/3d81f887be5063a6154bda396124983c31eb66d2/WebSubInterface/hub/hub.py#L261-L264): When the user starts the local Hub from Slicer (`HubServer.py:367`), `hub.py` is launched with only `--port`, so `--host` defaults to `0.0.0.0` (all network interfaces) and `HUB_AUTH_MODE` defaults to `mock` with `HUB_REQUIRE_AUTH=False`. In addition, when connected to a hub (local or cloud), `image_display_client_requests.py` responds to `status-request` events on the subscribed topic with `list_local_dicom_worklist_studies()` (which includes `PatientName`, `StudyDescription`, `StudyDate`, and `StudyInstanceUID` from `slicer.dicomDatabase`) and responds to `dicom-request` events by reading and publishing the raw DICOM files from `slicer.dicomDatabase` (`local_dicom_export.py`). While the UI shows a PHI warning when creating a conference, connecting to a shared/cloud hub or starting the local hub on `0.0.0.0` can expose local DICOM database metadata and images to other subscribers on the same topic or local network without a prompt before Connect or Start. Bind the local embedded Slicer hub to `127.0.0.1` by default in `HubServer.py` (e.g., passing `--host 127.0.0.1` unless the user explicitly opts in to LAN listening), and require explicit user confirmation before connecting the Image Display Client or allowing remote `dicom-request` / `status-request` access to `slicer.dicomDatabase`.
- [`WebSubInterface/CMakeLists.txt:4-13`](https://github.com/mbellehumeur/SlicerWebSub/blob/3d81f887be5063a6154bda396124983c31eb66d2/WebSubInterface/CMakeLists.txt#L4-L13): `WebSubInterface/Lib/HubServer.py` imports `from .spa_download import (...)` at module import time (lines 23-30), which is triggered when `WebSubInterface.py` imports `HubServerWidget` at Slicer startup. However, `Lib/spa_download.py` is omitted from `MODULE_PYTHON_SCRIPTS` in `WebSubInterface/CMakeLists.txt` (and there is no `install(DIRECTORY Lib ...)` rule). As a result, an installed package built by CMake will not include `Lib/spa_download.py`, causing `WebSubInterface` to fail to load with `ModuleNotFoundError: No module named 'Lib.spa_download'`. Add `Lib/spa_download.py` to `MODULE_PYTHON_SCRIPTS` in `WebSubInterface/CMakeLists.txt`.
- [`WebSubInterface/Lib/ImageDisplayClient.py:15-17`](https://github.com/mbellehumeur/SlicerWebSub/blob/3d81f887be5063a6154bda396124983c31eb66d2/WebSubInterface/Lib/ImageDisplayClient.py#L15-L17): `WebSubInterface.py` imports `Lib.ImageDisplayClient` at module import time (Slicer startup), which imports `hub_client`, which in turn executes `import aiohttp` at the top level (`WebSubInterface/python_client/src/hub_client/client.py:167`). `aiohttp` is not bundled in Slicer's standard Python environment and is only installed when the user clicks the local Hub "Start" button (`_ensure_hub_deps()` in `Lib/HubServer.py`). On a fresh Slicer installation, `WebSubInterface` will fail to import at startup before the user can open the module or trigger dependency installation. Furthermore, if a user only uses the "Image Display Client" section with a cloud hub and never starts a local hub, nothing prompts to install `aiohttp`. Defer importing `hub_client` and `image_display_client_hub` until the user clicks Connect (or enters the module), and ensure `aiohttp` is checked and installed (with user confirmation via `slicer.util.confirmYesNoDisplay`) before connecting the Image Display Client as well as before starting the local Hub.

Smaller suggestions:

- [`WebSubInterface/hub/Lib/oauth_tokens.py:422-427`](https://github.com/mbellehumeur/SlicerWebSub/blob/3d81f887be5063a6154bda396124983c31eb66d2/WebSubInterface/hub/Lib/oauth_tokens.py#L422-L427): In OIDC mode HUB_REQUIRE_AUTH is always true, and any valid bearer token is accepted as an admin without checking an admin role, even when a separate admin token is configured. Consequently any authenticated user can read all users' subscription and audit contexts through /api/hub/admin/snapshot or reset all sessions via /api/admin/reset (routes/admin.py:78-119, 133-148). Require an explicit admin authorization claim or the configured admin secret for privileged endpoints, separately from ordinary user authentication.
- [`WebSubInterface/Lib/repo_paths.py:23-35`](https://github.com/mbellehumeur/SlicerWebSub/blob/3d81f887be5063a6154bda396124983c31eb66d2/WebSubInterface/Lib/repo_paths.py#L23-L35): `ensure_monorepo_import_paths()` is called at the top level of `WebSubInterface.py` during Slicer startup and prepends `WebSubInterface` (which contains a top-level `Lib/` package) and `image_display/lib` directly to `sys.path[0]`. Note that in `WebSubInterface.py`, `from Lib.repo_paths import ...` relies on Slicer adding the scripted module directory to `sys.path`, which exposes the generic top-level package name `Lib` across Slicer's shared Python environment and can collide with other Slicer modules that use a `Lib` subdirectory. Namespace the helper libraries under a module-specific package name (e.g., `WebSubInterfaceLib`) rather than a generic `Lib` package and flat `sys.path` entries.
- [`WebSubInterface/Lib/HubServer.py:33-40`](https://github.com/mbellehumeur/SlicerWebSub/blob/3d81f887be5063a6154bda396124983c31eb66d2/WebSubInterface/Lib/HubServer.py#L33-L40): hub.py unconditionally imports oauth_tokens, which imports jwt and PyJWKClient at module import (oauth_tokens.py:14-15). When PyJWT is not already installed, accepting the offered package installation still leaves the hub subprocess unable to start. Include PyJWT with its needed crypto support in the confirmed dependency check and test on a clean Slicer environment.
