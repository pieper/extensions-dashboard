Please fix these before the extension can be merged:

- [`WebSubInterface/hub/Lib/routes/conference.py:61-72`](https://github.com/mbellehumeur/SlicerWebSub/blob/cf9a93425b0d5139afa583b18c4f720879283b41/WebSubInterface/hub/Lib/routes/conference.py#L61-L72): The route validates a bearer but does not bind hostTopic or attendees to that identity or require attendee approval. hub_request.py lines 44–60 expands requests to all conference topics, and the image display responds to status and DICOM requests. An authenticated user can create a conference including a victim topic and their own, then request the victim's worklist and DICOM data despite OIDC topic checks on ordinary subscription and publish. Bind conference mutations to the authenticated identity and require independently authenticated attendee consent before expanding cross-topic routing; test isolation across users.
- [`WebSubInterface/hub/hub.py:261-263`](https://github.com/mbellehumeur/SlicerWebSub/blob/cf9a93425b0d5139afa583b18c4f720879283b41/WebSubInterface/hub/hub.py#L261-L263): When the user clicks "Start" in the Hub section of the Slicer module (`HubServer.py` line 367: `proc.setArguments([script, "--port", str(port)])`), `hub.py` starts with its default `--host 0.0.0.0` and default mock authentication (`HUB_REQUIRE_AUTH=False`). This binds the FastAPI server on all network interfaces (LAN/Wi-Fi) rather than `127.0.0.1`, exposing the local hub, its stored payloads, and connected Slicer session to any host on the local network. Pass `"--host", "127.0.0.1"` by default when starting the local hub subprocess from `HubServer.py` (or add a "Bind to localhost only" checkbox enabled by default in the UI).
- [`WebSubInterface/CMakeLists.txt:4-13`](https://github.com/mbellehumeur/SlicerWebSub/blob/cf9a93425b0d5139afa583b18c4f720879283b41/WebSubInterface/CMakeLists.txt#L4-L13): `WebSubInterface/Lib/HubServer.py` imports `from .spa_download import (...)` at module import time (lines 23–30), which is triggered when `WebSubInterface.py` imports `HubServerWidget` (line 17). However, `Lib/spa_download.py` is omitted from `MODULE_PYTHON_SCRIPTS` in `WebSubInterface/CMakeLists.txt` and is not covered by the custom `install(DIRECTORY ...)` rules. In an installed package, importing `WebSubInterface` will fail with `ModuleNotFoundError: No module named 'Lib.spa_download'`, preventing the module from loading in 3D Slicer. Add `Lib/spa_download.py` to `MODULE_PYTHON_SCRIPTS` in `WebSubInterface/CMakeLists.txt`.
- [`WebSubInterface/Lib/HubServer.py:22-26`](https://github.com/mbellehumeur/SlicerWebSub/blob/cf9a93425b0d5139afa583b18c4f720879283b41/WebSubInterface/Lib/HubServer.py#L22-L26): WebSubInterface.py imports HubServer at module load, but WebSubInterface/CMakeLists.txt lines 4–13 omit Lib/spa_download.py and its directory install rules cover only hub, python_client, and image_display. An installed extension therefore raises ModuleNotFoundError before the module UI loads. Add Lib/spa_download.py to MODULE_PYTHON_SCRIPTS and test an installed package, not only a source checkout.
- [`WebSubInterface/python_client/src/hub_client/client.py:167`](https://github.com/mbellehumeur/SlicerWebSub/blob/cf9a93425b0d5139afa583b18c4f720879283b41/WebSubInterface/python_client/src/hub_client/client.py#L167): WebSubInterface.py imports ImageDisplayClient, which imports hub_client; its __init__.py imports this module. On a Slicer environment without aiohttp, module loading fails before the hub Start button can invoke the dependency confirmation in HubServer.py. Installing this extension therefore cannot bootstrap a missing dependency. Defer the client import until after an explicit dependency check and confirmation, or provide a supported dependency mechanism that makes it available before module import.
- [`WebSubInterface/image_display/lib/image_display_client_requests.py:125-132`](https://github.com/mbellehumeur/SlicerWebSub/blob/cf9a93425b0d5139afa583b18c4f720879283b41/WebSubInterface/image_display/lib/image_display_client_requests.py#L125-L132): Whenever the Image Display Client is connected to a hub (including the public cloud hubs `SLICER-HUB-CLOUD` and `SLICER-HUB-CLOUD-OIDC`), any peer on the same topic or in the same conference can send a `status-request` or `dicom-request`. `handle_status_request` automatically enumerates all patients and studies in `slicer.dicomDatabase` (`PatientName`, `StudyDescription`, `StudyDate`, `StudyInstanceUID`) via `list_local_dicom_worklist_studies()`, and `handle_dicom_request` exports and uploads the raw `.dcm` files from `slicer.dicomDatabase` for any requested `studyInstanceUID`. Although `ConferenceDialog.py` shows a warning when creating a conference from Slicer, no warning or opt-in is shown when simply connecting to a hub or when joining a conference started from the browser worklist. Add an explicit user opt-in checkbox (e.g., "Share local Slicer DICOM database with hub") or prompt before connecting to a remote hub or exporting local DICOM studies, rather than exposing `slicer.dicomDatabase` metadata and files by default upon connection.

Smaller suggestions:

- [`WebSubInterface/hub/Lib/oauth_tokens.py:422-427`](https://github.com/mbellehumeur/SlicerWebSub/blob/cf9a93425b0d5139afa583b18c4f720879283b41/WebSubInterface/hub/Lib/oauth_tokens.py#L422-L427): In authenticated mode any valid client JWT is accepted as admin, even when HUB_ADMIN_TOKEN is configured; no admin role is checked. The admin snapshot returns subscriptions and audit event contexts across topics, while the reset endpoint disconnects all clients. Thus an ordinary authenticated user can obtain other users' sensitive event data or disrupt their sessions. Require a separately authorized admin role or a mandatory admin secret for privileged endpoints, and test that ordinary OIDC users cannot access them.
- [`WebSubInterface/image_display/lib/image_display_client_load.py:178`](https://github.com/mbellehumeur/SlicerWebSub/blob/cf9a93425b0d5139afa583b18c4f720879283b41/WebSubInterface/image_display/lib/image_display_client_load.py#L178): Downloaded IDC and DICOM URL studies are imported into the user's DICOM database without copying the temporary files. clear_loaded_study removes that temporary directory at lines 433–446 when the study is closed or replaced, leaving database references to missing files; failures after import also remove the temporary directory. Copy imported files into persistent database storage, or use a separate temporary database and remove its records before deleting files.
