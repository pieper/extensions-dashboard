Suggestions for a later update:

- [`WebSubInterface/hub/Lib/publish.py:231-234`](https://github.com/mbellehumeur/SlicerWebSub/blob/838ce19d6cd87e23072d5f22a23ece40ed5867cf/WebSubInterface/hub/Lib/publish.py#L231-L234): Unlike the preceding ordinary delivery loop, this conference loop ignores subscribed event types and target actor, product, and subscriber filters. During a conference, a targeted message, including a DICOM transfer with downloadable payload IDs, is delivered to every connected subscriber on every participant topic rather than only the intended recipient. Apply event and all destination filters to conference delivery as well, with tests covering targeted binary messages and unrelated subscribers.
- [`WebSubInterface/hub/Resources/admin.html:2702-2706`](https://github.com/mbellehumeur/SlicerWebSub/blob/838ce19d6cd87e23072d5f22a23ece40ed5867cf/WebSubInterface/hub/Resources/admin.html#L2702-L2706): The privileged hub admin token is duplicated in the WebSocket query string. WebSocket handshake and reverse-proxy logs can retain that URL; anyone with access to such logs can reuse the token to obtain the admin snapshot, including audit data, or reset the hub. The local hub forwards subprocess output to Slicer's console. Authenticate the WebSocket without a reusable credential in the URL, for example using a short-lived single-use ticket or a securely authenticated post-connect exchange; ensure handshake logs cannot contain secrets.
- [`WebSubInterface/hub/Lib/hub_request.py:390-395`](https://github.com/mbellehumeur/SlicerWebSub/blob/838ce19d6cd87e23072d5f22a23ece40ed5867cf/WebSubInterface/hub/Lib/hub_request.py#L390-L395): Hub request responses include local DICOM worklist data, including patient names and IDs (local_dicom_worklist.py lines 116–139). The hub logs the first 200 characters of the serialized response at INFO level, potentially exposing those identifiers in Slicer console output or server logs without a separate warning about this logging. Log only counts, event types and correlation IDs; do not log serialized response payloads or patient-derived values by default.
- [`WebSubInterface/hub/Resources/admin.html:1391-1395`](https://github.com/mbellehumeur/SlicerWebSub/blob/838ce19d6cd87e23072d5f22a23ece40ed5867cf/WebSubInterface/hub/Resources/admin.html#L1391-L1395): The page stores the ordinary OIDC session token, but oauth_tokens.py lines 389–395 require HUB_ADMIN_TOKEN for privileged routes and explicitly reject ordinary client JWTs. In OIDC mode a rejected request clears the token and redirects to the same login rather than allowing entry of the separate admin token, so the dashboard cannot normally authenticate. Provide a safe way to supply or acquire the required admin authorization in OIDC mode and test the complete dashboard login flow.
