- [`AAL3BrainLabeling.py:74-77`](https://github.com/niyaziacer/SlicerAAL3BrainLabeling/blob/b08789e87142603744cc02512c79a9a8f480a74b/AAL3BrainLabeling.py#L74-L77): If the user does not pick a folder, all CSVs are written into Slicer's temporary directory, which is cleared on exit, so results silently disappear. The module also keeps no parameter node, so the selected input/output are not saved with the scene and cannot be scripted or restored, contrary to Slicer conventions. Require an explicit output folder (or warn when using the temp path) and store input/output in a vtkMRMLScriptedModuleNode parameter node.
- [`AAL3BrainLabeling.py:45`](https://github.com/niyaziacer/SlicerAAL3BrainLabeling/blob/b08789e87142603744cc02512c79a9a8f480a74b/AAL3BrainLabeling.py#L45): Appending the SlicerElastix module directory to sys.path mutates the shared interpreter state for the whole Slicer session, which can shadow other modules for unrelated code. The Elastix extension already exposes its Python module, so the fallback is normally unnecessary. Drop the sys.path manipulation and rely on the declared SlicerElastix dependency, reporting a clear error if the import fails.
- [`AAL3BrainLabeling.py:348-354`](https://github.com/niyaziacer/SlicerAAL3BrainLabeling/blob/b08789e87142603744cc02512c79a9a8f480a74b/AAL3BrainLabeling.py#L348-L354): README.md line 17 advertises 'Automatically computes the Asymmetry Index (AI)', but asymmetry() only prints to the Python console; nothing is written to outDir, so batch users lose the values. In addition, str.replace('_L', '_R') replaces every occurrence, which would corrupt names containing '_L' elsewhere. Write the AI values to a CSV in outDir (e.g. <vol>_AAL3_Asymmetry.csv) and derive the right-hemisphere name by replacing only the trailing suffix.
- [`AAL3BrainLabeling.py:293-295`](https://github.com/niyaziacer/SlicerAAL3BrainLabeling/blob/b08789e87142603744cc02512c79a9a8f480a74b/AAL3BrainLabeling.py#L293-L295): The return value of runSync is discarded, so a failed or cancelled N4 run leaves an empty output node that is then used as the registration input (line 174) and as the statistics volume (line 185). The user sees no error and gets plausible-looking but meaningless volumes/intensities. Similarly atlasMapping() (line 275) does not check that loadLabelVolume succeeded before calling atlasNode.GetDisplayNode(). Check the returned CLI node status (and that the output volume has data) and report failures with slicer.util.errorDisplay, aborting the pipeline; guard the atlas/color-table loads.

- [`AAL3BrainLabeling.py:280-281`](https://github.com/niyaziacer/SlicerAAL3BrainLabeling/blob/b08789e87142603744cc02512c79a9a8f480a74b/AAL3BrainLabeling.py#L280-L281): The documented way to reach the transform logic is slicer.modules.transforms.logic().hardenTransform(node); slicer.vtkSlicerTransformLogic() is not a module-level factory in the Slicer Python API. If it raises AttributeError, the pipeline dies after the atlas node has been added to the scene, leaving orphan nodes and no segmentation. Use slicer.modules.transforms.logic().hardenTransform(atlasNode) (or slicer.util.getModuleLogic('Transforms')).
