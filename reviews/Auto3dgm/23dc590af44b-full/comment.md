- [`meshviewer/web_view_mesh/README.md:1-3`](https://github.com/ToothAndClaw/SlicerAuto3dgm/blob/23dc590af44bdb2cafb460cdc1728cf5b43cce9d/meshviewer/web_view_mesh/README.md#L1-L3): The available repository has an MIT license only under Auto3dgm/auto3dgm_nazar, not at the extension root or in meshviewer. The bundled libraries' individual notices do not grant rights to these other files. Provide an extension-wide license covering the wrapper and author contributions, and identify and include the upstream license and any required notices for the forked viewer.
- [`meshviewer/web_view_mesh/viewer.py:20-30`](https://github.com/ToothAndClaw/SlicerAuto3dgm/blob/23dc590af44bdb2cafb460cdc1728cf5b43cce9d/meshviewer/web_view_mesh/viewer.py#L20-L30): The `meshviewer` CLI module starts an HTTP server bound to `""` (all network interfaces, `0.0.0.0:8000`) and overrides `SimpleHTTPRequestHandler.translate_path` with raw string concatenation (`self.ext_dir_path + path[len(self.ext_prefix):]` and `base_path + path`) without normalizing or sanitizing `..` segments. If a user runs the `meshviewer` CLI module (or calls `Auto3dgmLogic.serveWebViewer`), any host on the local network can read arbitrary files from the user's filesystem via path traversal requests to port 8000. Remove the unused `meshviewer` CLI module, or bind only to `127.0.0.1` and delegate path resolution to `SimpleHTTPRequestHandler.translate_path` (or verify `os.path.realpath` stays within the allowed directory).

Smaller suggestions:

- [`Auto3dgm/Auto3dgm.py:845-846`](https://github.com/ToothAndClaw/SlicerAuto3dgm/blob/23dc590af44bdb2cafb460cdc1728cf5b43cce9d/Auto3dgm/Auto3dgm.py#L845-L846): Clicking "View Phase 1 alignment" or "View Phase 2 alignment" calls `slicer.mrmlScene.Clear(0)` without asking the user for confirmation, destroying any existing nodes or unsaved work in the current Slicer scene. Confirm with the user before clearing the scene, or only remove nodes created by Auto3dgm.
- [`Auto3dgm/Auto3dgm.py:260-266`](https://github.com/ToothAndClaw/SlicerAuto3dgm/blob/23dc590af44bdb2cafb460cdc1728cf5b43cce9d/Auto3dgm/Auto3dgm.py#L260-L266): The selected FPS seed is stored but subsample passes an empty seed dictionary and the sampler calls random.seed() without that value. The maximum iteration slider and phase choice are likewise not read by the analysis; Run all always computes both phases and the optimizer uses a hard-coded 1000 iterations. Users can believe results are reproducible or configured when they are not. Pass each selected value through to the relevant algorithm, or remove unsupported controls; add tests showing the settings affect execution.
- [`Auto3dgm/Auto3dgm.py:720-729`](https://github.com/ToothAndClaw/SlicerAuto3dgm/blob/23dc590af44bdb2cafb460cdc1728cf5b43cce9d/Auto3dgm/Auto3dgm.py#L720-L729): rot aliases an array in corr.globalized_alignment['r']; changing elements in place alters the saved analysis state. A subsequent export or alignment based on that state can produce different or incorrect meshes and landmarks compared with the original result, particularly when rotations have nonzero z-axis cross terms. Copy each rotation before coordinate conversion and add a repeated-export consistency test.
- [`Auto3dgm/auto3dgm_nazar/analysis/correspondence.py:8-10`](https://github.com/ToothAndClaw/SlicerAuto3dgm/blob/23dc590af44bdb2cafb460cdc1728cf5b43cce9d/Auto3dgm/auto3dgm_nazar/analysis/correspondence.py#L8-L10): `from scipy import square` fails with `ImportError: cannot import name 'square' from 'scipy'` in SciPy >= 1.8 (bundled in current 3D Slicer versions), where deprecated NumPy ufunc re-exports were removed from the top-level `scipy` namespace. Calling `Auto3dgmLogic.correspondence()` (Phase 1, Phase 2, or Run all steps) immediately raises an ImportError when importing `auto3dgm_nazar.analysis.correspondence`. Replace `from scipy import square` with `from numpy import square` (or `np.square`).
- [`Auto3dgm/Auto3dgm.py:641-646`](https://github.com/ToothAndClaw/SlicerAuto3dgm/blob/23dc590af44bdb2cafb460cdc1728cf5b43cce9d/Auto3dgm/Auto3dgm.py#L641-L646): Exports always use fixed phase subdirectories and input-derived filenames. Existing directories are reused, and writers such as numpy.savetxt and the PLY writer write to the same paths without a collision check. Re-running or choosing a folder with prior results can silently destroy earlier files. Detect collisions and ask before overwriting, or create a fresh uniquely named run directory.
- [`Auto3dgm/CMakeLists.txt:21-25`](https://github.com/ToothAndClaw/SlicerAuto3dgm/blob/23dc590af44bdb2cafb460cdc1728cf5b43cce9d/Auto3dgm/CMakeLists.txt#L21-L25): `Auto3dgm/CMakeLists.txt` installs the entire `auto3dgm_nazar` directory into the runtime package, including a 16 MB test fixture (`Auto3dgm/auto3dgm_nazar/tests/fixtures/test.ply`) and a precompiled Python 3.6 Windows binary (`Auto3dgm/auto3dgm_nazar/lap_windows/_lapjv.cp36-win_amd64.pyd`). In addition, `meshviewer/CMakeLists.txt` installs the entire `web_view_mesh` directory including ~4 MB of unused textures and Python 3.6 `.pyc` files. Exclude `tests`, `lap_windows`, and `__pycache__` from the CMake `install(DIRECTORY ...)` rules and remove unused binary fixtures from the repository.
