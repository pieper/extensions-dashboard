Suggestions for a later update:

- [`BigImageViewer/BigImageViewer.py:1214`](https://github.com/gaoyi/SlicerBigImage/blob/15af77d3d348e9a3dce63131ca1a1ce9ddfcaea6/BigImageViewer/BigImageViewer.py#L1214): `installPreRequisites()` overwrites the process-wide CUDA_VISIBLE_DEVICES environment variable to "0". Any other component in the same Slicer process that later reads this variable (e.g. PyTorch-based extensions) sees a modified GPU selection caused by an unrelated module, and the value the user set is lost for the session. Remove the assignment; the module performs no GPU work (tensorflow/keras installs are commented out).
- [`BigImageViewer/BigImageViewer.py:121`](https://github.com/gaoyi/SlicerBigImage/blob/15af77d3d348e9a3dce63131ca1a1ce9ddfcaea6/BigImageViewer/BigImageViewer.py#L121): Every construction of BigImageViewerWidget forces the application layout to preset 6 and adds three permanent observers to the Red view's interactor. `cleanup()` only calls `removeObservers()` from VTKObservationMixin, so the interactor observers survive module destruction, keeping widget objects alive and firing callbacks (which touch `self.ui`) after the widget is gone; the layout change also persists even if the user never uses the module. Move layout switching and interactor observer setup into `enter()`/`setup()` only after a WSI is loaded, store the observer tags, and remove them in `cleanup()`.
- [`BigImageViewer/BigImageViewer.py:1005-1008`](https://github.com/gaoyi/SlicerBigImage/blob/15af77d3d348e9a3dce63131ca1a1ce9ddfcaea6/BigImageViewer/BigImageViewer.py#L1005-L1008): `onSegmentNucleiButton` passes 'outputEImage' and 'outputHImage', but NucleusSegmentation.xml has those outputs commented out; only `inputfileName`, `outputImageName`, `threshold` and `mpp` exist. The extra keys are either ignored (masking a partially removed feature) or cause the CLI node to be created with unknown parameters, and the two outputs also write to the same gray node, so the intent of the code cannot be satisfied. Drop the undeclared parameters and pass only the parameters the CLI actually declares.
- [`ColorDecomposition/ColorDecomposition.xml:7`](https://github.com/gaoyi/SlicerBigImage/blob/15af77d3d348e9a3dce63131ca1a1ce9ddfcaea6/ColorDecomposition/ColorDecomposition.xml#L7): The CLI descriptor for ColorDecomposition points to the template URL, so the in-app documentation link is wrong. Point it to the real documentation (README or Slicerscope page).
- [`ColorDecomposition/ColorDecomposition.cxx:95-106`](https://github.com/gaoyi/SlicerBigImage/blob/15af77d3d348e9a3dce63131ca1a1ce9ddfcaea6/ColorDecomposition/ColorDecomposition.cxx#L95-L106): License.txt is the Slicer BSD-style license, under which Part A §6 requires that contributions contain no reciprocally licensed code. The stain-matrix tables and cosx/cosy/cosz deconvolution in ColorDecomposition/ColorDecomposition.cxx are the same code as Landini's Colour Deconvolution plugin (GPL v3+), and NucleusSegmentation/include/TypeUtils.h is marked 'Author: tcpan', apparently from the cci/Pathology project. I could not verify the derivation or its license, so redistribution permission for these files is unclear. Add attribution/license notes for the third-party-derived deconvolution and segmentation code in the repository (e.g. a THIRD_PARTY file) and confirm the terms permit BSD-style redistribution.
