- [`DynamicPET/qSlicerDynamicPETModuleWidget.cxx:9297-9304`](https://github.com/DanieleDallOlio/SlicerDynamicPET/blob/b13eb6dc78149d147166a071512bab885e98d949/DynamicPET/qSlicerDynamicPETModuleWidget.cxx#L9297-L9304): The TAC save handler passes the chosen directory and default patient-based filename directly to this writer without checking for an existing file (lines 25647–25652 and 25749–25752). - [`DynamicPET/qSlicerDynamicPETModuleWidget.cxx:10713-10718`](https://github.com/DanieleDallOlio/SlicerDynamicPET/blob/b13eb6dc78149d147166a071512bab885e98d949/DynamicPET/qSlicerDynamicPETModuleWidget.cxx#L10713-L10718): When DICOM output is selected, the caller constructs deterministic filenames from the patient name, model and field (lines 22185–22205). Repeating an export into the same directory, including for a different study of the same patient, silently deletes the previous map; if writing fails after removal, the previous file is already lost. Detect collisions before export, ask for explicit replacement or generate unique filenames, and write to a temporary file before an atomic replacement.
- [`DynamicPET/qSlicerDynamicPETModuleWidget.cxx:9242-9254`](https://github.com/DanieleDallOlio/SlicerDynamicPET/blob/b13eb6dc78149d147166a071512bab885e98d949/DynamicPET/qSlicerDynamicPETModuleWidget.cxx#L9242-L9254): On parametric-map export, DPE_export_parametric_map calls this function; if highdicom is absent it downloads and installs a package into Slicer's shared Python environment without asking, even though the user selected an export rather than a package installation. Explain the dependency and request confirmation before installing it, as the Excel dependency helper does; handle missing dependencies without altering existing bundled packages.
- [`DynamicPET/Testing/Cxx/CMakeLists.txt:4-14`](https://github.com/DanieleDallOlio/SlicerDynamicPET/blob/b13eb6dc78149d147166a071512bab885e98d949/DynamicPET/Testing/Cxx/CMakeLists.txt#L4-L14): In `DynamicPET/Testing/Cxx/CMakeLists.txt`, `KIT_TEST_SRCS` is empty (the test source is commented out), which is then passed to `slicerMacroConfigureModuleCxxTestDriver`. - [`DynamicPET/qSlicerDynamicPETModule.cxx:58`](https://github.com/DanieleDallOlio/SlicerDynamicPET/blob/b13eb6dc78149d147166a071512bab885e98d949/DynamicPET/qSlicerDynamicPETModule.cxx#L58): `qSlicerDynamicPETModule.cxx` still has the cookiecutter template strings for `helpText()`, `acknowledgementText()` ("NIH grant NXNNXXNNNNNN-NNXN"), `contributors()` ("John Doe (AnyWare Corp.)"), and `categories()` ("Examples", whereas `CMakeLists.txt` and the catalog entry use "Quantification"). - [`DynamicPET/qSlicerDynamicPETModuleWidget.cxx:9182`](https://github.com/DanieleDallOlio/SlicerDynamicPET/blob/b13eb6dc78149d147166a071512bab885e98d949/DynamicPET/qSlicerDynamicPETModuleWidget.cxx#L9182): When a user exports a DICOM Parametric Map (`DPE_export_parametric_map`), `DPE_get_highdicom()` runs `slicer.util.pip_install("--no-deps highdicom")` without asking the user for confirmation first (unlike `DPE_prepare_excel_dependencies`, which prompts via `slicer.util.confirmYesNoDisplay`). Additionally, because `--no-deps` is used, if any of `highdicom`'s non-bundled dependencies (such as `pyjpegls` or newer `pillow`/`numpy` requirements depending on the PyPI release) are absent, importing or using `highdicom` may fail at runtime. Prompt the user with `slicer.util.confirmYesNoDisplay` before installing `highdicom` into Slicer's shared Python environment, just as `DPE_prepare_excel_dependencies` does for `pandas`/`openpyxl`/`xlsxwriter`.
