- [`PolycysticKidneySeg/SlicerPKDIALib/Widget.py:82-86`](https://github.com/conze/SlicerPolycysticKidneySeg/blob/3d9623a88225d8fcebe92922b09dcbe6bf91951e/PolycysticKidneySeg/SlicerPKDIALib/Widget.py#L82-L86): The .pth checkpoints are fetched from GitHub releases and loaded with torch.load (PKDIA.py:40). weights_only=True limits pickle-based code execution, but a corrupted or substituted download is still loaded without any SHA256 check, unlike the sample data in PolycysticKidneySeg.py:57/68 which do declare checksums. A truncated download also produces a confusing load error rather than a clear message. Add SHA256 checksums for PKDIAv1-weights.pth and PKDIAv2-weights.pth and verify after download, as already done for the sample volumes.
- [`PolycysticKidneySeg/SlicerPKDIALib/Widget.py:153-154`](https://github.com/conze/SlicerPolycysticKidneySeg/blob/3d9623a88225d8fcebe92922b09dcbe6bf91951e/PolycysticKidneySeg/SlicerPKDIALib/Widget.py#L153-L154): The pipeline reorients the volume with nibabel.as_closest_canonical (exam_genkyst_prod.py:23) and writes predictions in that canonical space, while the segmentation node is then given the original volume's geometry. If the loaded volume is not already in closest-canonical orientation, the resulting segments can be displayed misaligned with the image. SetReferenceImageGeometryParameterFromVolumeNode only sets the reference-geometry parameter, not the segment geometry. Either skip as_closest_canonical and work in the volume's own orientation, or resample the prediction back to the input volume geometry before creating the segmentation node.
- [`PolycysticKidneySeg/Testing/IntegrationTestCase.py:6`](https://github.com/conze/SlicerPolycysticKidneySeg/blob/3d9623a88225d8fcebe92922b09dcbe6bf91951e/PolycysticKidneySeg/Testing/IntegrationTestCase.py#L6): SlicerPKDIALib/__init__.py is empty, so `from SlicerPKDIALib import InstallLogic, SegmentationLogic, Widget` yields module objects. Calling `InstallLogic()` or `SegmentationLogic()` then raises TypeError. The test therefore cannot validate the pipeline, and the only test is also marked slow. Import the classes from their modules, e.g. `from SlicerPKDIALib.InstallLogic import InstallLogic`, and check the test runs in CI.
- [`PolycysticKidneySeg/PolycysticKidneySeg.py:30-35`](https://github.com/conze/SlicerPolycysticKidneySeg/blob/3d9623a88225d8fcebe92922b09dcbe6bf91951e/PolycysticKidneySeg/PolycysticKidneySeg.py#L30-L35): The module produces kidney segmentations used for ADPKD assessment, yet the help text and README have no statement that results are not for clinical decisions, and no validation or intended-use limits are given beyond a citation. Add a research-use-only disclaimer and the validation scope to the help text and README.
- [`README.md:35-39`](https://github.com/conze/SlicerPolycysticKidneySeg/blob/3d9623a88225d8fcebe92922b09dcbe6bf91951e/README.md#L35-L39): The repository LICENSE is Apache-2.0 for the code, but the PKDIAv1/v2 checkpoints distributed via GitHub releases and the Genkyst cohort data behind them have no explicit license or usage terms, and neither README.md nor the module helpText states that the output is for research use and not for clinical decision making. Users cannot tell what they may do with the weights. State the license/terms of the model weights explicitly (e.g. in README and next to the release assets) and add a research-use-only disclaimer to README and helpText.
- [`PolycysticKidneySeg/SlicerPKDIALib/Widget.py:136-145`](https://github.com/conze/SlicerPolycysticKidneySeg/blob/3d9623a88225d8fcebe92922b09dcbe6bf91951e/PolycysticKidneySeg/SlicerPKDIALib/Widget.py#L136-L145): Each failed check replaces errorMessage, so a user with no volume selected and missing weights only sees the weights message and may not understand why Apply does nothing useful. Also areWeightsFound() (SegmentationLogic.py:19-23) requires both T2 and CT checkpoints, so a user who only downloaded one modality is blocked from using it. Collect all failures into a list and display them together; check only the weights file for the selected modality.
- [`PolycysticKidneySeg/SlicerPKDIALib/SegmentationLogic.py:10-15`](https://github.com/conze/SlicerPolycysticKidneySeg/blob/3d9623a88225d8fcebe92922b09dcbe6bf91951e/PolycysticKidneySeg/SlicerPKDIALib/SegmentationLogic.py#L10-L15): Downloaded checkpoints land in <extension>/weights, i.e. inside the Slicer installation tree. On read-only or system-wide installs the mkdir/urlretrieve fails, and the files are not removed on uninstall. Slicer convention is to store such data in the user's settings/temporary directory. Store weights under slicer.util.settingsValue / a user-writable cache directory (e.g. slicer.mrmlScene temp dir or QStandardPaths AppDataLocation).
