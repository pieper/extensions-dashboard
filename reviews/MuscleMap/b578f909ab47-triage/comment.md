Suggestions for a later update:

- [`WholeBodyMuscleSegmentation/WholeBodyMuscleSegmentation.py:602-615`](https://github.com/MuscleMap/SlicerMuscleMap/blob/b578f909ab47f6033acfedc3ea6a900dde71f596/WholeBodyMuscleSegmentation/WholeBodyMuscleSegmentation.py#L602-L615): On first use the module (via the external mm_segment) downloads .pth weights from Zenodo and caches them under site-packages. Nothing in this repository verifies a hash or signature of the downloaded file, and PyTorch checkpoints are historically unpickled, so whatever the Zenodo record currently serves is executed/loaded inside the user's process. The download is announced in the progress dialog, so it is not concealed, but there is no integrity pinning. Record expected SHA-256 checksums for each published model version and verify them before use, and prefer torch.load(..., weights_only=True) in the upstream loader.
- [`WholeBodyMuscleSegmentation/WholeBodyMuscleSegmentation.py:373-379`](https://github.com/MuscleMap/SlicerMuscleMap/blob/b578f909ab47f6033acfedc3ea6a900dde71f596/WholeBodyMuscleSegmentation/WholeBodyMuscleSegmentation.py#L373-L379): onInstallClicked calls ensureDependencies synchronously, which runs multiple slicer.util.pip_install calls (possibly large downloads such as scipy and scikit-learn) on the Qt main thread. The UI can freeze for minutes, and no progress updates are shown beyond the static dialog. Run pip installs off the GUI thread or with explicit progress, and keep the progress dialog responsive.
- [`WholeBodyMuscleSegmentation/WholeBodyMuscleSegmentation.py:1088`](https://github.com/MuscleMap/SlicerMuscleMap/blob/b578f909ab47f6033acfedc3ea6a900dde71f596/WholeBodyMuscleSegmentation/WholeBodyMuscleSegmentation.py#L1088): On failure, runSegmentation keeps tempDir (containing the patient input volume) on disk and does not clean it up. Export writes _labels.csv and .ctbl next to the chosen path without a confirmation prompt, so existing files with those names are overwritten silently. Ask before overwriting existing sidecar files, and clean up or warn about the temp dir containing patient data after failures.
- [`WholeBodyMuscleSegmentation/Testing/Python/CMakeLists.txt:2`](https://github.com/MuscleMap/SlicerMuscleMap/blob/b578f909ab47f6033acfedc3ea6a900dde71f596/WholeBodyMuscleSegmentation/Testing/Python/CMakeLists.txt#L2): The only test hook is commented out (Testing/Python/CMakeLists.txt line 2), so nothing verifies segmentation or export. The help text and README do not state that output is research-only and not for clinical decisions. Add at least a smoke test (label-table parsing and export), and add a research-use disclaimer to the module help text.
- [`WholeBodyMuscleSegmentation/CMakeLists.txt:21-23`](https://github.com/MuscleMap/SlicerMuscleMap/blob/b578f909ab47f6033acfedc3ea6a900dde71f596/WholeBodyMuscleSegmentation/CMakeLists.txt#L21-L23): The module CMakeLists calls slicer_add_python_unittest on the module script, and Testing/Python/CMakeLists.txt has the corresponding line commented out. No test class (e.g. WholeBodyMuscleSegmentationTest) exists in WholeBodyMuscleSegmentation.py, so the generated test cannot instantiate the test class and the extension's test suite will report a failure on the build dashboard even though nothing is actually tested. Either add a minimal WholeBodyMuscleSegmentationTest (e.g. instantiate the widget logic / check getAvailableModels parsing) or drop the slicer_add_python_unittest call.
- [`WholeBodyMuscleSegmentation/WholeBodyMuscleSegmentation.py:113-117`](https://github.com/MuscleMap/SlicerMuscleMap/blob/b578f909ab47f6033acfedc3ea6a900dde71f596/WholeBodyMuscleSegmentation/WholeBodyMuscleSegmentation.py#L113-L117): The widget loads its logo from the module source directory ('MuscleMap.png' next to the .py), but MODULE_PYTHON_RESOURCES only installs Resources/Icons/MuscleMap.png and Resources/UI/....ui. In an installed extension build the plain MuscleMap.png is not copied next to WholeBodyMuscleSegmentation.py, so qt.QPixmap(logoPath) yields a null pixmap and the module shows a blank logo area. Use Resources/Icons/MuscleMap.png (which is installed) for the logo, or add the file to MODULE_PYTHON_RESOURCES.
- [`WholeBodyMuscleSegmentation/WholeBodyMuscleSegmentation.py:780-792`](https://github.com/MuscleMap/SlicerMuscleMap/blob/b578f909ab47f6033acfedc3ea6a900dde71f596/WholeBodyMuscleSegmentation/WholeBodyMuscleSegmentation.py#L780-L792): The constraints file protects numpy and torch only; scipy, scikit-learn and pandas are requested with no version bound. Slicer ships its own scipy/scikit-learn, and pip will leave them alone only as long as the installed versions satisfy the requirements pulled in transitively (e.g. by monai or scikit-learn). If a newer upstream requirement exceeds Slicer's version, pip upgrades those bundled packages in place, which is exactly the ABI-fragility the authors' own comment warns about for numpy/scipy. The environment is shared with every other Slicer extension. Add scipy, scikit-learn, pandas and other Slicer-bundled packages to the same constraints file (pinned to the installed versions), or use the SlicerWizard/PyTorch-extension-style helpers that only install what is missing.
