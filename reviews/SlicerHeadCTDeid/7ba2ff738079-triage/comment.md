Please fix these before the extension can be merged:

- [`HeadCTDeid/HeadCTDeid.py:598`](https://github.com/payabvashlab/SlicerHeadCTDeid/blob/7ba2ff738079fa8c98c57bf1507a5865419cd52f/HeadCTDeid/HeadCTDeid.py#L598): Any exception escaping process() -- a malformed CSV, a corrupt DICOM, an out-of-memory error, or a GUI error -- falls into a catch-all that unconditionally uninstalls and reinstalls PyTorch from the PyTorch index URL, pins python-gdcm==3.0.25 and pandas==2.2.3, and reinstalls transformers/pillow/pylibjpeg in the same Python environment Slicer and all other extensions share. PyTorch is not installed through the Slicer PyTorch extension (EXTENSION_DEPENDS is "NA"), and the user is never asked for confirmation; after this an unrelated extension or Slicer itself can break for the whole installation. Worse, the handler swallows the real error, so the user sees only a 'restart Slicer' message while the actual failure (and any partially written output) is unexplained. Remove the silent install block. Report the original exception to the user, and install optional dependencies only on an explicit user action with confirmation, using PyTorchUtils from the PyTorch extension for torch and without pinning packages Slicer bundles.

Smaller suggestions:

- [`HeadCTDeid/CMakeLists.txt:23-26`](https://github.com/payabvashlab/SlicerHeadCTDeid/blob/7ba2ff738079fa8c98c57bf1507a5865419cd52f/HeadCTDeid/CMakeLists.txt#L23-L26): A de-identification tool whose correctness is safety-relevant ships without any unit test (e.g. for the PS3.15 tag handling or UID remapping) and without sample data, so regressions in metadata scrubbing cannot be detected by the extension build. Add at least a self-test on a synthetic DICOM with known PHI tags and a small anonymized sample series.
- [`CMakeLists.txt:13`](https://github.com/payabvashlab/SlicerHeadCTDeid/blob/7ba2ff738079fa8c98c57bf1507a5865419cd52f/CMakeLists.txt#L13): The catalog entry has an empty build_dependencies list and the CMake project declares no dependency, yet the module needs PyTorch and transformers, and attempts to install them itself. Declaring the PyTorch extension dependency would make builds/installs consistent with the catalog entry and let the installer resolve torch correctly instead of the in-module pip logic. Add PyTorch to EXTENSION_DEPENDS and to the catalog entry's build_dependencies, and use PyTorchUtils rather than pip.
- [`HeadCTDeid/HeadCTDeid.py:988-989`](https://github.com/payabvashlab/SlicerHeadCTDeid/blob/7ba2ff738079fa8c98c57bf1507a5865419cd52f/HeadCTDeid/HeadCTDeid.py#L988-L989): HF_HOME/HUGGINGFACE_HUB_CACHE are written into the process environment (also in the worker at 1299-1300, 2351-2353), so a run changes cache locations for any other HuggingFace-using extension in the same Slicer process. It only takes effect when the non-default cache dir is configured, which limits the impact. Pass cache_dir= explicitly to from_pretrained/snapshot_download instead of mutating os.environ.
- [`README.md:108`](https://github.com/payabvashlab/SlicerHeadCTDeid/blob/7ba2ff738079fa8c98c57bf1507a5865419cd52f/README.md#L108): The README says the text-removal option 'removes the corresponding DICOM files', but the later Capabilities section and the code describe masking in place with no image discarded. Users relying on the README could expect different behavior from what they get. Update the README so the option description matches the masking behavior described at lines 65 and 48.
- [`HeadCTDeid/HeadCTDeid.py:2484`](https://github.com/payabvashlab/SlicerHeadCTDeid/blob/7ba2ff738079fa8c98c57bf1507a5865419cd52f/HeadCTDeid/HeadCTDeid.py#L2484): Only ValueError/FileNotFoundError are surfaced as user errors; every other failure (corrupt DICOM, pandas dtype issue, disk full, GPU OOM) is not reported, which conflicts with the rubric expectation that errors reach the user. Combined with the install block this can silently produce a batch the user believes is fine. Log and display the exception (traceback + processor._processing_errors), and let the per-examination summary report failures rather than masking them.
