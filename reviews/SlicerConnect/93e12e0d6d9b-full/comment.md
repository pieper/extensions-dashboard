Please fix these before the extension can be merged:

- [`SlicerConnectEditor/SlicerConnectEditor.py:339-343`](https://github.com/pka420/SlicerConnect/blob/93e12e0d6d9b3456e64779b89855355264e8346f/SlicerConnectEditor/SlicerConnectEditor.py#L339-L343): Despite the README claiming that all communication uses HTTPS and Secure WebSockets (WSS), `SlicerConnectEditorLogic` hardcodes an unencrypted `ws://` WebSocket endpoint (`ws://slicerconnect.from-delhi.net/collaboration/sessions`). In `connect()`, the user's authentication token is appended as a query parameter (`wsUrl = f"{self.WS_BASE_URL}/{sessionId}/ws?token={token}"`), and all segmentation voxel data and deltas are transmitted over this connection. This exposes both the bearer token and potentially sensitive medical segmentation data in cleartext over the network. Furthermore, the server URL is hardcoded in `SlicerConnectEditorLogic` and `SlicerConnectLoginLogic` rather than configurable by the user. Use `wss://` for WebSocket connections and read the server base URL from a user-configurable setting (matching `SlicerConnectServerURL` in `SlicerConnect.py`) rather than hardcoding an unencrypted `ws://` URL.

Smaller suggestions:

- [`SlicerConnectEditor/SlicerConnectEditor.py:691-699`](https://github.com/pka420/SlicerConnect/blob/93e12e0d6d9b3456e64779b89855355264e8346f/SlicerConnectEditor/SlicerConnectEditor.py#L691-L699): When the collaborative node does not exist, an incoming full sync adopts the first pre-existing segmentation, even if it belongs to another case. Lines 837–845 then call RemoveAllSegments on that node before importing the remote data, destroying unsaved local segmentations without confirmation; a failed import can also leave the adopted node empty. Create and track a dedicated session-owned node rather than adopting arbitrary scene nodes; stage and validate incoming data before replacing any existing data, with an explicit recovery path.
- [`SlicerConnect/SlicerConnect.py:487-490`](https://github.com/pka420/SlicerConnect/blob/93e12e0d6d9b3456e64779b89855355264e8346f/SlicerConnect/SlicerConnect.py#L487-L490): In `onDownloadSegClicked`, `local_path=Null` uses `Null` instead of Python's `None`. When the user clicks the "Download Segmentation" button, Python raises `NameError: name 'Null' is not defined` before the `try` block even executes, completely breaking segmentation downloads. Additionally, in the `finally` block (`if os.path.exists(local_path):`), if `download_segmentation` fails and `local_path` is `None`, `os.path.exists(None)` raises a `TypeError`. Initialize `local_path = None` and check `if local_path and os.path.exists(local_path):` in the `finally` block.
- [`SlicerConnectEditor/SlicerConnectEditor.py:365-369`](https://github.com/pka420/SlicerConnect/blob/93e12e0d6d9b3456e64779b89855355264e8346f/SlicerConnectEditor/SlicerConnectEditor.py#L365-L369): Each connection prints the complete bearer token to Slicer's Python output or application logs. Anyone receiving a troubleshooting log containing it can potentially impersonate the user; query-string tokens may also be retained in server or proxy access logs even after transport is secured. Never print credentials; authenticate with an authorization header or another mechanism that avoids URLs and logs.
- [`SlicerConnectLogin/SlicerConnectLogin.py:149-152`](https://github.com/pka420/SlicerConnect/blob/93e12e0d6d9b3456e64779b89855355264e8346f/SlicerConnectLogin/SlicerConnectLogin.py#L149-L152): After a successful login in `SlicerConnectLoginWidget.onLoginComplete`, the code calls `slicer.util.selectModule("CollaborativeSegmentation")`. However, the module included in this extension is named `SlicerConnect`, not `CollaborativeSegmentation`. This causes switching to the project hub module after login to fail. Change `"CollaborativeSegmentation"` to `"SlicerConnect"`.
- [`SlicerConnect/SlicerConnect.py:65-69`](https://github.com/pka420/SlicerConnect/blob/93e12e0d6d9b3456e64779b89855355264e8346f/SlicerConnect/SlicerConnect.py#L65-L69): In `BackendAPIClient._try_refresh_token()`, line 66 contains a stray `m` statement. When a 401 response triggers token refresh and the server responds with HTTP 200, executing line 66 raises `NameError: name 'm' is not defined`, which is caught by `except Exception` on line 80, causing token refresh to always fail. Remove the stray `m` on line 66.
- [`SlicerConnectEditor/SlicerConnectEditor.py:927-930`](https://github.com/pka420/SlicerConnect/blob/93e12e0d6d9b3456e64779b89855355264e8346f/SlicerConnectEditor/SlicerConnectEditor.py#L927-L930): `SlicerConnectEditorLogic.__init__()` instantiates `WebSocketHandler()`, which immediately calls `self.ensureDependencies()` and runs `slicer.util.pip_install("websocket-client")` without user confirmation. This happens whenever `SlicerConnectEditorWidget.setup()` runs (opening the module) or when `SlicerConnectEditorTest` instantiates `SlicerConnectEditorLogic()`. Installing packages into Slicer's shared Python environment when a module is opened or tested—without asking the user first—violates Slicer's environment rules. Prompt the user for confirmation (e.g., via `slicer.util.confirmOkCancelDisplay`) before calling `slicer.util.pip_install("websocket-client")`, and defer the check until the user actually initiates a connection rather than in `__init__`.
- [`SlicerConnectEditor/SlicerConnectEditor.py:257-265`](https://github.com/pka420/SlicerConnect/blob/93e12e0d6d9b3456e64779b89855355264e8346f/SlicerConnectEditor/SlicerConnectEditor.py#L257-L265): Opening the editor constructs WebSocketHandler and, if the package is missing, installs it into Slicer's shared environment without asking. Login similarly installs requests when missing. These are conditional on opening the modules, not module-import or startup installs. Explain the dependency and request confirmation before installation, with a way to decline.
