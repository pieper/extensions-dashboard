Suggestions for a later update:

- [`docs/index.md:35-37`](https://github.com/CSIM-Toolkits/AnomalousFiltersExtension/blob/043621ba83fde1f88b53fc11e5149f23f8752866/docs/index.md#L35-L37): The documentation markets the filters for downstream diagnostic-adjacent tasks (MS lesion segmentation, tissue classification) but neither README.md nor docs/index.md states that the output is for research use and not validated for clinical decision making. Users may treat the denoised volume as a validated preprocessing step. Add a short research-use-only / not-for-clinical-diagnosis statement to README.md and docs/index.md.
- [`AADImageFilter/itkAnisotropicAnomalousDiffusionImageFilter.hxx:172`](https://github.com/CSIM-Toolkits/AnomalousFiltersExtension/blob/043621ba83fde1f88b53fc11e5149f23f8752866/AADImageFilter/itkAnisotropicAnomalousDiffusionImageFilter.hxx#L172): `conductance` is declared in AADImageFilter.xml (lines 75-82) as a plain float with no `<constraints>` minimum, so a user can enter 0 (or a negative value). m_Conductance is then used as a divisor, producing inf/NaN that propagate into the output volume and are written to disk without any warning. Add a minimum constraint (e.g. 0.001) to the conductance parameter and/or guard against non-positive conductance in the filter.
- [`AADEPIData/AADEPIData.cxx:129-135`](https://github.com/CSIM-Toolkits/AnomalousFiltersExtension/blob/043621ba83fde1f88b53fc11e5149f23f8752866/AADEPIData/AADEPIData.cxx#L129-L135): Both branches do exactly the same thing, so the q-dependent conductance scaling that the DWI module applies (AADDiffusionWeightedData.cxx lines 201-207) is missing here. Either the branch is a leftover or the intended q-scaling was lost; in the latter case EPI results differ from the documented behaviour. Remove the redundant branch or restore the intended q-dependent scaling.
- [`README.md:3`](https://github.com/CSIM-Toolkits/AnomalousFiltersExtension/blob/043621ba83fde1f88b53fc11e5149f23f8752866/README.md#L3): README says the modules are for scalar MRI volumes and that DWI/DTI support is future work, but the CMake extension description and the AADDiffusionWeightedData module state DWI/DTI is already supported. Users may pick the wrong module or assume DWI support is absent. Align README, docs/index.md, and the CMake EXTENSION_DESCRIPTION on which modalities are supported and state validation status for DWI.
- [`AADImageFilter/AADImageFilter.cxx:180-184`](https://github.com/CSIM-Toolkits/AnomalousFiltersExtension/blob/043621ba83fde1f88b53fc11e5149f23f8752866/AADImageFilter/AADImageFilter.cxx#L180-L184): After the switch falls through, `main` returns EXIT_SUCCESS (line 193) even though no output file was produced. The same pattern is in IADImageFilter.cxx (lines 146-150) and AADDiffusionWeightedData.cxx (lines 290-294). Slicer will show the CLI as completed successfully while the output node stays empty, which is confusing rather than an error message. Return EXIT_FAILURE (and print to stderr) in the default case.
