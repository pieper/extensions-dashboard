Suggestions for a later update:

- [`AADDiffusionWeightedData/AADDiffusionWeightedData.cxx:214-217`](https://github.com/CSIM-Toolkits/AnomalousFiltersExtension/blob/043621ba83fde1f88b53fc11e5149f23f8752866/AADDiffusionWeightedData/AADDiffusionWeightedData.cxx#L214-L217): The same filter was connected to rescaler->GetOutput() at line 186. Reconnecting that rescaler to the filter output creates a cycle, so updating it can recurse rather than produce an output. AADEPIData/AADEPIData.cxx lines 114 and 142–145 constructs the same cycle. Use separate input and output rescalers, or disconnect a materialized intermediate image from its pipeline, and test both modules with representative 4D data.
- [`AADImageFilter/itkAnisotropicAnomalousDiffusionImageFilter.hxx:113-115`](https://github.com/CSIM-Toolkits/AnomalousFiltersExtension/blob/043621ba83fde1f88b53fc11e5149f23f8752866/AADImageFilter/itkAnisotropicAnomalousDiffusionImageFilter.hxx#L113-L115): In `AnisotropicAnomalousDiffusionImageFilter` (across `AADImageFilter`, `AADEPIData`, and `AADDiffusionWeightedData`) and `IsotropicAnomalousDiffusionImageFilter`, the filter implements `ThreadedGenerateData`, meaning ITK splits the output image into subregions across worker threads. Inside `ThreadedGenerateData`, the filter performs multiple diffusion iterations (`m_Iterations`) copying `aux` back to `output` within each thread's subregion without inter-thread synchronization between iterations, and reads boundary neighbors from adjacent thread regions concurrently while other threads are writing to `output`. This causes a data race along thread region boundaries and mathematically inconsistent multi-iteration results when `m_Iterations > 1` and multiple threads are used. Either override `GenerateData()` (single-threaded outer iteration loop invoking a single-step `ThreadedGenerateData` or `FiniteDifferenceImageFilter` pattern) or set `this->SetNumberOfWorkUnits(1)` in the constructor so that multi-iteration updates are synchronized across the whole image.
- [`AADDiffusionWeightedData/AADDiffusionWeightedData.cxx:157-161`](https://github.com/CSIM-Toolkits/AnomalousFiltersExtension/blob/043621ba83fde1f88b53fc11e5149f23f8752866/AADDiffusionWeightedData/AADDiffusionWeightedData.cxx#L157-L161): The loop's i is bounded by numberOfImages, counted from DWMRI_gradient metadata at lines 99–109, rather than by the VectorImage component count. A malformed or untrusted NRRD with more gradient keys than actual components makes this access cross pixel boundaries and eventually the image allocation, causing undefined behavior, potentially a crash or disclosure of process memory through derived output. Before indexing, require an exact match between valid, sequential gradient entries and img->GetNumberOfComponentsPerPixel(), and reject malformed gradient values; add malformed-input tests.
- [`AADImageFilter/Testing/Cxx/CMakeLists.txt:16-21`](https://github.com/CSIM-Toolkits/AnomalousFiltersExtension/blob/043621ba83fde1f88b53fc11e5149f23f8752866/AADImageFilter/Testing/Cxx/CMakeLists.txt#L16-L21): All four module `Testing/Cxx/CMakeLists.txt` files retain the template test invocation passing `--sigma 2.5`, which is not a valid CLI flag for any of the four modules (`AADImageFilter`, `IADImageFilter`, `AADEPIData`, `AADDiffusionWeightedData`). Running CTest will fail on argument parsing. Update the test command arguments in each module's `Testing/Cxx/CMakeLists.txt` to pass flags defined in the respective module XML (and appropriate 4D/DWI test inputs for `AADEPIData` and `AADDiffusionWeightedData`).
- [`AADImageFilter/AADImageFilter.cxx:97-105`](https://github.com/CSIM-Toolkits/AnomalousFiltersExtension/blob/043621ba83fde1f88b53fc11e5149f23f8752866/AADImageFilter/AADImageFilter.cxx#L97-L105): `AADImageFilter.xml` defines the `homoLevel` (`--homogeneity`) parameter for the Logistic edge function, and `itkAnisotropicAnomalousDiffusionImageFilter.h` defines `itkSetMacro(H, float)`, but `AADImageFilter.cxx` never passes `homoLevel` to `filter->SetH(homoLevel)`. Consequently, changes to "Homogeneity Level" in the GUI have no effect (it always uses the default `0.98`). Call `filter->SetH(homoLevel);` when configuring `filter` in `AADImageFilter.cxx`.
- [`AADImageFilter/itkAutomaticConductanceImageCalculator.hxx:94-99`](https://github.com/CSIM-Toolkits/AnomalousFiltersExtension/blob/043621ba83fde1f88b53fc11e5149f23f8752866/AADImageFilter/itkAutomaticConductanceImageCalculator.hxx#L94-L99): In `AutomaticConductanceImageCalculator::ComputeCanny`, `lowerBound` and `upperBound` are initialized with size `binsPerDimension` (256) instead of `MeasurementVectorSize` (1), whereas `size` has length `MeasurementVectorSize` (1). In ITK's `ImageToHistogramFilter`, the measurement vector length must match the number of components (1 for scalar images). Initialize `lowerBound(MeasurementVectorSize)` and `upperBound(MeasurementVectorSize)` instead of `binsPerDimension`.
- [`AADImageFilter/AADImageFilter.xml:45`](https://github.com/CSIM-Toolkits/AnomalousFiltersExtension/blob/043621ba83fde1f88b53fc11e5149f23f8752866/AADImageFilter/AADImageFilter.xml#L45): The CLI advertises this parameter, but AADImageFilter.cxx never calls the filter's SetH with homoLevel. Users selecting the logistic edge function get the hard-coded default regardless of their chosen homogeneity level. Pass homoLevel to filter->SetH and test that changing it affects the logistic result.
- [`AADImageFilter/AADImageFilter.cxx:118-121`](https://github.com/CSIM-Toolkits/AnomalousFiltersExtension/blob/043621ba83fde1f88b53fc11e5149f23f8752866/AADImageFilter/AADImageFilter.cxx#L118-L121): The filter operates on values rescaled to 0–255, but lines 110–111 cast those floating-point results to the original output type before this rescaling. For integer inputs, fractional values are discarded before expansion to the original range, reducing output precision; IADImageFilter uses the same ordering. Restore the original range in floating point and cast only as the final output step.
