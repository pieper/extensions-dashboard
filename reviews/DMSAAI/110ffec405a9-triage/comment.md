Suggestions for a later update:

- [`DMSAAI/DICOMDmsaaiPlugin.py:144-153`](https://github.com/4burakfe/SlicerDMSAAI/blob/110ffec405a958b8cbcbbf0c5bb3c11b63f5c0c0/DMSAAI/DICOMDmsaaiPlugin.py#L144-L153): Loading any DMSA series in the DICOM module silently takes the user out of the DICOM module, and DMSAAILogic.showLayout() then replaces the current layout with the fixed 2x3 layout (DMSAAI.py:1052-1062). The opt-out key `DMSAAI/SwitchToModuleAfterDICOMLoad` is documented in the README but has no UI in the module, so a user must edit QSettings by hand. Default the switch to off or expose a checkbox in the module's Advanced section; if the switch is kept, do not force the layout change on module entry.
- [`DMSAAI/DMSAAILib/networks.py:192-193`](https://github.com/4burakfe/SlicerDMSAAI/blob/110ffec405a958b8cbcbbf0c5bb3c11b63f5c0c0/DMSAAI/DMSAAILib/networks.py#L192-L193): download_weights fetches each .pth file from raw.githubusercontent.com with urllib.request.urlretrieve and no checksum or signature check, then loads it with torch.load. A compromised upstream repo or a network MITM would deliver arbitrary weights. The weights_only=True load limits code execution from pickle, but tampered weights could still change clinical outputs silently. Download is gated by user confirmation. Pin SHA-256 hashes for each weight file and verify before os.replace; state the source commit of the weights in the docs.
- [`DMSAAI/DMSAAI.py:411-423`](https://github.com/4burakfe/SlicerDMSAAI/blob/110ffec405a958b8cbcbbf0c5bb3c11b63f5c0c0/DMSAAI/DMSAAI.py#L411-L423): segment()/classify() call the networks synchronously from the button handler (no thread, no progress bar), so Slicer is frozen during CPU inference of up to 7 networks and looks hung. Additionally log() calls `slicer.app.processEvents()` for every message (DMSAAI.py:319-323), which re-enters the event loop from within a slot and can let the user click buttons while preprocessed state is half-updated. Run the analysis in a slicer.util.ProgressDialog worker (or disable/enable the buttons around a guarded event-process) and drop processEvents from log().
- [`DMSAAI/DMSAAI.py:1136-1141`](https://github.com/4burakfe/SlicerDMSAAI/blob/110ffec405a958b8cbcbbf0c5bb3c11b63f5c0c0/DMSAAI/DMSAAI.py#L1136-L1141): test_AnalysisSettings runs on the scene left over from the quantification test, and it writes to the user's real Qt settings (settings.save_analysis_settings), restoring only the values it captured. If the test is interrupted between save and restore, the user's saved preferences are replaced by the test's values. Call setUp() before every test and back up/restore the full QSettings group (or use a temporary settings scope).
- [`README.md:35-37`](https://github.com/4burakfe/SlicerDMSAAI/blob/110ffec405a958b8cbcbbf0c5bb3c11b63f5c0c0/README.md#L35-L37): The README explains installation and usage but gives no training cohort, validation metrics, failure modes or reference publication for the segmentation and classification networks, and the tests require an external DMSAAI checkout (Testing/test_pipeline.py:28-29) instead of shipping a small anonymised sample study. Users cannot judge the reliability of the printed findings such as "Probable Abnormal Cortical Uptake". Add a short model-provenance section (training data, reported accuracy, limitations) and ship or cite a small de-identified sample study.
- [`DMSAAI/DMSAAILib/networks.py:11-24`](https://github.com/4burakfe/SlicerDMSAAI/blob/110ffec405a958b8cbcbbf0c5bb3c11b63f5c0c0/DMSAAI/DMSAAILib/networks.py#L11-L24): The extension code is MIT, but about 140 MB of .pth weights are fetched at runtime from the author's DMSAAI repository and seven colour-map CSVs are bundled (DMSAAI/Resources/ColorMaps) whose origin is undocumented. I could not verify that the upstream repository grants permission to redistribute these artefacts, so distribution permission for the bundled/downloaded material is unconfirmed. State the license of the weights and of the colour maps in the README (and confirm the upstream DMSAAI repository carries a compatible license).
- [`README.md:61`](https://github.com/4burakfe/SlicerDMSAAI/blob/110ffec405a958b8cbcbbf0c5bb3c11b63f5c0c0/README.md#L61): The README says to click 'Clinical Evaluation', but the widget button is labeled 'AI-powered Evaluation'. Users following the docs will not find the button. Use the actual label 'AI-powered Evaluation' in the README.
- [`DMSAAI/DMSAAI.py:675-678`](https://github.com/4burakfe/SlicerDMSAAI/blob/110ffec405a958b8cbcbbf0c5bb3c11b63f5c0c0/DMSAAI/DMSAAI.py#L675-L678): `monai>=1.3` (REQUIREMENTS, DMSAAI.py:589-592) is an open-ended range, and pip_install resolves its transitive requirements into Slicer's shared environment, so a future MONAI release can pull different dependency versions (and its model API could change so the published weights no longer load). This affects all extensions sharing that Python once any user runs the install. Use an upper bound (e.g. `monai>=1.3,<1.6`), consider `pip_install(..., no_deps=True)` where feasible, and record the tested MONAI version in the README.
