- [`DCE_IDandPhaseSelect/Breast_DCEMRI_FTV_plugins1/gzip_gunzip_pyfuncs.py:165-170`](https://github.com/radiology-research/SlicerBreast_DCEMRI_FTV/blob/271ece80ce3db9cc79596ee5436dd5d44ed1a50c/DCE_IDandPhaseSelect/Breast_DCEMRI_FTV_plugins1/gzip_gunzip_pyfuncs.py#L165-L170): During phase selection for a mixed compressed/uncompressed DCE folder, this deletes each original uncompressed file even if 7-Zip fails, for example because of an invalid executable or a path containing spaces. The input exam can therefore lose its only copy of DICOM images or other files. Never modify source exams; decompress or copy into a private temporary directory, and verify subprocess success before using outputs.
- [`DCE_TumorMapProcess/DCE_TumorMapProcess.py:58-64`](https://github.com/radiology-research/SlicerBreast_DCEMRI_FTV/blob/271ece80ce3db9cc79596ee5436dd5d44ed1a50c/DCE_TumorMapProcess/DCE_TumorMapProcess.py#L58-L64): Both `DCE_IDandPhaseSelect.py` (lines 54-58) and `DCE_TumorMapProcess.py` (lines 83-89) execute `_pipEnsure` / `slicer.util.pip_install` at module top-level import time (when 3D Slicer starts up and discovers scripted modules, even if the user never opens the module) without user confirmation. Furthermore, `DCE_TumorMapProcess.py` line 84 calls `_importOptional('cv2', 'cv2')` (there is no valid PyPI package named `cv2`, and `pyproject.toml` lists `opencv-python` instead of `opencv-python-headless`, which bundles duplicate Qt libraries that conflict with Slicer's Qt). Move optional package imports and `pip_install` calls inside the widget `setup()` or logic `run()` methods after prompting the user for confirmation, and install `opencv-python-headless` rather than `cv2` or `opencv-python`.
- [`DCE_TumorMapProcess/Breast_DCEMRI_FTV_plugins2/gzip_gunzip_pyfuncs.py:163-170`](https://github.com/radiology-research/SlicerBreast_DCEMRI_FTV/blob/271ece80ce3db9cc79596ee5436dd5d44ed1a50c/DCE_TumorMapProcess/Breast_DCEMRI_FTV_plugins2/gzip_gunzip_pyfuncs.py#L163-L170): In `gzip_gunzip_pyfuncs.py` (present in both modules), `extractGZ` and `gunzipAllFilesDCE` construct shell commands by concatenating unescaped file paths and executing them with `os.system(...)`. If paths or filenames contain spaces or shell metacharacters, `os.system` will fail or execute unintended commands. In addition, lines 165-170 run `os.system(gzcmd)` and then unconditionally call `os.remove(fullfile)` on the user's original uncompressed DICOM files without checking whether `7z` succeeded, which permanently deletes user exam data if `7z` is missing or fails. Use Python's built-in `gzip` and `shutil` standard library modules to decompress `.gz` files directly into a temporary directory instead of invoking external `7z` via `os.system`, and never delete original files in the user's source exam directory.
- [`DCE_TumorMapProcess/DCE_TumorMapProcess.py:83-89`](https://github.com/radiology-research/SlicerBreast_DCEMRI_FTV/blob/271ece80ce3db9cc79596ee5436dd5d44ed1a50c/DCE_TumorMapProcess/DCE_TumorMapProcess.py#L83-L89): The helper calls pip when an import fails, so module discovery can change the shared environment before the user opens the extension. In particular cv2 is an import name, not the OpenCV distribution name, so a missing cv2 can cause module loading to fail; pyproject.toml instead declares opencv-python, which bundles Qt rather than the headless variant. Move dependency setup to a user-confirmed module action; use an appropriate Slicer-compatible headless OpenCV distribution and check requirements before proceeding.

Smaller suggestions:

- [`DCE_TumorMapProcess/Breast_DCEMRI_FTV_plugins2/ftv_plots.py:788-790`](https://github.com/radiology-research/SlicerBreast_DCEMRI_FTV/blob/271ece80ce3db9cc79596ee5436dd5d44ed1a50c/DCE_TumorMapProcess/Breast_DCEMRI_FTV_plugins2/ftv_plots.py#L788-L790): The JPEG and DICOM paths are derived from the path chosen in the report save dialog. Shell metacharacters in a chosen or externally supplied path can execute arbitrary commands, and spaces also break normal paths. The gzip helpers similarly concatenate exam paths into shell commands. - [`DCE_TumorMapProcess/Breast_DCEMRI_FTV_plugins2/gzip_gunzip_pyfuncs.py:108-113`](https://github.com/radiology-research/SlicerBreast_DCEMRI_FTV/blob/271ece80ce3db9cc79596ee5436dd5d44ed1a50c/DCE_TumorMapProcess/Breast_DCEMRI_FTV_plugins2/gzip_gunzip_pyfuncs.py#L108-L113): Module 2 calls this unconditionally after generating a report, including for uncompressed exams. Any pre-existing directory named gunzipped under the selected exam, including user-owned data never created by this extension, is recursively deleted without confirmation. Use a uniquely created temporary directory and only delete directories owned by the current run; never recursively delete a pre-existing exam folder.
- [`DCE_TumorMapProcess/Breast_DCEMRI_FTV_plugins2/ftv_plots.py:641-644`](https://github.com/radiology-research/SlicerBreast_DCEMRI_FTV/blob/271ece80ce3db9cc79596ee5436dd5d44ed1a50c/DCE_TumorMapProcess/Breast_DCEMRI_FTV_plugins2/ftv_plots.py#L641-L644): The report dialog asks for a PDF path, but the code derives a same-stem .txt path and opens it in truncating mode without checking whether it already exists. It also writes a same-stem JPEG; choosing a new PDF name can silently destroy unrelated existing sidecar files. Check all output paths before writing and ask for explicit overwrite confirmation, or create a new output directory.
