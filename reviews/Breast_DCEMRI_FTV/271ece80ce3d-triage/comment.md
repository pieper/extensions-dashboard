- [`CMakeLists.txt:7-12`](https://github.com/radiology-research/SlicerBreast_DCEMRI_FTV/blob/271ece80ce3db9cc79596ee5436dd5d44ed1a50c/CMakeLists.txt#L7-L12): The catalog entry points at https://github.com/radiology-research/SlicerBreast_DCEMRI_FTV, while homepage, icon and screenshot URLs point at rnadkarni2/SlicerBreast_DCEMRI_FTV. If the old repository is deleted or diverges, the Extension Manager shows broken icons/screenshots and users are sent to the wrong project. Point EXTENSION_HOMEPAGE/ICONURL/SCREENSHOTURLS at the radiology-research repository.
- [`DCE_TumorMapProcess/Breast_DCEMRI_FTV_plugins2/gzip_gunzip_pyfuncs.py:26`](https://github.com/radiology-research/SlicerBreast_DCEMRI_FTV/blob/271ece80ce3db9cc79596ee5436dd5d44ed1a50c/DCE_TumorMapProcess/Breast_DCEMRI_FTV_plugins2/gzip_gunzip_pyfuncs.py#L26): distutils was removed from the standard library in Python 3.12, which recent Slicer versions use. On such builds importing this plugin module raises ImportError, and because DCE_TumorMapProcess.py imports it at module level (line 101) the whole module fails to load. Use shutil.copytree(dirs_exist_ok=True) instead.
- [`DCE_TumorMapProcess/DCE_TumorMapProcess.py:268-270`](https://github.com/radiology-research/SlicerBreast_DCEMRI_FTV/blob/271ece80ce3db9cc79596ee5436dd5d44ed1a50c/DCE_TumorMapProcess/DCE_TumorMapProcess.py#L268-L270): Module 1 writes this pickle (DCE_IDandPhaseSelect.py lines 147-150) into the extension installation directory and module 2 unpickles it. Anyone able to write that file gets code execution in Slicer, and on a normal install the extension directory is read-only, so module 1 fails for non-admin users. It also stores patient-identifying exam metadata in the install tree. Store the workspace in a vtkMRMLScriptedModuleNode parameter node or in the user's temp/settings directory, and use JSON instead of pickle.
- [`DCE_TumorMapProcess/Breast_DCEMRI_FTV_plugins2/gzip_gunzip_pyfuncs.py:110-113`](https://github.com/radiology-research/SlicerBreast_DCEMRI_FTV/blob/271ece80ce3db9cc79596ee5436dd5d44ed1a50c/DCE_TumorMapProcess/Breast_DCEMRI_FTV_plugins2/gzip_gunzip_pyfuncs.py#L110-L113): After a report is written, deleteGunzipped removes exampath/gunzipped recursively. If the exam folder already contains a user-owned folder named 'gunzipped' with data, that data is deleted. The extension only creates this folder itself when the DICOMs are gzipped, so the risk is limited to unusual folder layouts.
- [`DCE_IDandPhaseSelect/DCE_IDandPhaseSelect.py:295`](https://github.com/radiology-research/SlicerBreast_DCEMRI_FTV/blob/271ece80ce3db9cc79596ee5436dd5d44ed1a50c/DCE_IDandPhaseSelect/DCE_IDandPhaseSelect.py#L295): A modal folder dialog is opened as soon as the module widget is constructed, so merely selecting the module in the module list pops a dialog and the rest of setup() runs against whatever the user picked (or an empty string). Combined with time.sleep(1) at line 239 and the long DICOM loading done on the GUI thread with processEvents, the UI is unresponsive during processing. Move folder selection to a button, and run the loading in a CLI logic call with a proper progress dialog.
- [`DCE_IDandPhaseSelect/Testing/Python/CMakeLists.txt:2`](https://github.com/radiology-research/SlicerBreast_DCEMRI_FTV/blob/271ece80ce3db9cc79596ee5436dd5d44ed1a50c/DCE_IDandPhaseSelect/Testing/Python/CMakeLists.txt#L2): The CTest registration for the module tests is commented out. The unittest class in DCE_IDandPhaseSelect.py (lines 822-866) only downloads 'FA.nrrd' from slicer.kitware.com and asserts nothing. There are no tests of the DICOM-parsing or FTV computation logic, so regressions are not caught.
- [`DCE_IDandPhaseSelect/DCE_IDandPhaseSelect.py:857-861`](https://github.com/radiology-research/SlicerBreast_DCEMRI_FTV/blob/271ece80ce3db9cc79596ee5436dd5d44ed1a50c/DCE_IDandPhaseSelect/DCE_IDandPhaseSelect.py#L857-L861): The only test is the Slicer template test: it downloads an unrelated FA volume over plain HTTP and asserts nothing about the extension, so it cannot catch regressions in the DCE loading or FTV logic. The Testing/Python/CMakeLists.txt files have their unittest lines commented out. Add a test that exercises the logic with a small anonymised DICOM series or synthetic volume.
- [`pyproject.toml:2-12`](https://github.com/radiology-research/SlicerBreast_DCEMRI_FTV/blob/271ece80ce3db9cc79596ee5436dd5d44ed1a50c/pyproject.toml#L2-L12): The Slicer extension build does not consume pyproject.toml, and the catalog entry has build_dependencies []. The real dependencies (nibabel, opencv, pynrrd, yattag, scikit-image, matplotlib) are therefore satisfied by silent pip installs at import time rather than by declared requirements, so the packaged extension has no reproducible dependency set. Declare the dependencies in the extension metadata / documentation and install them with explicit user consent.
