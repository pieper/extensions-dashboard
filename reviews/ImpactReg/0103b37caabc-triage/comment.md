Suggestions for a later update:

- [`ImpactReg/Testing/Python/CMakeLists.txt:2`](https://github.com/vboussot/SlicerImpactReg/blob/0103b37caabcb4431f7cc4570156b5b627dd4249/ImpactReg/Testing/Python/CMakeLists.txt#L2): `slicer_add_python_unittest(SCRIPT ${MODULE_NAME}.py)` registers ImpactReg.py as a CTest, but the module file contains no `ScriptedLoadableModuleTest` subclass (only module/widget classes), and the extra Python test is commented out. The registered test can therefore report nothing or fail as 'no test found', and no regression coverage exists for the argument construction that is the heart of the module. The video/tutorial manual workflow is the only validation. Add a ModuleTest class that at least instantiates the widget and, with small synthetic volumes, checks the generated `register`/`eval` argument lists.
- [`ImpactReg/ImpactReg.py:206`](https://github.com/vboussot/SlicerImpactReg/blob/0103b37caabcb4431f7cc4570156b5b627dd4249/ImpactReg/ImpactReg.py#L206): When a remote server is selected, the login token is appended as a plain CLI argument to the `impact-reg-konfai` process: any local user able to list processes (`ps`) on the same machine can read the credential, and it may also end up in log files or shell history. The same block also chooses the host that receives the fixed/moving images, so the destination is worth documenting explicitly for users. Pass the token through an environment variable or a stdin/temporary file with restrictive permissions instead of argv, and document in the UI that images are uploaded to the chosen host.
- [`ImpactReg/ImpactReg.py:304-306`](https://github.com/vboussot/SlicerImpactReg/blob/0103b37caabcb4431f7cc4570156b5b627dd4249/ImpactReg/ImpactReg.py#L304-L306): When no evaluation tab is active, `_export_node` can return None (nothing selected in the reference or moving selectors), yet the code unconditionally appends the value to the argument list, so `impact-reg-konfai eval -f None -m None` is constructed or the process launcher raises. The user gets a traceback instead of the 'select a reference image' message; also a failed `slicer.util.saveNode` is ignored and a non-existent filename is forwarded. Check for None (and the boolean return of `saveNode`) and report a clear message with `set_running(False)`, as the registration panel does for missing inputs.
- [`ImpactReg/ImpactReg.py:321`](https://github.com/vboussot/SlicerImpactReg/blob/0103b37caabcb4431f7cc4570156b5b627dd4249/ImpactReg/ImpactReg.py#L321): The evaluation export uses the manifest key as a filename base: `file_name = self._export_node(selector.currentNode(), key)` and then `self._work_dir / f"{base}.mha"`. Keys come from the preset `app.json` fetched from Hugging Face rather than from this repository, so a manifest containing `../` segments would make `slicer.util.saveNode`/`_write_volume` write outside the temporary folder. Impact is bounded by the fixed `.mha`/`.fcsv` suffixes and requires a compromised or malicious upstream manifest, hence low confidence and minor severity. Whitelist/escape the manifest keys (e.g. take os.path.basename and allow only [A-Za-z0-9_-]) before using them as file names.
- [`ImpactReg/ImpactReg.py:92`](https://github.com/vboussot/SlicerImpactReg/blob/0103b37caabcb4431f7cc4570156b5b627dd4249/ImpactReg/ImpactReg.py#L92): The first run of a preset triggers downloads that are executed locally: the preset apps from Hugging Face (`VBoussot/ImpactReg`, whose python/yaml configs drive the run), the TorchScript feature models, `pip install fireants`, and the elastix-IMPACT binary built for the installed CUDA (README.md:103, README.md:141). This is the advertised function and is documented, but nothing in this repository shows hash/signature verification of these payloads; that logic, if any, is in impact-reg-konfai and could not be inspected. A compromised upstream hub repo would therefore run code inside the user's registrations. Surface a confirmation before the first download of each preset/binary and state (in the UI or README) whether downloads are integrity-checked and from which exact repository/revision.
- [`ImpactReg/ImpactReg.py:224-226`](https://github.com/vboussot/SlicerImpactReg/blob/0103b37caabcb4431f7cc4570156b5b627dd4249/ImpactReg/ImpactReg.py#L224-L226): Only `Transform.h5` is checked before continuing; `Moved.mha` is read and pushed with no existence test, and per-preset fields are globbed with `sorted((case_dir / "Ensemble").glob("*.h5"))`, which silently yields an empty sequence if `--keep-fields` produced nothing. A partial CLI run therefore raises inside the completion callback (leaving the panel without a message) or leaves an empty DVF sequence behind while the log still reports success. Verify the presence of `Moved.mha` (and warn when `Ensemble/` is empty although uncertainty was ticked) and report the problem through `_update_logs(..., False)`.
- [`README.md:103`](https://github.com/vboussot/SlicerImpactReg/blob/0103b37caabcb4431f7cc4570156b5b627dd4249/README.md#L103): The module downloads presets, feature models (TotalSegmentator, MIND, anatomix), elastix-IMPACT binaries and fireants at run time. README.md line 103 refers to a NOTICE for FireANTs, but no such file or summary of the terms for the models is in the repository. The redistribution and commercial-use terms for these downloads cannot be checked from the repository alone. Add a short section listing the license of each downloaded model, binary and preset, with links.
