Thanks for FlywheelCaseIterator!

Suggestions for a later update:

- `FlywheelCaseIterator/FlywheelCaseIteratorLib/CsvFWTableIterator.py`: The module silently falls back to the API key stored by the Flywheel CLI in ~/.config/flywheel/user.json (lines 312-317) and then writes the key in plaintext into ~/.config/flywheel/fw_connect.json. Credentials are therefore harvested from another tool's config and stored unencrypted on disk; the docs mention the saving but not the CLI fallback. Only use a key the user explicitly entered, and store it with restrictive file permissions or in Slicer's settings rather than a plaintext JSON file.
- `FlywheelCaseIterator/Resources/config_defaults.json`: Downloaded patient images are cached in /tmp/flywheel_cache, a world-writable, predictable location on Linux/macOS. Another local user can pre-create that directory or symlinks inside it, and cached medical images are left behind after the session with default permissions. Default to a per-user directory (e.g. under the user's home or Slicer's temporary directory created with tempfile.mkdtemp) and create it with user-only permissions.
- `FlywheelCaseIterator/Testing/Python/CMakeLists.txt`: The only test registration is commented out, and FlywheelCaseIterator.py contains no unittest subclass for the slicer_add_python_unittest call in FlywheelCaseIterator/CMakeLists.txt line 32. Nothing verifies that the module loads or that the CSV parsing works, so regressions reach users unnoticed. Add a minimal module test (module loads, iterator factory returns the CSV widget) and enable it in CMake.
- `FlywheelCaseIterator/FlywheelCaseIterator.py`: start(), nextCase() and previousCase() (lines 585-588, 606-611, 633) catch every exception, including KeyboardInterrupt/SystemExit, and just advance the index. A case that fails to load (network error, permission problem, bad file) is skipped with no user-visible message, so a reader can silently miss cases and believe the batch was complete. Catch Exception, log the failing case index, and surface a warning to the user (slicer.util.warningDisplay) when cases are skipped.
- `FlywheelCaseIterator/FlywheelCaseIteratorLib/CsvFWTableIterator.py`: CsvFWTableIterator.py imports the flywheel SDK at module level, but required_modules.json declares only fw-pyqt-management 0.0.4. The project's own TODO.md (lines 57-59) notes that the required SDK version is not specified. Installs can therefore break on SDK API changes, and the dependency is not visible to the extension manager. Declare the flywheel SDK and its version in required_modules.json, or in the install logic, and keep it consistent with the fw-pyqt-management pin.
- `FlywheelCaseIterator/FlywheelCaseIteratorLib/CsvFWTableIterator.py`: In the else branch the code logs `image_data["name"]` even when image_data is falsy (None/{}), which raises TypeError/KeyError and aborts loading of the whole case instead of skipping the bad entry. Guard the log message with `if image_data:` and use .get('name').
- `README.md`: The documented fw_case_management package is not in the repository and not installed by FlywheelCaseIterator/CMakeLists.txt; the code now imports fw_pyqt_management from PyPI. Users and reviewers following the README will look for code that does not exist, and the actual runtime dependency is undocumented. Update the module-structure section and document the fw-pyqt-management dependency.
- `FlywheelCaseIterator/FlywheelCaseIteratorLib/IteratorFactory.py`: The imp module was deprecated in Python 3.4 and removed in Python 3.12, which newer Slicer versions ship. onReload() of the module widget will therefore raise ImportError on those Slicer builds. Use importlib (importlib.reload / importlib.util.find_spec) instead of imp.
