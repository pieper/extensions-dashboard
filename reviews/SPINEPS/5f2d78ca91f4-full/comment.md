- [`SlicerSPINEPS/SlicerSPINEPSLib/InstallLogic.py:498-507`](https://github.com/BerDom-Ing/SlicerSPINEPS/blob/5f2d78ca91f413f2b9a10023b7c940d7d7019c05/SlicerSPINEPS/SlicerSPINEPSLib/InstallLogic.py#L498-L507): The Slicer Extensions Index review policy explicitly requires PyTorch to be installed through the Slicer PyTorch extension (`PyTorchUtils`, listed in `build_dependencies` and `EXTENSION_DEPENDS`) rather than via direct use of `light-the-torch`. Additionally, the catalog entry has `"build_dependencies": []` and `CMakeLists.txt` has `set(EXTENSION_DEPENDS "NA")`. While the author's design rationale (avoiding an extra extension install, Slicer restart, and importing `torch` into the main Slicer process on Windows) and the care taken to reuse existing PyTorch installations and pin core packages (`SimpleITK`, `numpy`, `scipy`, `torch`, `nnunetv2`) are well-reasoned, bypassing the `PyTorch` extension directly conflicts with the Extensions Index policy for managing Slicer's shared Python environment. Declare `PyTorch` (and optionally `NNUNet` if sharing its install logic) in `EXTENSION_DEPENDS` in `CMakeLists.txt` and `build_dependencies` in `SPINEPS.json`, and use `PyTorchUtils` to manage PyTorch installation in accordance with Slicer Extensions Index policy.

Smaller suggestions:

- [`SlicerSPINEPS/SlicerSPINEPS.py:173-180`](https://github.com/BerDom-Ing/SlicerSPINEPS/blob/5f2d78ca91f413f2b9a10023b7c940d7d7019c05/SlicerSPINEPS/SlicerSPINEPS.py#L173-L180): The widget warns when the model folder is empty, but running inference initiates downloads without a confirmation. Once any model directory exists it only lists directories, so selecting a different model may silently trigger further downloads of hundreds of MB per model. Check whether the selected model and its companion weights are available, and ask for confirmation before any substantial missing-weight download.
- [`SlicerSPINEPS/SlicerSPINEPS.py:394-398`](https://github.com/BerDom-Ing/SlicerSPINEPS/blob/5f2d78ca91f413f2b9a10023b7c940d7d7019c05/SlicerSPINEPS/SlicerSPINEPS.py#L394-L398): Parameter.asArgList emits --cpu, not -cpu, so this registered test fails deterministically. Its later CT assertions also expect old -model_instance and -model_labeling spellings rather than the current double-dash forms. Update the assertions to match the current flags and run the registered Slicer test.
- [`SlicerSPINEPS/SlicerSPINEPSLib/SegmentationLogic.py:121-127`](https://github.com/BerDom-Ing/SlicerSPINEPS/blob/5f2d78ca91f413f2b9a10023b7c940d7d7019c05/SlicerSPINEPS/SlicerSPINEPSLib/SegmentationLogic.py#L121-L127): The process emits its finished signal for nonzero exits and cancellation as well as success. If a matching final file was written before failure or cancellation, this method returns it without consulting the exit code and the widget can load an incomplete or failed-run result. Only signal successful completion and load outputs after confirming normal exit with code zero; report cancellation and failed runs separately.
- [`SlicerSPINEPS/SlicerSPINEPS.py:409-415`](https://github.com/BerDom-Ing/SlicerSPINEPS/blob/5f2d78ca91f413f2b9a10023b7c940d7d7019c05/SlicerSPINEPS/SlicerSPINEPS.py#L409-L415): `Parameter.asArgList` was updated for SPINEPS >= 2.1.1 to emit double-dash hyphenated flags (`--model-semantic`, `--model-instance`, `--model-labeling`, `--cpu`), and line 395 of `test_ParameterArgList` was updated to check `--model-semantic`. However, lines 397, 413, and 414 of `test_ParameterArgList` still check for the old single-dash flags (`-cpu`, `-model_instance`, `-model_labeling`), which causes `SlicerSPINEPSTest.test_ParameterArgList` to fail with a `ValueError` when the self-test runs. Update `test_ParameterArgList` in `SlicerSPINEPS/SlicerSPINEPS.py` to assert `"--cpu"`, `"--model-instance"`, and `"--model-labeling"` instead of `"-cpu"`, `"-model_instance"`, and `"-model_labeling"`.
