Suggestions for a later update:

- [`SPECTRecon/SPECTRecon.py:513-520`](https://github.com/PyTomography/SlicerSPECTRecon/blob/012dad91bd6e78eac23509a1dc0aec3a08749bc3/SPECTRecon/SPECTRecon.py#L513-L520): self.ui.scatter_toggle is a QCheckBox object, which is always truthy, so 'not self.ui.scatter_toggle' is always False and the scatter windows are never cleared when the user unchecks scatter correction. The same pattern appears on line 519 for the single-photopeak branch. Users who disable scatter correction can still get scatter estimates applied, silently changing quantification. Use self.ui.scatter_toggle.checked in both places.
- [`SPECTRecon/Logic/SPECTReconLogic.py:50-53`](https://github.com/PyTomography/SlicerSPECTRecon/blob/012dad91bd6e78eac23509a1dc0aec3a08749bc3/SPECTRecon/Logic/SPECTReconLogic.py#L50-L53): Any failure in the CT-based attenuation map (wrong series selected, missing geometry, out-of-memory) is swallowed and retried as a SIMIND attenuation map, which then fails with a confusing secondary error or silently produces a wrong mu-map. Errors are not reported to the user. Catch the specific exception raised for non-CT input and report other failures with slicer.util.errorDisplay.
- [`SPECTRecon/SPECTRecon.py:1-3`](https://github.com/PyTomography/SlicerSPECTRecon/blob/012dad91bd6e78eac23509a1dc0aec3a08749bc3/SPECTRecon/SPECTRecon.py#L1-L3): pkg_resources is imported at module top level and is deprecated, and newer setuptools releases may remove it. That would break the module at import time on newer Slicer Python builds. Use importlib.metadata to list installed packages, or import pkg_resources lazily with a fallback.
- [`LICENSE.txt:3`](https://github.com/PyTomography/SlicerSPECTRecon/blob/012dad91bd6e78eac23509a1dc0aec3a08749bc3/LICENSE.txt#L3): The copyright line uses bracketed placeholders, which is a cosmetic defect in the license file. The grant itself is intact. Replace with the full copyright holder name and year.
- [`SPECTRecon/SPECTRecon.py:334-343`](https://github.com/PyTomography/SlicerSPECTRecon/blob/012dad91bd6e78eac23509a1dc0aec3a08749bc3/SPECTRecon/SPECTRecon.py#L334-L343): currentText is a bound method, so these comparisons are always False; the scatter window selectors and the Prior group box are never shown/hidden as intended (lines 334-343). Users selecting 'Energy Window' scatter correction may not see the window selectors, and the prior group box visibility does not follow the algorithm choice. Call currentText() (or use currentTextChanged signals) in hideShowItems().
- [`SPECTRecon/SPECTRecon.py:16`](https://github.com/PyTomography/SlicerSPECTRecon/blob/012dad91bd6e78eac23509a1dc0aec3a08749bc3/SPECTRecon/SPECTRecon.py#L16): onReconstructButton calls self.logic.reconstruct synchronously; the only event processing is slicer.app.processEvents() inside the callbacks (Callbacks.py:12, 25). A multi-bed, multi-iteration GPU reconstruction therefore freezes the Slicer UI with no way to cancel, and any exception leaves the modal progress dialog open (see the store_recons bug above). Run the reconstruction in a CLI/worker thread (or at least keep a cancel button and close the dialog in a finally block).
- [`SPECTRecon/Logic/VolumeUtils.py:7-8`](https://github.com/PyTomography/SlicerSPECTRecon/blob/012dad91bd6e78eac23509a1dc0aec3a08749bc3/SPECTRecon/Logic/VolumeUtils.py#L7-L8): create_volume_node_from_recon (SPECTReconLogic.py:216-221) creates a temp directory per reconstruction and never deletes it; removeNode() exists but is never called. Every reconstruction leaves DICOM copies of the reconstructed patient image in the system temp folder indefinitely, which is a privacy/hygiene issue on shared workstations. Delete the temporary directory (shutil.rmtree) after the volume is loaded, e.g. in a finally block.
- [`SPECTRecon/Logic/SPECTReconLogic.py:216-221`](https://github.com/PyTomography/SlicerSPECTRecon/blob/012dad91bd6e78eac23509a1dc0aec3a08749bc3/SPECTRecon/Logic/SPECTReconLogic.py#L216-L221): Reconstructed DICOM slices are written to a fresh temp directory and loaded into the database, but the directory is never deleted. Patient-identifying DICOM files remain in the system temp location after use. removeNode with its dir-cleanup option exists but is unused. Remove the temp directory after the DICOM import completes (try/finally with shutil.rmtree), or write directly to the Slicer DICOM database path.
