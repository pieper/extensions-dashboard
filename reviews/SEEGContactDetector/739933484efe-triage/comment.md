Suggestions for a later update:

- [`SEEGContactDetector/SEEGContactDetector.py:369`](https://github.com/EpiReC-ISARG/SlicerSEEGContactDetector/blob/739933484efeb08cf1b72d2507bf3b4795e3ac6b/SEEGContactDetector/SEEGContactDetector.py#L369): The whole detection chain (bolt segmentation, PCA, GMM over all metal voxels, curve fitting with a correlation loop per offset) executes in the GUI thread guarded only by slicer.app.processEvents() calls (e.g. lines 958, 1030, 1134). The progress dialog has its cancel button removed and shows hard-coded percentages, so the UI appears frozen for the multi-minute runs the README advertises and the user cannot abort. Move the pipeline into the logic class as a cli/CLI-node or use a QThread/slicer.util.createProgressDialog with real progress and cancellation support, as other Slicer extensions do.
- [`README.md:20-24`](https://github.com/EpiReC-ISARG/SlicerSEEGContactDetector/blob/739933484efeb08cf1b72d2507bf3b4795e3ac6b/README.md#L20-L24): The module produces electrode contact coordinates used to interpret invasive recordings, and the README/docs claim high accuracy, but no accuracy numbers, no statement of validation cohort, and no 'not for primary clinical decision making / research use' disclaimer appear anywhere (searched for clinical/disclaimer/not intended terms). Add a short 'Intended use / limitations' section citing the reported accuracy from the Janca et al. paper on the tested data and stating that automatic results must be reviewed by a clinician.
- [`SEEGContactDetector/SEEGContactDetector.py:671-681`](https://github.com/EpiReC-ISARG/SlicerSEEGContactDetector/blob/739933484efeb08cf1b72d2507bf3b4795e3ac6b/SEEGContactDetector/SEEGContactDetector.py#L671-L681): Any volume whose name contains 'ct' or 't1' (and any markup list containing 'fiducials') is assigned to the module's inputs as soon as it is added to the scene, replacing the node the user explicitly selected. Loading e.g. 'T1_postcontrast' or 'func_t1_map' after choosing the preoperative T1 changes the input without notification and can silently change registration/masking results. Use name heuristics only to prefill empty selections (as initializeParameterNode does) and never overwrite a non-empty user choice without asking.
