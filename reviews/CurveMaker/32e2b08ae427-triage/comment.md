Suggestions for a later update:

- [`CurveMaker/CurveMaker.py:386-387`](https://github.com/tokjun/CurveMaker/blob/32e2b08ae427074f0d4c98261d53857c9962382f/CurveMaker/CurveMaker.py#L386-L387): Observers are added to the source markups node, the destination model node and its display node (lines 407, 426, 429, 578) but never removed when the module widget is closed or the scene is closed. The observers keep references to the widget's Python methods, so later node modifications can call into a half-destroyed widget, and the vtkScalarBarWidget stays registered with the 3D view interactor. Remove all observer tags and disable the scalar bar widget in cleanup(), and reset the stored node references.
- [`CMakeLists.txt:1`](https://github.com/tokjun/CurveMaker/blob/32e2b08ae427074f0d4c98261d53857c9962382f/CMakeLists.txt#L1): CMake 4.x removed compatibility with cmake_minimum_required values below 3.5 and errors out, so the extension cannot be configured on a modern build machine unless the Slicer superbuild injects CMAKE_POLICY_VERSION_MINIMUM. Raise the minimum to a version supported by current Slicer builds (e.g. 3.16 or higher).
- [`CurveMaker/CurveMaker.py:905-909`](https://github.com/tokjun/CurveMaker/blob/32e2b08ae427074f0d4c98261d53857c9962382f/CurveMaker/CurveMaker.py#L905-L909): computeCurvatures divides by ds, the distance between consecutive points, without checking for zero. Two identical adjacent fiducials give a NaN or ZeroDivisionError during curvature updates. This is an ordinary robustness bug. Skip or merge duplicate points before computing tangents, and guard the division.
- [`CurveMaker/CMakeLists.txt:9-10`](https://github.com/tokjun/CurveMaker/blob/32e2b08ae427074f0d4c98261d53857c9962382f/CurveMaker/CMakeLists.txt#L9-L10): CurveMaker/Resources/Icons/CurveMaker.png exists, but MODULE_PYTHON_RESOURCES is empty, so the icon is not installed with the module. The module's icon depends on the external URL in the root CMakeLists instead. Add Resources/Icons/CurveMaker.png to RESOURCES, or delete the unused file.
- [`CurveMaker/CurveMaker.py:914-917`](https://github.com/tokjun/CurveMaker/blob/32e2b08ae427074f0d4c98261d53857c9962382f/CurveMaker/CurveMaker.py#L914-L917): minKappa is initialized to 0.0 and kappa is a norm, so it is never negative. Its update is therefore never triggered, so the 'Minimum' readout in the GUI always shows 0. The max branch is also an elif, so a value that lowers the minimum cannot also raise the maximum. Users relying on the min/max readouts get wrong values. Initialize minKappa and maxKappa from the first kappa value (or to +/-inf), and use two independent `if` statements.
- [`README.md:1-4`](https://github.com/tokjun/CurveMaker/blob/32e2b08ae427074f0d4c98261d53857c9962382f/README.md#L1-L4): The only documentation is a two-line README (with a typo); there is no tutorial, no sample markups, no screenshots in the repository and no working test. The core function (fit a curve through markups and render it as a tube) is already provided by the MarkupsToModel extension, so users have no guidance on when to prefer this module. Add a README with usage steps and a sample .mrk.json, and state the difference from MarkupsToModel.
- [`CurveMaker/Testing/Python/CMakeLists.txt:2`](https://github.com/tokjun/CurveMaker/blob/32e2b08ae427074f0d4c98261d53857c9962382f/CurveMaker/Testing/Python/CMakeLists.txt#L2): The only test wiring is a commented-out line in Testing/Python/CMakeLists.txt, and the in-script unittest is not exercised by CMake. Regressions such as the distanceToPoint and curvature bugs above would not be caught by CI. Add a unit test that exercises the logic class (nodeToPoly, distanceToPoint, computeCurvatures) without the GUI, and register it with slicer_add_python_unittest.
- [`CurveMaker/CMakeLists.txt:23-25`](https://github.com/tokjun/CurveMaker/blob/32e2b08ae427074f0d4c98261d53857c9962382f/CurveMaker/CMakeLists.txt#L23-L25): CurveMaker.py imports unittest (line 2) but defines no unittest.TestCase subclass, and CurveMaker/Testing/Python/CMakeLists.txt has its test commented out. The generated ctest therefore has nothing to run and will fail or silently pass, so the extension has no automated coverage. Add a CurveMakerTest(unittest.TestCase) class exercising nodeToPoly/calculateLineLength/distanceToPoint, or remove the registration.
