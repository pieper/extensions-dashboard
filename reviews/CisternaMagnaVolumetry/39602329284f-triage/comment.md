- [`CisternaMagnaVolumetry/CisternaMagnaVolumetry.py:259-260`](https://github.com/niyaziacer/SlicerCisternaVolumetry/blob/39602329284f0769a109119faeb6a1d7df13878b/CisternaMagnaVolumetry/CisternaMagnaVolumetry.py#L259-L260): The check only reaches this branch when nibabel or scipy fails to import, but the command asks pip to install both. scipy ships with Slicer; if a user's scipy import is broken (or a resolver decides to satisfy a dependency), pip can replace or upgrade Slicer's bundled scipy in the shared environment, affecting other extensions. Only nibabel is actually needed from PyPI. Install only the missing package, e.g. pip_install("nibabel"), and tell the user to reinstall/repair Slicer if scipy itself is missing.
- [`CisternaMagnaVolumetry/CisternaMagnaVolumetry.py:394-398`](https://github.com/niyaziacer/SlicerCisternaVolumetry/blob/39602329284f0769a109119faeb6a1d7df13878b/CisternaMagnaVolumetry/CisternaMagnaVolumetry.py#L394-L398): Any segmentation node in the scene that happens to carry this name - including one the user created or edited themselves - has all of its segments deleted on Calculate. The loss is in-scene only (no file is overwritten), but unsaved manual work can be destroyed without warning. Track the node created by this module (e.g. keep a reference or use a dedicated attribute/name prefix) and only clear that node, or ask before replacing a node the module did not create.
- [`CisternaMagnaVolumetry/CisternaMagnaVolumetry.py:203-205`](https://github.com/niyaziacer/SlicerCisternaVolumetry/blob/39602329284f0769a109119faeb6a1d7df13878b/CisternaMagnaVolumetry/CisternaMagnaVolumetry.py#L203-L205): run()/runSynthSeg() call the core analysis synchronously; the core performs per-slice distance transforms and repeated np.argwhere over the full volume (cisterna_core.py:325-336, 362-364, 384-386), which on a 1 mm T1 can take many seconds to minutes. During that time Slicer's UI is frozen with no progress bar and no way to cancel, which looks like a hang to the user. Run the analysis in a CLI node or a worker thread with slicer.util.ProgressDialog / a progress callback, or at minimum show a busy cursor and document the expected runtime.
- [`CisternaMagnaVolumetry/CisternaMagnaVolumetry.py:416-419`](https://github.com/niyaziacer/SlicerCisternaVolumetry/blob/39602329284f0769a109119faeb6a1d7df13878b/CisternaMagnaVolumetry/CisternaMagnaVolumetry.py#L416-L419): The registered test cannot detect regressions in the segmentation logic, and README.md:81-97 reports Dice 0.56-0.66 on two cases with limits tuned on the scored cases. Users get a research-grade heuristic; the README and the module note do warn about this and ask for visual checking, so this is a maturity limitation rather than a defect. Add a synthetic phantom test (a small label volume with a brainstem, 4th ventricle and CSF shell) that asserts non-empty masks and plausible volumes, so the CI test exercises the core code path.
- [`CisternaMagnaVolumetry/CisternaMagnaVolumetryLib/cisterna_core.py:341`](https://github.com/niyaziacer/SlicerCisternaVolumetry/blob/39602329284f0769a109119faeb6a1d7df13878b/CisternaMagnaVolumetry/CisternaMagnaVolumetryLib/cisterna_core.py#L341): pmj comes either from max(pons) (a key of ant) or from the fallback `top - round(18 / v1)` at line 315, which need not be a slice containing brainstem and therefore need not be a key of the `ant` dict built at line 312. On such data the analysis aborts with KeyError instead of a meaningful message; the widget catches it and shows the raw exception text. Clamp pmj to the nearest slice present in `ant` (or use the nearest key) before indexing, and raise a descriptive ValueError if no brainstem slice qualifies.
- [`README.md:200-202`](https://github.com/niyaziacer/SlicerCisternaVolumetry/blob/39602329284f0769a109119faeb6a1d7df13878b/README.md#L200-L202): The README states that live testing in Slicer 5.11.0 matched the CLI, then says 'These numbers were produced with method v1; the CLI repo has not been updated to v2 yet.' The vendored cisterna_core.py is v2 (its docstring says 'method v2'). Users may assume the v2 code has been tested in Slicer when it has not. Re-run the Slicer live test on the v2 code and update the README, or state clearly that the Slicer path is untested for v2.
- [`CisternaMagnaVolumetry/CisternaMagnaVolumetry.py:324`](https://github.com/niyaziacer/SlicerCisternaVolumetry/blob/39602329284f0769a109119faeb6a1d7df13878b/CisternaMagnaVolumetry/CisternaMagnaVolumetry.py#L324): If the selected vtkMRMLSegmentationNode contains no segments, arr stays None and is returned; runSynthSeg then calls np.unique(seg) on None, producing a TypeError instead of the intended "no 'csf' or 'brain-stem' segment" message. - [`CisternaMagnaVolumetry/CisternaMagnaVolumetry.py:364-366`](https://github.com/niyaziacer/SlicerCisternaVolumetry/blob/39602329284f0769a109119faeb6a1d7df13878b/CisternaMagnaVolumetry/CisternaMagnaVolumetry.py#L364-L366): The resampled T1 node is removed only on the success path; if run_cistern_analysis_synthseg raises (e.g. missing brainstem/4th-ventricle landmark), the temporary volume stays in the scene and is saved with the user's MRB, silently adding a duplicate volume.
