Suggestions for a later update:

- [`PETDenoise/PETDenoise.py:608-620`](https://github.com/4burakfe/SlicerPETDenoise/blob/40a63cbfba7875615de0f75e3fd936a4b1ba95b6/PETDenoise/PETDenoise.py#L608-L620): After user confirmation, `slicer.util.pip_install("monai")` (also VolumeComparator.py line 309) resolves monai's dependencies inside Slicer's Python, which can upgrade Slicer-bundled numpy, while `einops==0.6.1` is an exact pin that can conflict with other extensions needing a newer einops. Installation is at least user-confirmed and not at import, so this is not a blocking environment change. Pin a tested monai version (e.g. monai==1.3.x) and relax the einops pin to a minimum version, and mention the tested versions in the README.
- [`PETDenoise/PETDenoise.py:440-442`](https://github.com/4burakfe/SlicerPETDenoise/blob/40a63cbfba7875615de0f75e3fd936a4b1ba95b6/PETDenoise/PETDenoise.py#L440-L442): The whole sliding-window inference (PETDenoise.py lines 1184-1266) and the metric computation (VolumeComparator.py lines 406-464) run in the button-click slot; progress is only shown by pumping the Qt event loop with processEvents. During a long run the UI stays re-entrant, so scene changes or module switches can occur mid-inference, and the application appears frozen between log messages. Move the heavy work to a slicer.util.ProgressDialog / CLI-style worker thread (or a qSlicerCLI-like background task) and keep processEvents out of the compute path.
- [`PETDenoise/PETDenoise.py:993`](https://github.com/4burakfe/SlicerPETDenoise/blob/40a63cbfba7875615de0f75e3fd936a4b1ba95b6/PETDenoise/PETDenoise.py#L993): isCompleteModelFile returns False for an existing file of a different size, so the download path is taken and os.replace() overwrites the file in the user's model folder. A user-supplied model with the same name, or a partially edited file, is replaced without confirmation. The data loss is limited to model files, but it is unannounced. Ask for confirmation before replacing an existing file, or download into a separate folder and report the conflict.
- [`PETDenoise/PETDenoise.py:648-656`](https://github.com/4burakfe/SlicerPETDenoise/blob/40a63cbfba7875615de0f75e3fd936a4b1ba95b6/PETDenoise/PETDenoise.py#L648-L656): saveModelFolderPath writes model_config.ini next to the module file. In an installed extension that directory is typically read-only (and shared by all users), so the write fails and is only logged at info level; the setting is still kept in QSettings, so functionality is preserved, but writing into the program installation is not a user-chosen location. Keep the folder only in QSettings, or write the compatibility ini into the user settings/cache directory instead of the module directory.
- [`PETDenoise/CMakeLists.txt:9-12`](https://github.com/4burakfe/SlicerPETDenoise/blob/40a63cbfba7875615de0f75e3fd936a4b1ba95b6/PETDenoise/CMakeLists.txt#L9-L12): PETDenoise.py lines 282-284 and 376-381 (and VolumeComparator.py lines 32-34, 82-87) load Resources/logo.png and Resources/banner.png, but only Icons/*.png and UI/*.ui are listed as module resources, so those files are not installed with the extension. The os.path.exists guards mean no crash, but users of the installed extension get no module icon and no banner, and the 9 MB banner files are dead weight in the repository. Add Resources/logo.png (and, if wanted, Resources/banner.png) to MODULE_PYTHON_RESOURCES in both module CMakeLists.txt files, or drop the unused images.
- [`PETDenoise/CMakeLists.txt:27`](https://github.com/4burakfe/SlicerPETDenoise/blob/40a63cbfba7875615de0f75e3fd936a4b1ba95b6/PETDenoise/CMakeLists.txt#L27): Both module CMakeLists.txt register a Python unittest on the module script, but a search for unittest classes in PETDenoise.py and VolumeComparator.py found none, and Testing/Python/CMakeLists.txt only contains a commented-out line. The generated test therefore exercises nothing, so the extension ships without any automated verification of the denoising or metric code. Add a real test class (e.g. exercising parseSidecar/parseSequence/validateParameters and the metric formulas on synthetic arrays) or remove the test registration.
- [`PETDenoise/PETDenoise.py:817`](https://github.com/4burakfe/SlicerPETDenoise/blob/40a63cbfba7875615de0f75e3fd936a4b1ba95b6/PETDenoise/PETDenoise.py#L817): Asset names come from the GitHub release JSON (parseReleaseAssets, lines 207-221) and are joined directly onto the model folder, both for the .pth (line 1021) and the sidecar (line 1036). An asset named e.g. '../../x.pth' would make the download write outside the chosen model folder. The repository is author-controlled, so the practical risk is low, but the path is not validated. Reject asset names containing path separators or '..' (e.g. require os.path.basename(name) == name) before using them as file names.
- [`README.md:10`](https://github.com/4burakfe/SlicerPETDenoise/blob/40a63cbfba7875615de0f75e3fd936a4b1ba95b6/README.md#L10): The scan reports PETDenoise/Resources/banner.png and VolumeComparator/Resources/banner.png at ~9 MB each (not readable here). Large binaries in the source repository slow clones and the extension build, and they are not even installed (see the resource finding). Downscale the banners to a few hundred KB, or reference the images from the README only.
