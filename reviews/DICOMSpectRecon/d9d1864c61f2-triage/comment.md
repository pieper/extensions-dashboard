- [`DICOMSpectRecon/SPECTCalibration.py:75`](https://github.com/4burakfe/SlicerDICOMSpectRecon/blob/d9d1864c61f23c0830359c31f39f297da2400b22/DICOMSpectRecon/SPECTCalibration.py#L75): If the calibration library cannot be read, the user gets no drift comparison and no indication that the check was skipped, which matters for a quantitative calibration workflow where a large drift is the main warning sign. - [`DICOMSpectRecon/DICOMSpectReconLib/collimators.py:196-199`](https://github.com/4burakfe/SlicerDICOMSpectRecon/blob/d9d1864c61f23c0830359c31f39f297da2400b22/DICOMSpectRecon/DICOMSpectReconLib/collimators.py#L196-L199): saveLibrary writes to path + '.tmp' and then os.replace()s it. Two Slicer instances saving at once would write to the same temp file and could interleave, and an exception during json.dump leaves the .tmp file behind. The library is a shared user file, so a corrupted or lost edit is possible. The calibration library in quantification.py already uses mkstemp, so this is inconsistent. Use tempfile.mkstemp in the same folder, as quantification._writeLibrary does, and remove the temp file on failure.
- [`DICOMSpectRecon/DICOMSpectRecon.py:68-75`](https://github.com/4burakfe/SlicerDICOMSpectRecon/blob/d9d1864c61f23c0830359c31f39f297da2400b22/DICOMSpectRecon/DICOMSpectRecon.py#L68-L75): These dictionaries accumulate one entry per examined NM file for the lifetime of the Slicer session and are only partially cleared in addMultiBedLoadables (lines 225-226). In a long session with many studies they grow without bound, and stale CT/bed pairings from an earlier examine can be reused by load() (lines 376-379) if the browser serves cached loadables. Clear the caches at the start of examine() or key them on the study/series UID and drop entries for series no longer in the database.
- [`README.md:91-94`](https://github.com/4burakfe/SlicerDICOMSpectRecon/blob/d9d1864c61f23c0830359c31f39f297da2400b22/README.md#L91-L94): The README documents the workflow well, but the only tests are manual scripts under Testing/PyTomography4 (run_recon.py, compare.py, check_beds.py) and there is no statement that the reconstructions and Bq/ml/SUV values are for research use and not validated for clinical decisions - relevant for a quantitative nuclear-medicine tool. Add a short 'not for clinical use / research only' note and, if feasible, a small headless test that runs the pure-numpy parts (quantification, collimators, FBP windows) in CI.
- [`README.md:82`](https://github.com/4burakfe/SlicerDICOMSpectRecon/blob/d9d1864c61f23c0830359c31f39f297da2400b22/README.md#L82): The README describes Bq/ml and SUV quantification, dosimetry traceability and clinical-style workflows (e.g. 'the usual clinical choice'), but contains no statement that outputs are unvalidated for clinical decisions or that the user must verify calibration. Users may trust the numbers without checking. This is a documentation gap, not a code defect. Add a 'Research use only / not validated for clinical decisions' disclaimer and a short validation note (phantom checks, versioning) to the README and the module helpText.
- [`DICOMSpectRecon/DICOMSpectReconLib/dialog.py:2089-2093`](https://github.com/4burakfe/SlicerDICOMSpectRecon/blob/d9d1864c61f23c0830359c31f39f297da2400b22/DICOMSpectRecon/DICOMSpectReconLib/dialog.py#L2089-L2093): The OSEM/BSREM/FBP loop is driven from the dialog with slicer.app.processEvents() to keep the UI responsive, so a long reconstruction blocks the event loop between callbacks and can make Slicer appear hung; the abort callback (reconstruction.py:149-157) mitigates this but the work is not moved off the GUI thread. Run the reconstruction in a worker thread (or a CLI) and report progress through signals, as other Slicer reconstruction extensions do.
- [`DICOMSpectRecon/DICOMSpectRecon.py:118`](https://github.com/4burakfe/SlicerDICOMSpectRecon/blob/d9d1864c61f23c0830359c31f39f297da2400b22/DICOMSpectRecon/DICOMSpectRecon.py#L118): If the subject-hierarchy check or insertion fails, the error is dropped with a bare except and pass. The CT then loads without DICOM metadata, and the user gets no message, which makes the later fusion or calibration steps hard to debug. Log the traceback with logging.warning, as the surrounding code does elsewhere in this file.
- [`DICOMSpectRecon/DICOMSpectRecon.py:60-62`](https://github.com/4burakfe/SlicerDICOMSpectRecon/blob/d9d1864c61f23c0830359c31f39f297da2400b22/DICOMSpectRecon/DICOMSpectRecon.py#L60-L62): The hidden module is imported when Slicer starts, so this prepends the module folder to sys.path for the whole process (same pattern in SPECTCalibration.py:28-30 and SPECTCollimators.py:23-25). Any file in that folder whose name shadows a stdlib or Slicer module would then win the import; today the folder only holds the extension's own files, so the practical risk is low. Append instead of insert, or rely on the extension build's normal package layout and drop the sys.path change.
