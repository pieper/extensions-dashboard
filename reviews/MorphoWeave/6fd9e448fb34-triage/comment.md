- [`MorphoWeaveLandmarkTransfer/MorphoWeaveLandmarkTransfer.py:211-218`](https://github.com/agporto/SlicerMorphoWeave/blob/6fd9e448fb3441b71f7fed2bec9434a9b2190d24/MorphoWeaveLandmarkTransfer/MorphoWeaveLandmarkTransfer.py#L211-L218): Installing tiny3d-rs/rustcpd is user-confirmed and acceptable, but the code also uninstalls the legacy 'tiny3d' distribution from Slicer's shared environment. Any other installed extension that imports tiny3d (for example a SlicerMorph-style point-cloud workflow) stops working after this action, for a user who only wanted to run MorphoWeave. The confirmation dialog at lines 203-206 mentions the removal, which limits the surprise, but the impact on other extensions is not stated. State in the confirmation dialog that other extensions using tiny3d will stop working, and prefer installing tiny3d-rs without removing tiny3d when the two can coexist, or document the conflict in the module help text.
- [`MorphoWeaveAtlasBuilder/MorphoWeaveAtlasBuilder.py:256`](https://github.com/agporto/SlicerMorphoWeave/blob/6fd9e448fb3441b71f7fed2bec9434a9b2190d24/MorphoWeaveAtlasBuilder/MorphoWeaveAtlasBuilder.py#L256): Atlas Builder alignment/export and Model Library ingest (MorphoWeaveModelLibrary.py:589) run synchronously on the GUI thread and call processEvents to keep the UI alive. Because the Run button is not disabled during the run (self.runBtn is only enabled/disabled by _reeval, line 308), a second click during a pumped event loop can start a second pipeline that writes into the same output/library folders, and there is no cancel path for long runs. This is a usability/robustness issue, not a data-safety one, since outputs go to timestamped folders. Disable the Run/Ingest buttons for the duration of the pipeline (or move the work to a slicer.util.ProgressDialog / CLI-style worker) and add a cancellation check between specimens.
- [`MorphoWeaveModelLibrary/MorphoWeaveModelLibrary.py:573-579`](https://github.com/agporto/SlicerMorphoWeave/blob/6fd9e448fb3441b71f7fed2bec9434a9b2190d24/MorphoWeaveModelLibrary/MorphoWeaveModelLibrary.py#L573-L579): The name typed in 'New Database Name' is joined to the library root without any check, so a name such as '../atlas' or 'a/b' makes ingestSSMDatabase create directories and copy files outside the configured library folder. The same unvalidated path is later passed to removeSSMDatabase, which calls shutil.rmtree(dbPath) (line 199) after a single confirmation dialog, so a mis-typed or crafted name can delete a directory the user did not intend. Atlas Builder already implements the correct guard (isSafeLibraryName, MorphoWeaveAtlasBuilder.py:536-545) but Model Library does not reuse it. Reuse MorphoWeaveAtlasBuilderLogic.isSafeLibraryName (or an equivalent check) in onIngestButton and in Atlas Builder's _saveSsmToLibrary path, and refuse names containing separators, '..' or reserved characters before creating or deleting anything.
