Suggestions for a later update:

- [`slicer-plugin/RemoteView/remoteview_core/consent.py:53-56`](https://github.com/dolegadolegowski/SlicerRemoteView/blob/ebe397a89efd47c0ec60df7a4d5446cdd96b8367/slicer-plugin/RemoteView/remoteview_core/consent.py#L53-L56): The disclosure adjacent to Start says models and segments are sent, but does not say their names and segment IDs can contain patient identifiers, or that later opened scenes are also shared. The linked help is not necessarily opened before Start. PanelController creates LiveUpdates without an anonymization argument (panel.py 936–952), so its False default (live.py 216) is used; names and IDs can therefore be sent to the chosen relay and anyone joining without adequately informed opt-in. Before Start, explicitly disclose names, IDs, future loaded scenes, and who can access them; provide a functional name-hiding control before transmission or clearly state that names cannot be hidden.
- [`slicer-plugin/RemoteView/RemoteView.py:75-79`](https://github.com/dolegadolegowski/SlicerRemoteView/blob/ebe397a89efd47c0ec60df7a4d5446cdd96b8367/slicer-plugin/RemoteView/RemoteView.py#L75-L79): The UI has no Hide node names control, and the panel creates LiveUpdates without setting anonymize_names, which defaults to False. A user trying to follow this help cannot activate the described protection, and names and segment IDs remain included when a session starts. Wire a pre-session name-hiding control through PanelController to LiveUpdates, or remove the claim and warn that identifying names will be sent.
- [`slicer-plugin/RemoteView/RemoteView.py:92-94`](https://github.com/dolegadolegowski/SlicerRemoteView/blob/ebe397a89efd47c0ec60df7a4d5446cdd96b8367/slicer-plugin/RemoteView/RemoteView.py#L92-L94): When Slicer finishes starting up, `RemoteView.__init__` connects `startupCompleted()` to `self.addToolbar()`, which adds a `RemoteView` toolbar (`Send scene now` button and `Send changes:` combo box) to Slicer's main window even if the user never opens the RemoteView module. While lightweight (no network or heavy imports), modifying the global main window UI at startup affects all users who have the extension installed. Consider creating or showing the toolbar only when the user first opens the `RemoteView` module or starts a session, or providing a setting to hide it by default.
