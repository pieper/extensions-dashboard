- [`ZebrafishEmbryoAnalyzer/ZebrafishEmbryoAnalyzerLib/logic.py:68`](https://github.com/MarkDanielArndt/SlicerZebrafishEmbryoAnalyzer/blob/a6b1b6e93dee7e00f5e5eccb698ec4100423781d/ZebrafishEmbryoAnalyzer/ZebrafishEmbryoAnalyzerLib/logic.py#L68): The extension replaces zebrafish_measure.seg._load_unet_model process-wide and stashes the original on the library module to survive reloads. Any other code in the same Slicer process that uses zebrafish_measure gets the cached wrapper and an unbounded _MODEL_CACHE of ~180 MB models. It is confined to a third-party library rather than Slicer/VTK, and analysis runs in a worker subprocess, so impact is limited, but it is a global side effect that is not undone. Pass a cache/loader explicitly to segmentation_pipeline if the library allows it, or bound the cache and restore the original on module cleanup.
- [`ZebrafishEmbryoAnalyzer/ZebrafishEmbryoAnalyzer.py:48-53`](https://github.com/MarkDanielArndt/SlicerZebrafishEmbryoAnalyzer/blob/a6b1b6e93dee7e00f5e5eccb698ec4100423781d/ZebrafishEmbryoAnalyzer/ZebrafishEmbryoAnalyzer.py#L48-L53): On import, the extension pops its own module names from sys.modules to force reloads. The work is confined to the extension's own names, so the impact is limited, but it is a global side effect that runs before the module is used. Keep the eviction to setup() and enter() only, and document why it is needed for Slicer reload.
- [`ZebrafishEmbryoAnalyzer/ZebrafishEmbryoAnalyzerLib/logic.py:429`](https://github.com/MarkDanielArndt/SlicerZebrafishEmbryoAnalyzer/blob/a6b1b6e93dee7e00f5e5eccb698ec4100423781d/ZebrafishEmbryoAnalyzer/ZebrafishEmbryoAnalyzerLib/logic.py#L429): analyse_images() iterates over sorted(image_paths), so the returned list order is alphabetical, not the order the user loaded the images. InferenceController._merge_originals (inference_runner.py:296-300) then pairs results[i] with originals[i] positionally. If the widget collects originals in load order, a result row can be displayed with another image's pixels, i.e. wrong measurements shown against the wrong picture. I could not read widget.py to confirm the originals ordering, so this is a suspected rather than verified mismatch. Either drop the sort (preserve caller order) or key the merge on image_path/filename instead of list index.
- [`ZebrafishEmbryoAnalyzer/ZebrafishEmbryoAnalyzerLib/overlay.py:8-9`](https://github.com/MarkDanielArndt/SlicerZebrafishEmbryoAnalyzer/blob/a6b1b6e93dee7e00f5e5eccb698ec4100423781d/ZebrafishEmbryoAnalyzer/ZebrafishEmbryoAnalyzerLib/overlay.py#L8-L9): gallery_tab.populate() calls make_overlay() for every result, including placeholders for images that have not been analysed, so merely listing loaded images requires OpenCV. The dependency_installer comments acknowledge this ('Showing images at all needs OpenCV'), which means the 'images' purpose pulls a package the user may not need; it is a usability wart rather than a defect. Import cv2 lazily inside make_full_overlay and fall back to a plain numpy thumbnail when it is unavailable.
