Suggestions for a later update:

- [`GeodesicSlicer/GeodesicSlicer.py:814`](https://github.com/FredericBr/SlicerGeodesic/blob/9641c81e8fef5183594f53f40bffad01b1a0a0b8/GeodesicSlicer/GeodesicSlicer.py#L814): The guard at line 791 only checks that a markups node is selected, not how many fiducials it holds; line 831 then evaluates list[1], so with 0 or 1 fiducials the user gets a Python IndexError traceback instead of the intended error dialog. Same pattern in draw() (lines 913-930). Check numFids >= 2 and show the error dialog before indexing the list.
- [`GeodesicSlicer/GeodesicSlicer.py:593`](https://github.com/FredericBr/SlicerGeodesic/blob/9641c81e8fef5183594f53f40bffad01b1a0a0b8/GeodesicSlicer/GeodesicSlicer.py#L593): mesh()/mesh2()/EEG()/ProjectedPoint()/CorrectedPoint() run thresholding, morphological closing and many Dijkstra passes synchronously in the button callback; mesh2() additionally sleeps 5 s twice and 3 s once (lines 707, 716, 740), during which the UI is frozen and the progress dialog cannot be cancelled. Only a few code paths call slicer.app.processEvents(). Move the heavy work to a CLI module or a worker thread (slicer.util.ProgressDialog with wasCanceled checks) and remove the artificial sleeps.
- [`GeodesicSlicer/GeodesicSlicer.py:1771-1772`](https://github.com/FredericBr/SlicerGeodesic/blob/9641c81e8fef5183594f53f40bffad01b1a0a0b8/GeodesicSlicer/GeodesicSlicer.py#L1771-L1772): ProjectedPoint assumes the first four fiducials are the landmarks and the last three are the stimulation point and T3P3. A user who adds or reorders fiducials gets a wrong nearest-electrode list with no warning. Select electrodes by their label names rather than by slice position, and validate the fiducial count and labels before use.
- [`GeodesicSlicer/GeodesicSlicer.py:804-807`](https://github.com/FredericBr/SlicerGeodesic/blob/9641c81e8fef5183594f53f40bffad01b1a0a0b8/GeodesicSlicer/GeodesicSlicer.py#L804-L807): run_djikstra(), draw() and EEG() (lines 806, 905, 997) look the model up by name and dereference GetStorageNode() unconditionally. A model without a storage node (created in the scene, or loaded from a scene file) yields AttributeError, and a duplicate node name can select the wrong node. The retrieved filename is only used for logging in run_djikstra/EEG, so the crash is avoidable. Use the model node passed in directly and guard the storage-node lookup (or drop it where it is only logged).
- [`GeodesicSlicer/GeodesicSlicer.py:486-489`](https://github.com/FredericBr/SlicerGeodesic/blob/9641c81e8fef5183594f53f40bffad01b1a0a0b8/GeodesicSlicer/GeodesicSlicer.py#L486-L489): Every callback constructs a new GeodesicSlicerLogic() (e.g. lines 426-443), so setStimulationPoint()/setM1Site() write to objects that are immediately discarded; the values are never read anywhere, so the radio-button state has no effect on the computation. Nothing is stored in a parameter node, so module state is not saved with the scene and cannot be scripted, contrary to Slicer conventions. The base-class __init__ is also not called. Use a vtkMRMLScriptedModuleNode parameter node (or a single widget-owned logic instance) and read the state from there.
- [`GeodesicSlicer/Testing/Python/CMakeLists.txt:2`](https://github.com/FredericBr/SlicerGeodesic/blob/9641c81e8fef5183594f53f40bffad01b1a0a0b8/GeodesicSlicer/Testing/Python/CMakeLists.txt#L2): The module's unit-test registration is commented out, and no test class is defined in the module file. Changes to geodesic or threshold calculations cannot be checked automatically. Add a small test using the bundled template, or a synthetic mesh, to check path length and fiducial placement.
- [`GeodesicSlicer/GeodesicSlicer.py:589-591`](https://github.com/FredericBr/SlicerGeodesic/blob/9641c81e8fef5183594f53f40bffad01b1a0a0b8/GeodesicSlicer/GeodesicSlicer.py#L589-L591): The threshold 100..5000 HU only makes sense for CT. With an MRI volume (the module's own example template is a .nii) the segment is empty or wrong, and the subsequent surface extraction/Dijkstra steps silently produce meaningless paths rather than an error. Same values at lines 702-703. Expose the threshold range in the UI (or auto-detect CT vs MR) and warn when the resulting segment is empty.
- [`GeodesicSlicer/CMakeLists.txt:22-29`](https://github.com/FredericBr/SlicerGeodesic/blob/9641c81e8fef5183594f53f40bffad01b1a0a0b8/GeodesicSlicer/CMakeLists.txt#L22-L29): slicer_add_python_unittest is pointed at GeodesicSlicer.py, but the file defines no unittest.TestCase subclass (only 'import unittest' at line 57), so the registered ctest exercises nothing; GeodesicSlicer/Testing/Python/CMakeLists.txt is entirely commented out. Users therefore get no automated verification of the geodesic/10-20 computations. Add a real test class (e.g. GeodesicSlicerTest) using the bundled template data, or remove the test registration.
