Suggestions for a later update:

- [`MirrorOrbitRecon/MirrorOrbitRecon.py:100-105`](https://github.com/chz31/SlicerOrbitSurgerySim/blob/144ec0dfc2d52484d6a59ee1404d2a0933a08c08/MirrorOrbitRecon/MirrorOrbitRecon.py#L100-L105): When the user clicks the sample-data entry, downloadSampleDataInFolder downloads a ZIP from https://github.com/chz31/orbitSurgeySim_sampleData/raw/refs/heads/main/... with `checksums=None` (line 79) and then imports and runs any `setup.py` found in the chosen folder. Whoever controls that repository (or a compromised account / MITM without checksum verification) can execute arbitrary Python inside the user's Slicer process with the user's privileges. The same code exists in PlateRegistration/PlateRegistration.py:112-117. It currently fails only because `importlib` is not imported in either file, which is a one-line fix away from being live. Remove the setup.py execution entirely. If post-download setup is needed, implement it in the extension's own code, and pin the sample data to a fixed commit with a published SHA256 checksum passed to downloadFile.
- [`PlateRegistration/PlateRegistration.py:210-224`](https://github.com/chz31/SlicerOrbitSurgerySim/blob/144ec0dfc2d52484d6a59ee1404d2a0933a08c08/PlateRegistration/PlateRegistration.py#L210-L224): Simply opening the PlateRegistration module modifies Slicer's shared Python environment with unpinned pip installs, without a consent prompt. Unpinned installs can upgrade shared packages (e.g. numpy) that Slicer and other extensions rely on, affecting users who never use this module. The tutorial even tells users 'Required Python packages will be installed automatically' (Tutorials/00_Quick_Tutorial.md:84-86). Ask the user for confirmation before installing, pin compatible versions, and prefer declaring the dependency so the extension build/Extension Manager handles it.
- [`PlateRegistration/PlateRegistration.py:204`](https://github.com/chz31/SlicerOrbitSurgerySim/blob/144ec0dfc2d52484d6a59ee1404d2a0933a08c08/PlateRegistration/PlateRegistration.py#L204): This pattern (also MirrorOrbitRecon.py:392-399, 480-487, 520-527, 545-548) hides real errors such as a missing display node or an unset parameter, so the module can silently do nothing when the user clicks a button instead of reporting the problem. Example: onResetPushButton calls `self.halfModelRigidNode.GetDisplayNode.SetVisibility(False)` (missing parentheses, line 546) and the resulting AttributeError is swallowed. Catch specific exceptions and report unexpected ones to the user (slicer.util.errorDisplay) or log them.
- [`MirrorOrbitRecon/MirrorOrbitRecon.py:221`](https://github.com/chz31/SlicerOrbitSurgerySim/blob/144ec0dfc2d52484d6a59ee1404d2a0933a08c08/MirrorOrbitRecon/MirrorOrbitRecon.py#L221): onRigidMirroredHalfButton stores the half-model point sets in self.sourcePointsHalf/self.targetPointsHalf (line 466), but onAffineMirroredHalfButton passes the full-skull self.sourcePoints/self.targetPoints. The affine transform applied to the half model is therefore computed from the wrong point clouds, producing a silently wrong registration result that the user may then use for fit metrics. Use self.sourcePointsHalf and self.targetPointsHalf here.
- [`MirrorOrbitRecon/MirrorOrbitRecon.py:344-350`](https://github.com/chz31/SlicerOrbitSurgerySim/blob/144ec0dfc2d52484d6a59ee1404d2a0933a08c08/MirrorOrbitRecon/MirrorOrbitRecon.py#L344-L350): FPFH/RANSAC/ICP registration and the CPD affine step (line 372) run synchronously in the button slot with no progress dialog or cancellation, so Slicer appears frozen for the duration on large skull meshes. The same applies to the heatmap/projection batch operations in PlateRegistration. Run the heavy work in a CLI or a worker thread with progress reporting, or at minimum show a progress dialog with processEvents.
- [`PlateRegistration/PlateRegistration.py:44-54`](https://github.com/chz31/SlicerOrbitSurgerySim/blob/144ec0dfc2d52484d6a59ee1404d2a0933a08c08/PlateRegistration/PlateRegistration.py#L44-L54): Both modules are listed under the "Examples" category and their help text still says 'This is an example of scripted loadable module bundled in an extension. See more information in <a href="https://github.com/organization/projectname#PlateRegistration">module documentation</a>.' (lines 51-54; MirrorOrbitRecon.py:38-48 identical). Users looking for a planning tool will not find it, and the in-app help points to a nonexistent URL. Set a real category (e.g. Planning) and write help text linking to the tutorials in this repository.
- [`README.md:4`](https://github.com/chz31/SlicerOrbitSurgerySim/blob/144ec0dfc2d52484d6a59ee1404d2a0933a08c08/README.md#L4): The README markets the tool for 'clinical decision support' and plate ranking for surgery, but contains no statement that it is not cleared for clinical use and that results must be verified by a clinician. Users may treat computed fit metrics as validated surgical guidance. Add an explicit research-use-only / not-for-clinical-use disclaimer and describe the validation status of the fit metrics.
- [`Tutorials/00_Quick_Tutorial.md:39`](https://github.com/chz31/SlicerOrbitSurgerySim/blob/144ec0dfc2d52484d6a59ee1404d2a0933a08c08/Tutorials/00_Quick_Tutorial.md#L39): The extension downloads a ZIP from a separate repository (chz31/orbitSurgeySim_sampleData) containing segmentations derived from a third-party dataset, but neither the extension repository nor the README states the license of that data or of the derived segmentations. Distribution permission for the bundled/downloaded material is therefore unclear. State the license of the sample data (and of the source dataset) in the README and in the sample-data repository.
