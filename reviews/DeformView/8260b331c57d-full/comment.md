Suggestions for a later update:

- [`DeformView/DeformView.py:2065-2069`](https://github.com/elisedl1/SlicerDeformView/blob/8260b331c57d7d692957482e80bcbb19b86f3eb9/DeformView/DeformView.py#L2065-L2069): Compute discards the fixed/background volume's existing parent transform before calculations and later assigns the selected transform to it (line 2102), without restoring the prior relationship even if calculation fails. The slider also changes the shared input transform itself at lines 1262–1264, affecting any other nodes using it and potentially changing subsequently saved registration results. Operate on module-owned copies or derived nodes, preserve the original parent transform, and avoid mutating the user-selected transform.
- [`DeformView/DeformView.py:2191-2197`](https://github.com/elisedl1/SlicerDeformView/blob/8260b331c57d7d692957482e80bcbb19b86f3eb9/DeformView/DeformView.py#L2191-L2197): Compute creates a new map and calls this loader, which instead picks the first scene volume whose name contains the suffix. Lines 2233–2253 then copy the latest computed arrays into that selected volume. Recomputing after changing inputs can silently overwrite the old map or an unrelated matching user volume; different array sizes can instead raise an error. Load maps by the actual newly created node references or explicit user selection and never copy cached arrays into an independently selected node.
- [`DeformView/DeformView.py:779-786`](https://github.com/elisedl1/SlicerDeformView/blob/8260b331c57d7d692957482e80bcbb19b86f3eb9/DeformView/DeformView.py#L779-L786): The apply handler instead attaches the selected transform to backgroundVolume at line 2102 and displays it as the background. Thus the fixed image is moved even though the UI says it does not warp, potentially producing misleading overlays and interpretation. Keep the fixed image in its original coordinate system and explicitly define and test the mapping grid and transform direction in an end-to-end GUI test.
- [`DeformView/DeformView.py:1644-1649`](https://github.com/elisedl1/SlicerDeformView/blob/8260b331c57d7d692957482e80bcbb19b86f3eb9/DeformView/DeformView.py#L1644-L1649): The cursor RAS position is in world coordinates, but the volume's local RAS-to-IJK matrix does not invert its parent transform. The apply handler assigns a transform to the displacement map at line 2105, so with a non-identity parent the hover value can come from the wrong voxel or be reported out of bounds. Transform the cursor world position into the volume's local coordinates before applying RAS-to-IJK, or keep the output in world coordinates; test a translated and non-linear parent transform.
- [`DeformView/DeformView.py:454-456`](https://github.com/elisedl1/SlicerDeformView/blob/8260b331c57d7d692957482e80bcbb19b86f3eb9/DeformView/DeformView.py#L454-L456): When DeformViewWidget.setup() runs, enableVTKErrorTracking() replaces VTK's global singleton vtkOutputWindow with a new unconfigured vtkFileOutputWindow instance. This breaks Slicer's application-wide VTK error and warning logging for the rest of the session across all modules, and causes VTK to write a default output file in the current working directory. Note also that errorCallback defined in that method is never attached as an observer. Remove enableVTKErrorTracking() and the call to vtk.vtkOutputWindow.SetInstance(), or use standard Slicer logging without replacing the global VTK output window singleton.
- [`DeformView/DeformView.py:235-238`](https://github.com/elisedl1/SlicerDeformView/blob/8260b331c57d7d692957482e80bcbb19b86f3eb9/DeformView/DeformView.py#L235-L238): During widget setup, removeAllNamedNode collects and removes every node with this name without checking its class, origin or ownership (lines 683–707). A user's existing volume, transform, markup or color node named JacobianMap is removed merely by opening the module, potentially losing unsaved scene data and references. Keep references to extension-owned color nodes and remove only those created by this module; do not delete arbitrary nodes by name.
- [`DeformView/DeformView.py:1934-1936`](https://github.com/elisedl1/SlicerDeformView/blob/8260b331c57d7d692957482e80bcbb19b86f3eb9/DeformView/DeformView.py#L1934-L1936): In cleanup(), calling crosshairNode.RemoveAllObservers() removes all observers on the shared singleton crosshair node, not just the observer added by DeformView (which was already removed on lines 1929-1932). This can break other modules or Slicer components observing the crosshair node. Remove the crosshairNode.RemoveAllObservers() call and rely only on removing self.crosshairObserverTag.
- [`DeformView/DeformView.py:1238-1246`](https://github.com/elisedl1/SlicerDeformView/blob/8260b331c57d7d692957482e80bcbb19b86f3eb9/DeformView/DeformView.py#L1238-L1246): Grid, linear and other transforms can be used for maps but cannot use this advertised increment feature. README.md lines 76–79 describes the slider without this restriction, while the independent incremental logic tested in DeformViewTesting.py is not called by this slider. Document the restriction or implement and test GUI incremental visualization for the other supported transform types.
