Suggestions for a later update:

- [`DeformView/DeformView.py:454-456`](https://github.com/elisedl1/SlicerDeformView/blob/7ca647fe4d6550c5fa07939d3e10f7da8431dd17/DeformView/DeformView.py#L454-L456): When `DeformViewWidget.setup()` runs, `enableVTKErrorTracking()` replaces Slicer's global `vtkOutputWindow` singleton with a default `vtkFileOutputWindow()`. This redirects all subsequent VTK warnings and errors across the entire Slicer session away from Slicer's error log into a local file in the current working directory. Remove `enableVTKErrorTracking()` or do not replace the global `vtk.vtkOutputWindow` instance.
- [`DeformView/DeformView.py:235-240`](https://github.com/elisedl1/SlicerDeformView/blob/7ca647fe4d6550c5fa07939d3e10f7da8431dd17/DeformView/DeformView.py#L235-L240): During widget setup, removeAllNamedNode is called on a generic name. Its implementation at lines 688–707 removes every matching node without checking its class or ownership, so an unrelated unsaved image, segmentation, or other scene node named JacobianMap is deleted simply by opening DeformView. Manage only color nodes created by this extension, using a unique ownership attribute or stored node reference; never remove arbitrary same-named scene nodes.
- [`DeformView/DeformView.py:2191-2197`](https://github.com/elisedl1/SlicerDeformView/blob/7ca647fe4d6550c5fa07939d3e10f7da8431dd17/DeformView/DeformView.py#L2191-L2197): After a new computation, onLoadDisplacementVolume selects the first matching scene volume rather than the newly created one. Lines 2233–2253 then copy the newly computed array into that selected volume: if an older result has the same voxel count, its data is silently overwritten; if counts differ, the assignment can fail. This also applies to Jacobian maps when loaded. Keep explicit references to the newly computed output nodes and only restore arrays to their corresponding nodes after checking geometry; never select writable outputs by name substring.
- [`DeformView/DeformView.py:1262-1264`](https://github.com/elisedl1/SlicerDeformView/blob/7ca647fe4d6550c5fa07939d3e10f7da8431dd17/DeformView/DeformView.py#L1262-L1264): Changing the slider alters the selected transform itself rather than a display-only copy. Other scene nodes using this transform are also changed, and saving the scene while it is at an intermediate setting may preserve an unintended registration; selecting 0% actually applies 0.0001 rather than zero. Apply scaling to an extension-owned transform or resampled display copy, preserving the user's original transform and its prior scale.
- [`DeformView/DeformView.py:1934-1936`](https://github.com/elisedl1/SlicerDeformView/blob/7ca647fe4d6550c5fa07939d3e10f7da8431dd17/DeformView/DeformView.py#L1934-L1936): In `DeformViewWidget.cleanup()`, calling `crosshairNode.RemoveAllObservers()` removes all observers on the shared crosshair node, not just the observer added by `DeformView` (which is already removed via `self.crosshairObserverTag` immediately above). This can break other Slicer modules or built-in components (such as DataProbe) that observe crosshair movements. Remove the `crosshairNode.RemoveAllObservers()` call and rely solely on `self.crosshairNode.RemoveObserver(self.crosshairObserverTag)`.
- [`DeformView/DeformView.py:1238-1246`](https://github.com/elisedl1/SlicerDeformView/blob/7ca647fe4d6550c5fa07939d3e10f7da8431dd17/DeformView/DeformView.py#L1238-L1246): The module accepts general transform nodes, but the GUI disables incremental scaling when the underlying transform lacks this method. The README describes the slider without this restriction, and the analytic incremental test exercises a separate logic method rather than this UI path. Document the restriction or implement the slider for the other accepted transform types; add a GUI-path test.
- [`DeformView/DeformView.py:2274-2280`](https://github.com/elisedl1/SlicerDeformView/blob/7ca647fe4d6550c5fa07939d3e10f7da8431dd17/DeformView/DeformView.py#L2274-L2280): Each call to `onLoadDisplacementVolume` creates a new display node in the MRML scene via `AddNewNodeByClass`, then immediately overwrites the `internalDisplayNode` variable with `persistentDisplayNode`, leaving an orphaned, unused display node in the scene every time a volume is loaded. Remove the unused `slicer.mrmlScene.AddNewNodeByClass(persistentDisplayNode.GetClassName())` call.
- [`DeformView/DeformView.py:301`](https://github.com/elisedl1/SlicerDeformView/blob/7ca647fe4d6550c5fa07939d3e10f7da8431dd17/DeformView/DeformView.py#L301): `resetWindowLevelButton`'s `clicked(bool)` signal passes a boolean (`False`) as the first argument to `onResetWindowLevel(self, volumeNode)`. When `self.defaultWindow` and `self.defaultLevel` are set, `onResetWindowLevel` calls `volumeNode.GetDisplayNode()` on `False`, raising `AttributeError: 'bool' object has no attribute 'GetDisplayNode'`. Note also that `self.defaultWindow` and `self.defaultLevel` are never assigned (only `self.defaultWindow_DisplacementMag` / `self.defaultWindow_Jacobian` are assigned), so clicking the button currently re-runs `initializeWindowLevelControls` instead of resetting as intended. Change `onResetWindowLevel` to accept `checked=False` and retrieve `volumeNode = self.ui.loadedTransformVolume.currentNode()`, and check `self.defaultWindow_DisplacementMag` rather than `self.defaultWindow`.
