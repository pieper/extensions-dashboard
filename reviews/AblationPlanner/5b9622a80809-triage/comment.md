- [`AblationPlanner/AblationPlanner.py:382-388`](https://github.com/naterex23/SlicerAblationPlanner/blob/5b9622a808096cb2d1a7b14410c8b50b1b6f29a3/AblationPlanner/AblationPlanner.py#L382-L388): self.formerMarkupID and self.observerID are only assigned at the end of onProbeButton (lines 446-447). The same pattern appears in onProbeButton at lines 439-444. Neither handler has error handling, so the user sees a Python traceback instead of guidance. Initialise formerMarkupID/observerID to None in setup() and guard the observer removal; report a clear message when probes have not been placed yet.

- [`AblationPlanner/AblationPlanner.py:57`](https://github.com/naterex23/SlicerAblationPlanner/blob/5b9622a808096cb2d1a7b14410c8b50b1b6f29a3/AblationPlanner/AblationPlanner.py#L57): The template registration was left in place: the URI is a SlicerTestingData SHA256 blob (not ablation data), and thumbnailFileName points to Resources/Icons/AblationPlanner1.png, which does not exist (the only icon in that folder is AblationPlanner.png). - [`AblationPlanner/AblationPlanner.py:854-863`](https://github.com/naterex23/SlicerAblationPlanner/blob/5b9622a808096cb2d1a7b14410c8b50b1b6f29a3/AblationPlanner/AblationPlanner.py#L854-L863): test_AblationPlanner1 only shows delay dialogs and always reports 'Test passed', so the ctest registered by slicer_add_python_unittest (AblationPlanner/CMakeLists.txt:27) can never detect a regression. - [`AblationPlanner/AblationPlanner.py:746-751`](https://github.com/naterex23/SlicerAblationPlanner/blob/5b9622a808096cb2d1a7b14410c8b50b1b6f29a3/AblationPlanner/AblationPlanner.py#L746-L751): When the two probe direction vectors are parallel or antiparallel (a plausible user placement, e.g. two probes along the same needle track), s is 0 and the expression divides by zero, producing NaNs that are then written into the transform matrix. Similarly updateProbePosition (lines 498-504) divides by fiducialDistance1/2, which is zero if the tip and entry fiducials coincide. The resulting transform is silently invalid rather than reported. Handle the parallel/antiparallel and zero-length cases explicitly and report an error to the user instead of building a NaN transform.
- [`AblationPlanner/AblationPlanner.py:429-435`](https://github.com/naterex23/SlicerAblationPlanner/blob/5b9622a808096cb2d1a7b14410c8b50b1b6f29a3/AblationPlanner/AblationPlanner.py#L429-L435): Inside the loop, self.endPoints_positions is appended with xyz each iteration, then immediately reassigned to xyz. The append is dead code and misleads readers. Also, self.probeNodeIDs is indexed with endPoints_positions[i*2], which will raise IndexError if the fiducial count is odd or no probes were created. Remove the append and guard the index loop against odd counts and missing probe IDs; report the error to the user instead of printing.
- [`AblationPlanner/AblationPlanner.py:277-291`](https://github.com/naterex23/SlicerAblationPlanner/blob/5b9622a808096cb2d1a7b14410c8b50b1b6f29a3/AblationPlanner/AblationPlanner.py#L277-L291): None of the three nodes is checked before being passed to the FiducialRegistration CLI, and the returned CLI node status is ignored. If a selector is empty or the two fiducial sets have different point counts, the registration fails silently and the tumor is still attached to a transform node (line 291), so the user may believe the tumor was moved when it was not. Validate that both fiducial nodes exist and have equal, >=3 point counts, check the CLI status, and report failures with slicer.util.errorDisplay.
