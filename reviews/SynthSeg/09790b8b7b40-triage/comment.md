- [`SlicerSynthSeg/SlicerSynthSeg.py:993-995`](https://github.com/niyaziacer/SlicerSynthSeg/blob/09790b8b7b40fb2396312a055927eb9828a583b3/SlicerSynthSeg/SlicerSynthSeg.py#L993-L995): WITH_GENERIC_TESTS is enabled in SlicerSynthSeg/CMakeLists.txt:22, so this test runs in the extension build/CI, but it only displays two messages and always passes. It gives no signal about configuration loading, label-name parsing, colour-table construction or the CSV annotation step, all of which are testable without TensorFlow. Add assertions for the pure-Python helpers (getConfiguration defaults, _labelNames, _buildColorTableNode, _annotateVolumeCsv) and mark the segmentation run as skipped when models/TensorFlow are absent.
- [`SlicerSynthSeg/SlicerSynthSeg.py:58`](https://github.com/niyaziacer/SlicerSynthSeg/blob/09790b8b7b40fb2396312a055927eb9828a583b3/SlicerSynthSeg/SlicerSynthSeg.py#L58): installSlicerTensorFlow (lines 204-220) installs these exact pins into Slicer's own Python after user confirmation. numpy is protected by a constraints file, but TensorFlow's other transitive dependencies (protobuf, ml_dtypes, h5py, ...) are not, so other extensions that need different versions can break for users who accept the install. The pinned version also has to exist on PyPI for the Slicer Python version in use; if it does not, the install fails with a pip error rather than a clear message. Constrain the full dependency set (or install into a separate venv/launcher), and verify the pinned version exists for the Slicer Python versions you support.
- [`SlicerSynthSeg/SlicerSynthSegLib/synthseg_config.py:32-37`](https://github.com/niyaziacer/SlicerSynthSeg/blob/09790b8b7b40fb2396312a055927eb9828a583b3/SlicerSynthSeg/SlicerSynthSegLib/synthseg_config.py#L32-L37): Any error reading config.json (corrupt JSON, permission problem) is swallowed and the module silently falls back to defaults, so a user whose saved custom-Python configuration is unreadable sees the module behave as if never configured, with no diagnostic. The bare except also hides KeyboardInterrupt/SystemExit. Catch (OSError, ValueError) and log a warning naming the file and the error.
- [`SlicerSynthSeg/SlicerSynthSegLib/synthseg_config.py:77-82`](https://github.com/niyaziacer/SlicerSynthSeg/blob/09790b8b7b40fb2396312a055927eb9828a583b3/SlicerSynthSeg/SlicerSynthSegLib/synthseg_config.py#L77-L82): Any existing file passes validation, so a user who selects a non-executable or a Python without TensorFlow/nibabel gets 'Configuration saved successfully' and only discovers the problem when segmentation fails with a subprocess exit code. The dialog text (lines 477-478) promises a Python 'that has TensorFlow, Keras and nibabel'. Run the chosen interpreter once with a short import check (e.g. `-c "import tensorflow, nibabel"`) and report the result in the dialog.
- [`SlicerSynthSeg/SlicerSynthSeg.py:735-736`](https://github.com/niyaziacer/SlicerSynthSeg/blob/09790b8b7b40fb2396312a055927eb9828a583b3/SlicerSynthSeg/SlicerSynthSeg.py#L735-L736): With no saved configuration, synthseg_path defaults to bundledSynthSegPath() (lines 718-721), i.e. the installed extension tree under Slicer's qt-scripted-modules directory. downloadModelsWithProgress then mkdirs and writes ~150 MB of .h5 files there. If the extension is installed in a read-only or administrator-owned location (common for system-wide Slicer installs), the download fails with a permission error, and in all cases user data is written into an installation directory that extension updates may replace. Store models in a user-writable location (e.g. under slicer.app.userSettingsPath() or a per-user cache dir) and point SynthSeg at it, or copy the bundled source to a user directory on first use.
- [`SlicerSynthSeg/SlicerSynthSeg.py:927-938`](https://github.com/niyaziacer/SlicerSynthSeg/blob/09790b8b7b40fb2396312a055927eb9828a583b3/SlicerSynthSeg/SlicerSynthSeg.py#L927-L938): process() is called directly from onApplyButton (line 438) and spins on processEvents() for up to 30 minutes. The UI stays partially responsive but the user gets no progress or elapsed-time feedback and cannot cancel, which for a CPU-only SynthSeg run of several minutes looks like a freeze. Run the subprocess from a slicer.util.ProgressDialog / CLI-style worker with a cancel button, or at least show elapsed time and allow cancellation.
- [`README.md:42-44`](https://github.com/niyaziacer/SlicerSynthSeg/blob/09790b8b7b40fb2396312a055927eb9828a583b3/README.md#L42-L44): The README states TensorFlow installation changed h5py from 3.16.0 to 3.14.0 in the authors' environment. Installing TensorFlow into Slicer's Python can therefore break other extensions that depend on Slicer's shared packages. The numpy constraint in code does not protect h5py or other shared packages. Extend the pip constraints file to every package already installed in Slicer (not just numpy), or pin them to their current versions, so no existing package is downgraded.
