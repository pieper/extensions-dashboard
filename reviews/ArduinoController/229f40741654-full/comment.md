Please fix these before the extension can be merged:

- [`ArduinoConnect/ArduinoConnect.py:9-15`](https://github.com/pzaffino/SlicerArduinoController/blob/229f407416549b33f8431a960c7d0479a7a5b564/ArduinoConnect/ArduinoConnect.py#L9-L15): `ArduinoConnect.py` installs `pyserial` via `slicer.util.pip_install("pyserial")` at top-level module import time. Because Slicer imports all installed scripted modules during application startup, this triggers a network package installation on first launch after installing the extension, blocking startup and modifying Slicer's shared Python environment even for users who never open the module. Move the `serial` import and `slicer.util.pip_install("pyserial")` call out of the top-level module scope into `ArduinoConnectWidget.setup()` or `ArduinoConnectLogic.connect()` / `onDetectDeviceButton()` so that installation only occurs when the user interacts with the module.

Smaller suggestions:

- [`ArduinoPedalBoard/ArduinoPedalBoard.py:453-459`](https://github.com/pzaffino/SlicerArduinoController/blob/229f407416549b33f8431a960c7d0479a7a5b564/ArduinoPedalBoard/ArduinoPedalBoard.py#L453-L459): The self-tests in all three modules (`ArduinoConnectTest`, `ArduinoPedalBoardTest`, `ArduinoMotionSensorTest`) are unmodified boilerplate that call `logic.hasImageData(volumeNode)` (which does not exist on the logic classes), and `ArduinoPedalBoardTest.runTest` calls `self.test_ArduinoPedalBoard1()` while the method is named `test_ArduinoPedalBoard11`. Running the self-tests will fail with `AttributeError` or `TypeError`. Replace the template test methods with tests that instantiate the module logic and verify basic parameter node and message handling behavior.
- [`ArduinoPedalBoard/ArduinoPedalBoard.py:36-37`](https://github.com/pzaffino/SlicerArduinoController/blob/229f407416549b33f8431a960c7d0479a7a5b564/ArduinoPedalBoard/ArduinoPedalBoard.py#L36-L37): If a user opens the `ArduinoPedalBoard` or `ArduinoMotionSensor` module before ever opening `ArduinoConnect` (which creates the `"arduinoNode"` node in `ArduinoConnectLogic.__init__`), `slicer.mrmlScene.GetFirstNodeByName("arduinoNode")` returns `None`. In `ArduinoPedalBoardWidget.setup()` (line 50), `self.ArduinoNode.AddObserver(...)` will immediately raise an `AttributeError: 'NoneType' object has no attribute 'AddObserver'`. Similarly, in `ArduinoMotionSensorWidget.onStartButton()` (line 59), `self.ArduinoNode.AddObserver(...)` will fail if `ArduinoConnect` was not opened first. Additionally, `ArduinoPedalBoardLogic.__init__` (lines 186-188) creates a second duplicate node named `"arduinoNode"` in the scene without assigning it to `self.ArduinoNode`. Ensure a single shared singleton node or helper function retrieves or creates `"arduinoNode"` if it does not already exist in `slicer.mrmlScene`, and remove the duplicate node creation in `ArduinoPedalBoardLogic.__init__`.
- [`ArduinoConnect/ArduinoConnect.py:209-212`](https://github.com/pzaffino/SlicerArduinoController/blob/229f407416549b33f8431a960c7d0479a7a5b564/ArduinoConnect/ArduinoConnect.py#L209-L212): `ArduinoConnectWidget` saves the user's Arduino IDE executable path by writing directly to `Resources/ArduinoConnectConfig.json` inside the installed extension directory (`writeConfig` at lines 250-252). If Slicer or the extension is installed in a read-only or system-wide directory, `open(self.configFileName, 'w')` will fail with a `PermissionError`, and settings will not persist across extension updates. Store user preferences such as the Arduino IDE path in `slicer.app.userSettings()` (`qt.QSettings`) rather than writing into the installed module's `Resources` directory.
- [`ArduinoConnect/ArduinoConnect.py:448-449`](https://github.com/pzaffino/SlicerArduinoController/blob/229f407416549b33f8431a960c7d0479a7a5b564/ArduinoConnect/ArduinoConnect.py#L448-L449): The port is opened at line 426 without a read timeout, and polling runs in a Qt timer callback. If a device sends some bytes but no newline, readline waits indefinitely on the GUI thread, preventing interaction and risking loss of unsaved work if the user must terminate Slicer. Use nonblocking or bounded reads and accumulate partial lines, preferably with serial I/O isolated from the GUI thread.
- [`ArduinoPedalBoard/ArduinoPedalBoard.py:401-403`](https://github.com/pzaffino/SlicerArduinoController/blob/229f407416549b33f8431a960c7d0479a7a5b564/ArduinoPedalBoard/ArduinoPedalBoard.py#L401-L403): With button 3 configured to change views and button 2 configured for Slice Offset -, pressing button 2 in the yellow view only prints the offset. Unlike the red and green branches, it never calls SetSliceOffset, so the slice does not move. Apply the offset decrement in this branch and test all view/button mapping combinations.
- [`ArduinoPedalBoard/ArduinoPedalBoard.py:49-50`](https://github.com/pzaffino/SlicerArduinoController/blob/229f407416549b33f8431a960c7d0479a7a5b564/ArduinoPedalBoard/ArduinoPedalBoard.py#L49-L50): The widget's cleanup at lines 168-169 is empty, so the observer and callback remain attached until the observed node is destroyed. Reloading or recreating the widget can leave multiple callbacks processing each pedal message and changing slice views more than once. Remove the saved observer during cleanup and on scene changes, and disable the active pedal mapping when appropriate.
