Suggestions for a later update:

- [`LICENSE:1-3`](https://github.com/dmolony3/SlicerFractionalMyocardialMass/blob/b8d055933783c33f5c6e239b3790b38eeb8b2517/LICENSE#L1-L3): The MIT grant text is present, so distribution is permitted, but the copyright line still contains the template placeholders, so no licensor is identified and the notice cannot be reproduced as required by the license itself. The sample data published in the GitHub release has no stated license either. Fill in the year and copyright holder (e.g. David Molony) and state the license of the sample data assets.
- [`FMM/FMM.py:80-84`](https://github.com/dmolony3/SlicerFractionalMyocardialMass/blob/b8d055933783c33f5c6e239b3790b38eeb8b2517/FMM/FMM.py#L80-L84): The RCA/LCA markup sources pass checksums=None and the surface/volume sources omit checksums altogether (FMM/FMM.py:85-127), so the .vtp/.stl/.vtu/.mrk.json payloads pulled from the GitHub release are loaded into the scene without verification. Combined with the setup.py execution above, a tampered release asset would be consumed silently. Provide checksums for every registered sample data source.
- [`FMM/FMM.py:454-459`](https://github.com/dmolony3/SlicerFractionalMyocardialMass/blob/b8d055933783c33f5c6e239b3790b38eeb8b2517/FMM/FMM.py#L454-L459): addMMARArray marks a point as at-risk when its index in the concatenated polydata is >= the index of the closest point to the stenosis marker. Point order in the appended LCA/RCA polydata is an implementation detail of markupToPolyData, so the split between 'proximal' and 'distal' depends on insertion order rather than on arc length along the curve; results can silently be wrong for trees whose points are not ordered root-to-leaf. Compute the arc-length position of each point along its curve and compare with the arc-length position of the MMAR point.
- [`FMM/FMM.py:320-321`](https://github.com/dmolony3/SlicerFractionalMyocardialMass/blob/b8d055933783c33f5c6e239b3790b38eeb8b2517/FMM/FMM.py#L320-L321): The Voronoi point interpolation (FMM/FMM.py:469-486) and the per-cell Python loop in computeVolume (FMM/FMM.py:494-501) run synchronously in the Apply slot with only a wait cursor and a single status message. For the tetrahedral meshes the README recommends, Slicer will appear frozen with no progress or cancel option. Run the computation in a CLI or a worker thread with progress reporting, or at least report progress per cell block.
- [`FMM/FMM.py:336`](https://github.com/dmolony3/SlicerFractionalMyocardialMass/blob/b8d055933783c33f5c6e239b3790b38eeb8b2517/FMM/FMM.py#L336): segmentMesh creates a new table node literally named 'MMAR' on each run (FMM/FMM.py:584), and the widget then fetches it by name. After a second run there are several 'MMAR' nodes and getNode may return the wrong (stale) one or raise if the user renamed it; the scene also accumulates duplicate tables. Return the MMAR table node from segmentMesh (or store it in the parameter node) instead of looking it up by name, and reuse an existing node.
- [`FMM/FMM.py:581-583`](https://github.com/dmolony3/SlicerFractionalMyocardialMass/blob/b8d055933783c33f5c6e239b3790b38eeb8b2517/FMM/FMM.py#L581-L583): The MMAR table uses vtkIntArray for volumes in mm^3, so the fractional part of the computed volume is silently discarded. The table value for 'Myocardial volume at risk' and 'Total volume' is therefore inaccurate by up to 1 mm^3 per entry. Use vtk.vtkDoubleArray, consistent with the per-segment volume column.
- [`README.md:51-54`](https://github.com/dmolony3/SlicerFractionalMyocardialMass/blob/b8d055933783c33f5c6e239b3790b38eeb8b2517/README.md#L51-L54): EXTENSION_DEPENDS is "NA" (CMakeLists.txt:16), so SegmentMesher and SlicerVMTK are not installed with the extension; users following the README will not find the tools it tells them to use. The README also gives no statement that the computed FMM/MMAR values are research output and not validated for clinical decision making, which matters for a cardiac risk metric. Correct the dependency statement and add a short research-use disclaimer.
- [`FMM/FMM.py:58`](https://github.com/dmolony3/SlicerFractionalMyocardialMass/blob/b8d055933783c33f5c6e239b3790b38eeb8b2517/FMM/FMM.py#L58): registerSampleData is only called from the test (FMM/FMM.py:616); there is no `slicer.util.infoDisplay`/`startupCompleted` connection anywhere in the file, so the RCA/LCA/myocardium sample data never appears in the Sample Data module for normal users, contrary to the README's tutorial intent. Connect registerSampleData to slicer.app.startupCompleted as in the module template.
