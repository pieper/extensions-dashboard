Thanks for SeqSeg!

Please fix these before the extension can be merged:

- [`seqseg/seqseg.py:1951-1958`](https://github.com/numisveinsson/SlicerSeqSeg/blob/7d4e3959b0cef777673e9726292e22edf268a1f4/seqseg/seqseg.py#L1951-L1958): When the user runs SeqSeg, setupPythonRequirements() checks if numpy >= 2.0.0 and immediately runs `slicer.util.pip_install("numpy<2")` without user confirmation (before `confirmOkCancelDisplay` is ever reached), and additionally forces an exact pin of `torch==2.2.2` and `torchvision==0.17.2` (lines 1941-1942, 2022-2023). Downgrading Slicer's bundled numpy or overriding already-installed PyTorch/nnUNet versions modifies Slicer's shared Python environment and can break Slicer core or other installed extensions (such as TotalSegmentator or MONAI) that rely on Slicer's bundled numpy or a newer PyTorch build. Do not downgrade Slicer's bundled `numpy` package or force-pin `torch==2.2.2`. Instead, allow `PyTorchUtils` and `SlicerNNUNetLib` to use or install versions compatible with the current Slicer release, and ensure all package installations only happen after explicit user confirmation.

Smaller suggestions:

- [`seqseg/seqseg.py:2072-2075`](https://github.com/numisveinsson/SlicerSeqSeg/blob/7d4e3959b0cef777673e9726292e22edf268a1f4/seqseg/seqseg.py#L2072-L2075): If `PyTorch` and `nnunetv2` are already installed, `confirmPackagesToInstall` is empty so `slicer.util.confirmOkCancelDisplay` is skipped, yet `setupPythonRequirements()` still proceeds to query PyPI and run `pipInstallSelective` to install or upgrade `seqseg` and its transitive dependencies (`vtk`, `scipy`, `matplotlib`, etc., if any are declared by `seqseg` and not in `packagesToSkip`) without asking the user first. Furthermore, `packagesToSkip` omits `vtk` and `scipy` which Slicer bundles. Include `seqseg` in `confirmPackagesToInstall` so the user is always prompted before installing or upgrading `seqseg` from PyPI, and add `vtk`, `scipy`, and `pydicom` to `packagesToSkip` so `seqseg`'s dependencies cannot overwrite Slicer's bundled packages.
- [`seqseg/seqseg.py:2018-2023`](https://github.com/numisveinsson/SlicerSeqSeg/blob/7d4e3959b0cef777673e9726292e22edf268a1f4/seqseg/seqseg.py#L2018-L2023): Any installed torch version whose base version is not 2.2.2 is treated as requiring replacement, including newer versions used by other extensions. Although the PyTorch extension performs the install and a generic confirmation is shown, users are not told that an existing shared installation may be downgraded. Support compatible installed PyTorch versions and avoid forcing a shared exact version; if replacement is unavoidable, clearly disclose the current and proposed versions.
- [`seqseg/seqseg.py:2465-2467`](https://github.com/numisveinsson/SlicerSeqSeg/blob/7d4e3959b0cef777673e9726292e22edf268a1f4/seqseg/seqseg.py#L2465-L2467): Each run truncates any existing seeds.json in the chosen output directory without asking, including a user-maintained file unrelated to this run. Lines 2434–2438 likewise save the input volume to a predictable images/<sanitized-volume-name>.nii.gz, potentially replacing a previous image with the same name. Create a unique per-run workspace, or detect collisions and request explicit overwrite permission before writing any input or seed file.
- [`seqseg/seqseg.py:1547-1549`](https://github.com/numisveinsson/SlicerSeqSeg/blob/7d4e3959b0cef777673e9726292e22edf268a1f4/seqseg/seqseg.py#L1547-L1549): `_downloadNnunetWeightsFromZenodo` downloads a zip archive over HTTPS from fixed Zenodo record URLs and extracts it with `zip_ref.extractall(download_dir)` without verifying a cryptographic checksum (unlike `SampleData`) or validating archive member paths against path traversal (`..`). While the Zenodo URLs are hardcoded, verifying SHA256 checksums and validating zip member paths before extraction is safer practice. Verify the SHA256 checksum of the downloaded `.zip` archive before extracting, and validate that all member paths in the `ZipFile` resolve inside `download_dir` before extraction.
- [`seqseg/seqseg.py:1678`](https://github.com/numisveinsson/SlicerSeqSeg/blob/7d4e3959b0cef777673e9726292e22edf268a1f4/seqseg/seqseg.py#L1678): The output directory is reused and the search does not restrict files to the current case or require them to have been created during the run. If the CLI exits successfully without producing a new matching file, an earlier patient's or earlier run's segmentation may be loaded and displayed over the current volume as a successful result. Use a fresh per-run output directory and validate that the returned output belongs to the current case before loading it.
- [`seqseg/seqseg.py:2208-2215`](https://github.com/numisveinsson/SlicerSeqSeg/blob/7d4e3959b0cef777673e9726292e22edf268a1f4/seqseg/seqseg.py#L2208-L2215): `subprocess.run(["seqseg", ...])` is called synchronously on the main UI thread, freezing the Slicer GUI while nnUNet inference runs, and relies on `"seqseg"` being on the system `PATH`. On some platforms (especially Windows or macOS app bundles), Slicer's Python scripts directory is not necessarily on `PATH`, so invoking `seqseg` by bare executable name can fail with `FileNotFoundError` even when the `seqseg` package is installed in Slicer's Python environment. Invoke SeqSeg via `sys.executable` (e.g., `[sys.executable, "-m", "seqseg", ...]` or resolving the script path inside Slicer's Python `bin`/`Scripts` folder) so it reliably uses Slicer's Python environment.
