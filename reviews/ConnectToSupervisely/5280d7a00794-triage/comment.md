- [`ConnectToSupervisely/labelingJobsAnnotating.py:138-143`](https://github.com/supervisely-ecosystem/SlicerConnectToSupervisely/blob/5280d7a007948ac0486b57edaf55aefdb6479c6a/ConnectToSupervisely/labelingJobsAnnotating.py#L138-L143): enter() raises the root logger to CRITICAL and hides the Data Probe for the whole Slicer session while the module is open. The logger level is restored immediately, but the Data Probe change is global and only undone in exit(); if the module crashes or is reloaded, other modules keep the modified state. Use a module-scoped logger instead of the root logger and restore the Data Probe in cleanup() as well as exit().
- [`ConnectToSupervisely/moduleLib/baseLogic.py:157`](https://github.com/supervisely-ecosystem/SlicerConnectToSupervisely/blob/5280d7a007948ac0486b57edaf55aefdb6479c6a/ConnectToSupervisely/moduleLib/baseLogic.py#L157): With "Remember login" checked, Api.from_credentials(..., env_file=ENV_FILE_PATH) writes the server address and credentials/token to ~/supervisely_slicer.env (baseLogic.py:47) with default file permissions. On a shared workstation another local user can read the token. The behaviour is opt-in and documented in README.md:139, but the file is not permission-restricted. Create the env file with 0600 permissions and mention the plaintext storage in the UI next to the checkbox.
- [`ConnectToSupervisely/moduleLib/baseLogic.py:239`](https://github.com/supervisely-ecosystem/SlicerConnectToSupervisely/blob/5280d7a007948ac0486b57edaf55aefdb6479c6a/ConnectToSupervisely/moduleLib/baseLogic.py#L239): removeLocalData() recursively deletes self.savePath, which is built as os.path.join(self.workingDir, f"{self.activeJob.project_id}") (baseLogic.py:227) where workingDir comes from the user-editable working-directory button. If a user points the working directory at an existing folder, the extension deletes <workingDir>/<project_id> on logout/finish. The path is extension-derived, so risk is limited, but there is no guard that the directory belongs to the extension. Write a marker file into the download directory and refuse to delete a directory that lacks it.

If the refreshed job no longer contains that entity (for example after a sync or a server-side change), volumeId is unbound and the accept/reject action fails with an obscure error instead of a clear message. - [`ConnectToSupervisely/moduleLib/baseLogic.py:29`](https://github.com/supervisely-ecosystem/SlicerConnectToSupervisely/blob/5280d7a007948ac0486b57edaf55aefdb6479c6a/ConnectToSupervisely/moduleLib/baseLogic.py#L29): The import is wrapped in try/except ModuleNotFoundError, but BaseLogic.__init__ immediately calls dotenv.get_key(ENV_FILE_PATH, "WORKING_DIR") (baseLogic.py:78). Declare python-dotenv in requirements.txt and handle its absence explicitly in import_supervisely().
