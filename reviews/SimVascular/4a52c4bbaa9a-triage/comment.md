Suggestions for a later update:

- [`SeqSeg/Testing/Python/CMakeLists.txt:2`](https://github.com/SimVascular/SlicerSimVascular/blob/4a52c4bbaa9a500f0012c8488331e9546a1abc74/SeqSeg/Testing/Python/CMakeLists.txt#L2): The same commented-out line appears in SDFStent, PaintModel, FaceAwareRemesh and SeqSeg Testing/Python/CMakeLists.txt, so the in-module `ScriptedLoadableModuleTest` classes (e.g. PaintModel/PaintModel.py:1070-1133) are never run by ctest. The package-level pytest suites exist (FaceAwareRemesh/tests, SimVascularMeshPrep/Testing/Python) but are not wired into the build either, so a regression in these modules would not be caught by the extension build. Register the existing module tests with `slicer_add_python_unittest`, or add a ctest that runs the package pytest suites.
- [`PaintModel/PaintModel.py:250-256`](https://github.com/SimVascular/SlicerSimVascular/blob/4a52c4bbaa9a500f0012c8488331e9546a1abc74/PaintModel/PaintModel.py#L250-L256): `createFaceGroups` builds per-cell normals, an edge map and a merge loop over all cells (lines 905-975) synchronously on the GUI thread with only a wait cursor and no progress or cancel, so a large surface freezes Slicer. The module also adds `ModelFaceID` and `_PaintModelSelectionDisplay` arrays directly to the user's model node polydata, so the in-memory model is modified without an undo snapshot for the selection overlay (only `onClearFaceGroups` calls `SaveStateForUndo`, line 278). Run the grouping in a `qt.QTimer`/worker with progress and cancellation, and take an undo snapshot before the first modification of the model.
- [`SDFStent/SDFStent.py:1079-1082`](https://github.com/SimVascular/SlicerSimVascular/blob/4a52c4bbaa9a500f0012c8488331e9546a1abc74/SDFStent/SDFStent.py#L1079-L1082): Inserting the module directory at position 0 can shadow other top-level packages imported later in the session. The effect is global to the process.
- [`SimVascularROM/SimVascularROM.py:253-258`](https://github.com/SimVascular/SlicerSimVascular/blob/4a52c4bbaa9a500f0012c8488331e9546a1abc74/SimVascularROM/SimVascularROM.py#L253-L258): The ROM panel installs `svromutils` with `--no-deps` and skips vmtk/vtk/numpy/scipy (ROM_PACKAGE_SKIPPED_DEPENDENCIES, line 173), and `svzerod` whole, after a confirmation dialog. This is the careful pattern the policy asks for, but `svzerod` is installed with its own dependencies (numpy unpinned, pandas) into Slicer's environment, so a future release could still change Slicer's NumPy. Worth documenting the residual risk or pinning the solver install. Consider installing svzerod with `--no-deps` plus an explicit skip list for numpy/pandas, or verify after install that Slicer's numpy version is unchanged.
- [`SeqSeg/seqseg.py:2304-2310`](https://github.com/SimVascular/SlicerSimVascular/blob/4a52c4bbaa9a500f0012c8488331e9546a1abc74/SeqSeg/seqseg.py#L2304-L2310): The archive comes from Zenodo over HTTPS after a user confirm, with no checksum verification and no member path validation before extractall. A malicious archive could write outside the target folder. The risk is limited by the trusted hosts, but integrity is not checked.
