Please fix these before the extension can be merged:

- [`AnnotationPanel/CMakeLists.txt:6-11`](https://github.com/TeamOrydex/SlicerAnnotationPanel/blob/8f15ebf7c7b23f7b4f7120f190bec89cbdd73bae/AnnotationPanel/CMakeLists.txt#L6-L11): `AnnotationPanel/CMakeLists.txt` only lists `AnnotationPanel.py` in `KIT_PYTHON_SCRIPTS` and leaves `KIT_PYTHON_RESOURCES` empty. When Slicer builds and packages this extension for the Extensions Manager, CMake will only install `AnnotationPanel.py` into `${Slicer_INSTALL_QTSCRIPTEDMODULES_LIB_DIR}`, omitting all the sibling modules it imports (`AnnotationModel.py`, `ClassLabelTab.py`, `ConfigurationScreen.py`, `ConfigurationValidation.py`, `LabelColors.py`, `PanelWidget.py`, `PresetStorage.py`, `ROITab.py`, `RadiologyTerms.py`, `SegmentationTab.py`, `SliceInfo.py`) as well as the module icon (`Resources/Icons/AnnotationPanel.png`). Consequently, when Slicer attempts to load `AnnotationPanel.py` from an installed extension package, the import check at lines 16-23 of `AnnotationPanel.py` (`import LabelColors`, `import PresetStorage`) will immediately raise `ImportError` and the module will fail to load at Slicer startup. List all Python files required by the module in `KIT_PYTHON_SCRIPTS` (or in a subdirectory package) and add `Resources/Icons/AnnotationPanel.png` to `KIT_PYTHON_RESOURCES` so that `ctkMacroCompilePythonScript` copies and installs them into the extension package.

Smaller suggestions:

- [`AnnotationPanel/SliceInfo.py:271-277`](https://github.com/TeamOrydex/SlicerAnnotationPanel/blob/8f15ebf7c7b23f7b4f7120f190bec89cbdd73bae/AnnotationPanel/SliceInfo.py#L271-L277): IJK axes depend on the volume's orientation, not on anatomical plane names. For permuted or oblique acquisitions this can export a different voxel axis as the slice index; additionally, index zero falls through to a different calculation in capture_slice_info_for_view. Derive the relevant axis and index from the volume and slice geometry, and explicitly handle zero and oblique views in tests.
- [`AnnotationPanel/PanelWidget.py:232-235`](https://github.com/TeamOrydex/SlicerAnnotationPanel/blob/8f15ebf7c7b23f7b4f7120f190bec89cbdd73bae/AnnotationPanel/PanelWidget.py#L232-L235): When importing a different configuration, the preset name is derived from the imported scan or directory. If that name already exists, save_preset_overwrite truncates and replaces its JSON without asking; importing another package with the same name can destroy the user's previously saved configuration. Check for name collisions and ask before replacement, or save to a unique name; use atomic writes.
- [`AnnotationPanel/PanelWidget.py:548-553`](https://github.com/TeamOrydex/SlicerAnnotationPanel/blob/8f15ebf7c7b23f7b4f7120f190bec89cbdd73bae/AnnotationPanel/PanelWidget.py#L548-L553): The matching-configuration import path calls set_record with its default clear_existing=True, without the replacement prompt used for differing configurations. Existing ROI and segmentation scene nodes and classification annotations are removed, including unsaved work; a subsequent segmentation load can also fail after this destruction. Explicitly confirm replacement whenever existing annotations are present, and load and validate the incoming project before deleting the old session.
- [`AnnotationPanel/SliceInfo.py:72-79`](https://github.com/TeamOrydex/SlicerAnnotationPanel/blob/8f15ebf7c7b23f7b4f7120f190bec89cbdd73bae/AnnotationPanel/SliceInfo.py#L72-L79): The eventFilter method closes over the loop-local name _remember_view rather than binding the current callback. After the loop completes, filters can all use the last view's callback, so mouse or wheel events in another view may record the wrong active slice and thus the wrong ROI context. Bind the view name or callback separately to each tracker instance and test interactions in all slice views.
- [`AnnotationPanel/AnnotationPanel.py:11-18`](https://github.com/TeamOrydex/SlicerAnnotationPanel/blob/8f15ebf7c7b23f7b4f7120f190bec89cbdd73bae/AnnotationPanel/AnnotationPanel.py#L11-L18): At module import time (which happens during Slicer startup for all scripted loadable modules), `AnnotationPanel.py` inserts its directory at the front of `sys.path` and imports top-level modules with generic names (`LabelColors`, `PresetStorage`, and later `PanelWidget`, `AnnotationModel`, `SliceInfo`, `ROITab`, `SegmentationTab`, `ClassLabelTab`, `ConfigurationScreen`). While Slicer normally adds scripted module directories or packages, placing 11 generic top-level module names in `sys.path[0]` at startup risks name collisions with other Slicer extensions in the shared Python environment. Move the helper modules into a dedicated Python package directory (e.g., `AnnotationPanelLib/`) and install them via `KIT_PYTHON_SCRIPTS`, importing them as `from AnnotationPanelLib import ...`.
- [`AnnotationPanel/AnnotationModel.py:1039-1043`](https://github.com/TeamOrydex/SlicerAnnotationPanel/blob/8f15ebf7c7b23f7b4f7120f190bec89cbdd73bae/AnnotationPanel/AnnotationModel.py#L1039-L1043): Patient ID and DICOM identifiers are automatically captured and written into the user-selected export. Users sharing annotation packages may not realize they contain identifiers: the README mentions series metadata and UIDs but does not explicitly mention patient ID. No automatic network transmission was found. Warn in the export dialog and documentation, and offer a de-identified export option.
- [`AnnotationPanel/PanelWidget.py:742-746`](https://github.com/TeamOrydex/SlicerAnnotationPanel/blob/8f15ebf7c7b23f7b4f7120f190bec89cbdd73bae/AnnotationPanel/PanelWidget.py#L742-L746): `install_slice_tracking()` in `SliceInfo.py` attaches VTK observers and Qt event filters to Slicer's Red/Green/Yellow slice nodes, interactors, and slice views, storing them in the module-level `_slice_observers` list. Although `SliceInfo.py` defines `remove_slice_tracking()`, `AnnotationPanelRootWidget.cleanup()` never calls `remove_slice_tracking()`, leaving those observers and event filters active after the widget is cleaned up. Call `remove_slice_tracking()` inside `AnnotationPanelRootWidget.cleanup()`.
