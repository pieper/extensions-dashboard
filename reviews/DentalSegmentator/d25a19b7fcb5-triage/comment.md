Suggestions for a later update:

- [`DentalSegmentator/DentalSegmentatorLib/SegmentationWidget.py:179-190`](https://github.com/gaudot/SlicerDentalSegmentator/blob/d25a19b7fcb59724a0faedf775f885d187880f56/DentalSegmentator/DentalSegmentatorLib/SegmentationWidget.py#L179-L190): The widget adds a scene observer (line 175) but has no cleanup() override, so the observer is only removed if Python's __del__ happens to run (unreliable under PythonQt and on module reload), leaving a dangling callback into a destroyed widget. onSceneChanged also calls AddNewNodeByClass("vtkMRMLSegmentEditorNode") on every scene close without removing the previous node, accumulating orphan nodes in the scene. Override cleanup() to remove the observer and disconnect signals; reuse or remove the previous segmentEditorNode in onSceneChanged.
- [`DentalSegmentator/DentalSegmentatorLib/SegmentationWidget.py:608`](https://github.com/gaudot/SlicerDentalSegmentator/blob/d25a19b7fcb59724a0faedf775f885d187880f56/DentalSegmentator/DentalSegmentatorLib/SegmentationWidget.py#L608): When the user ticks glTF export and clicks Export, the module installs a third-party extension from the Slicer server and then registers and loads its module (factory.registerModule/loadModules) without any confirmation dialog. The user asked to export a file, not to install software; the install also persists in their Slicer profile. The source is the official extension server, so the risk is limited, but the action is unannounced. Ask the user before installing (or simply tell them to install SlicerOpenAnatomy and abort the glTF export).
- [`DentalSegmentator/DentalSegmentatorLib/PythonDependencyChecker.py:15-19`](https://github.com/gaudot/SlicerDentalSegmentator/blob/d25a19b7fcb59724a0faedf775f885d187880f56/DentalSegmentator/DentalSegmentatorLib/PythonDependencyChecker.py#L15-L19): requests.ReadTimeout (and other RequestException subclasses such as TooManyRedirects or SSLError) are not ConnectionError, so on a slow or filtered network the exception escapes hasInternetConnection() and surfaces as an unhandled traceback in the module instead of the intended 'no internet' path. Catch requests.RequestException (or requests.exceptions.Timeout as well).
- [`DentalSegmentator/DentalSegmentatorLib/PythonDependencyChecker.py:74-75`](https://github.com/gaudot/SlicerDentalSegmentator/blob/d25a19b7fcb59724a0faedf775f885d187880f56/DentalSegmentator/DentalSegmentatorLib/PythonDependencyChecker.py#L74-L75): The code takes the first asset of the first release and extracts it with zipfile.extractall (line 166) with no checksum or signature check. The extracted nnU-Net checkpoint is later deserialized by the NNUNet extension (torch.load), so a compromised or replaced release asset would be executed as pickle data on the user's machine. HTTPS to github.com limits but does not remove this risk, and there is no pinning to a known-good release. Pin the expected release asset and verify a published SHA-256 (or signature) before extraction; fail loudly on mismatch.
- [`DentalSegmentator/DentalSegmentatorLib/PythonDependencyChecker.py:142`](https://github.com/gaudot/SlicerDentalSegmentator/blob/d25a19b7fcb59724a0faedf775f885d187880f56/DentalSegmentator/DentalSegmentatorLib/PythonDependencyChecker.py#L142): The zip is taken from the first asset of the latest GitHub release, with no checksum, signature, or pinned hash. It is extracted with zipfile.extractall into the module folder. The source is the author's own release, so the risk is limited to a compromised release or a malicious archive entry path (zip slip). The code does not validate member names. Pin and verify a SHA-256 for the expected weights archive, and validate member paths before extraction.
- [`README.md:326`](https://github.com/gaudot/SlicerDentalSegmentator/blob/d25a19b7fcb59724a0faedf775f885d187880f56/README.md#L326): The extension code is Apache-2.0 (LICENSE.txt), but the nnU-Net checkpoint that the module downloads and runs (README.md:294-318, PythonDependencyChecker.py:115-166) has no license statement in the repository. Users and downstream packagers therefore cannot tell under what terms the model may be used or redistributed; the Zenodo record may state terms but that is not referenced here. State the weights' license (and any research-only restriction) in README.md and next to the release assets.
- [`DentalSegmentator/DentalSegmentatorLib/PythonDependencyChecker.py:14-19`](https://github.com/gaudot/SlicerDentalSegmentator/blob/d25a19b7fcb59724a0faedf775f885d187880f56/DentalSegmentator/DentalSegmentatorLib/PythonDependencyChecker.py#L14-L19): hasInternetConnection() is called from PythonDependencyChecker.__init__ (line 47) and from areWeightsOutdated/downloadWeights, so simply opening the DentalSegmentator module sends an HTTP request to a third party (Google) with the user's IP and user agent, with no opt-in and no disclosure. It also misreports 'no internet' on networks that block Google (e.g. some hospital or Chinese networks), disabling weight download. No medical data is transmitted. Probe the actual endpoint you need (e.g. api.github.com or the release URL) instead of google.com, and only do so when the user triggers a download.
- [`README.md:206-208`](https://github.com/gaudot/SlicerDentalSegmentator/blob/d25a19b7fcb59724a0faedf775f885d187880f56/README.md#L206-L208): The README advertises clinical workflows (guided tooth autotransplantation, endodontics, orbital surgery planning) and the module is offered in the Segmentation category, but there is no statement that the output is not validated for primary diagnosis or treatment planning. Users may over-trust an unvalidated AI output in patient care. Add an explicit research-use / not-a-medical-device disclaimer to README.md and the module help text.
