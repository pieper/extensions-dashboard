- [`ScapularMorphology/Scripts/scapularmorphology_inference.py:110`](https://github.com/liukuan5625/SlicerScapularMorphology/blob/28fe666318286c72303515ba32902b51cf1864a5/ScapularMorphology/Scripts/scapularmorphology_inference.py#L110): downloadModel() fetches model_2d.pt/model_3d.pt with `checksum=None` (ScapularMorphology.py:381-382) and the inference script (also line 175) unpickles them with weights_only=False. If the release asset or the download is tampered with, arbitrary Python code runs with the user's privileges in the PythonSlicer subprocess. There is no integrity check anywhere in the chain. Pin expected SHA256 checksums for both weight files and pass them to downloadFile, and load with `weights_only=True` (or load a state_dict-only checkpoint) so no pickle code can execute.
- [`ScapularMorphology/ScapularMorphology.py:616-618`](https://github.com/liukuan5625/SlicerScapularMorphology/blob/28fe666318286c72303515ba32902b51cf1864a5/ScapularMorphology/ScapularMorphology.py#L616-L618): `returnNode` was removed from slicer.util load functions in current Slicer, so the registered unittest (slicer_add_python_unittest in ScapularMorphology/CMakeLists.txt:27) raises TypeError. The test also downloads sample data into the extension's Scripts folder and runs full GPU/CPU inference, so it cannot serve as a CI smoke test. Use the current load API, keep test data in a temporary directory, and make the test skip gracefully when network or models are unavailable.
- [`ScapularMorphology/ScapularMorphology.py:390-393`](https://github.com/liukuan5625/SlicerScapularMorphology/blob/28fe666318286c72303515ba32902b51cf1864a5/ScapularMorphology/ScapularMorphology.py#L390-L393): updateGUIFromParameterNode compares `GetParameter("Heat") == "true"` (lines 221-222) while the default is "True", so on a fresh scene the checkboxes do not reflect the stored state and the saved settings are not restored consistently. Use one canonical value (e.g. "true"/"false") everywhere.
- [`ScapularMorphology/Scripts/scapularmorphology_inference.py:84-85`](https://github.com/liukuan5625/SlicerScapularMorphology/blob/28fe666318286c72303515ba32902b51cf1864a5/ScapularMorphology/Scripts/scapularmorphology_inference.py#L84-L85): An empty slice range (e.g. scapula and humerus masks never within 25 mm, or an IS range outside the volume) aborts with a bare AssertionError instead of a user-readable message. Related: `np.int8(np.round(gc_idx))` (line 154) overflows for indices above 127 in the 512-wide crop, and `affine = ori_aff_mat` followed by in-place modification (lines 89-90) mutates the original affine metadata. Raise a descriptive error, use int32/int64 for indices, and copy the affine before modifying it.
- [`ScapularMorphology/Resources/UI/ScapularMorphology.ui:41`](https://github.com/liukuan5625/SlicerScapularMorphology/blob/28fe666318286c72303515ba32902b51cf1864a5/ScapularMorphology/Resources/UI/ScapularMorphology.ui#L41): The .ui declares vtkMRMLScalarVolumeNode for both inputs and the output, the code overrides them to vtkMRMLSegmentationNode (ScapularMorphology.py:103-105), and initializeParameterNode() auto-selects the first vtkMRMLScalarVolumeNode into 'ScapulaVolume'/'HumerusVolume' (lines 176-183), which the segmentation-only selectors cannot display. The masks are then written with a vtkMRMLSegmentationStorageNode to a .nrrd file (lines 488-491) and read back by MONAI LoadImage, which is unlikely to yield the single binary mask the pipeline expects. Make the .ui, the code and the parameter-node defaults agree on segmentation nodes, and verify the written file is a binary labelmap the inference script can consume.
- [`ScapularMorphology/Scripts/scapularmorphology_inference.py:154`](https://github.com/liukuan5625/SlicerScapularMorphology/blob/28fe666318286c72303515ba32902b51cf1864a5/ScapularMorphology/Scripts/scapularmorphology_inference.py#L154): np.int8 wraps values outside -128 to 127. CT slice and voxel indices routinely exceed 127, so the glenoid index wraps to a wrong value and is passed on to cal_landmarks. The landmark index list is not written to the output in the current code, so the visible effect is limited, but the cast is wrong. Use np.int32 or plain integers, and apply the same fix to the landmark index cast on line 194.
- [`README.md:16`](https://github.com/liukuan5625/SlicerScapularMorphology/blob/28fe666318286c72303515ba32902b51cf1864a5/README.md#L16): The extension code is MIT, but nothing in the repository states the terms under which model_2d.pt and model_3d.pt (and the linked training repository) may be redistributed or used, and the 2D model also initializes with `encoder_weights="imagenet"` (scapularmorphology_inference.py:103), which downloads third-party pretrained weights at runtime. Users and the index cannot tell whether the weights are research-only. State the weights' license/provenance in the README (and in the release notes), and note any non-commercial or research-only restriction.
- [`ScapularMorphology/ScapularMorphology.py:516-517`](https://github.com/liukuan5625/SlicerScapularMorphology/blob/28fe666318286c72303515ba32902b51cf1864a5/ScapularMorphology/ScapularMorphology.py#L516-L517): process() runs pip installs (line 436), the weight download (line 437) and the blocking readline loop of logProcessOutput on the GUI thread, so Slicer freezes for the whole run (minutes on first use, when pip installs and downloads happen) with only a wait cursor and no progress or cancel. Run the pipeline in a CLI node or a worker thread with progress reporting, and separate dependency installation from the inference step.
