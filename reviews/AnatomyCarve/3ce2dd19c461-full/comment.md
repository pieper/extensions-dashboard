Suggestions for a later update:

- [`AnatomyCarve/AnatomyCarveLogic/AnatomyCarveLogic.py:328-337`](https://github.com/andrey-titov/SlicerAnatomyCarve/blob/3ce2dd19c461184cf17456bdbbd84a30c6ad8f7b/AnatomyCarve/AnatomyCarveLogic/AnatomyCarveLogic.py#L328-L337): The array has four floats per actual control point, but the native OpenGL call is told to read 32 vec4s. Rendering starts with one point, so absent wrapper-side padding this asks the driver to read beyond the NumPy allocation, potentially crashing Slicer or uploading unrelated process memory to the GPU. The call is made on every render. Upload only the actual number of vectors, or explicitly allocate and zero-pad a contiguous 32-by-4 array; enforce the 32-sphere limit and test with one and many spheres.
- [`AnatomyCarve/AnatomyCarveLogic/AnatomyCarveLogic.py:228-234`](https://github.com/andrey-titov/SlicerAnatomyCarve/blob/3ce2dd19c461184cf17456bdbbd84a30c6ad8f7b/AnatomyCarve/AnatomyCarveLogic/AnatomyCarveLogic.py#L228-L234): When `startRender` is called, an observer for `vtkCommand.StartEvent` is added to the 3D view's `vtkRenderWindow`, but `observerTag` is stored only in a local variable and is never removed when the scene closes, when the module is exited/cleaned up, or if rendering is restarted. If the scene is closed afterwards, `applyCarveVoxelsComputeShaderTick` will continue to fire on every render of the 3D view and attempt to access deleted/stale MRML nodes and textures. Store `observerTag` and the observed `renderWindow` on `self`, and provide a cleanup method (called on scene close and widget cleanup) that removes the observer from `renderWindow` and releases OpenGL textures.
- [`AnatomyCarve/AnatomyCarveLogic/Context.py:211-213`](https://github.com/andrey-titov/SlicerAnatomyCarve/blob/3ce2dd19c461184cf17456bdbbd84a30c6ad8f7b/AnatomyCarve/AnatomyCarveLogic/Context.py#L211-L213): The label map is generated in the segmentation's saved reference geometry and uploaded without resampling to the selected intensity volume. FillColorVolume.comp then indexes both grids with the same coordinates, so differing origins, extents, spacing, directions or transforms can produce displaced or missing anatomy and incorrect clipping. Resample the segmentation into the selected intensity volume's geometry, including transforms, or reject mismatched inputs with a clear message. Add tests with different extents and geometry.
- [`AnatomyCarve/AnatomyCarve.py:22-25`](https://github.com/andrey-titov/SlicerAnatomyCarve/blob/3ce2dd19c461184cf17456bdbbd84a30c6ad8f7b/AnatomyCarve/AnatomyCarve.py#L22-L25): When 'OpenGL' cannot be imported, the module file calls slicer.util.pip_install at import. Slicer imports scripted modules at startup, so this changes the shared Python environment and downloads from the network for anyone who installed the extension. It happens without confirmation, and a failure will leave later wildcard imports broken. Defer the OpenGL import to the widget or logic. Ask the user before installing PyOpenGL, ideally from a button in the module UI. Show an error if installation fails.
- [`AnatomyCarve/AnatomyCarve.py:483-488`](https://github.com/andrey-titov/SlicerAnatomyCarve/blob/3ce2dd19c461184cf17456bdbbd84a30c6ad8f7b/AnatomyCarve/AnatomyCarve.py#L483-L488): The test downloads a segmentation and constructs the logic but never renders a volume or asserts clipping results. Regressions in the central visualization workflow can therefore pass the registered test. Add automated checks for rendering, sphere limits, segmentation geometry and cleanup, with an appropriate OpenGL-capable test environment.
- [`AnatomyCarve/AnatomyCarveLogic/AnatomyCarveLogic.py:49-50`](https://github.com/andrey-titov/SlicerAnatomyCarve/blob/3ce2dd19c461184cf17456bdbbd84a30c6ad8f7b/AnatomyCarve/AnatomyCarveLogic/AnatomyCarveLogic.py#L49-L50): AnatomyCarveLogic.__init__ calls glCreateShader and glCompileShader via ComputeShader before any 3D view's context is made current. That happens when the widget is created. The calls may fail or act on the wrong context. Later GL work runs from a render StartEvent observer that is never removed, and errors there are only cleared with glGetError. Create shaders lazily in startRender after calling renderWindow.MakeCurrent(). Remove the StartEvent observer on cleanup. Check the GL version and report a clear error if OpenGL 4.3 is not available.
- [`VolumeTextureIDHelper/qSlicerVolumeTextureIDHelperModule.cxx:71`](https://github.com/andrey-titov/SlicerAnatomyCarve/blob/3ce2dd19c461184cf17456bdbbd84a30c6ad8f7b/VolumeTextureIDHelper/qSlicerVolumeTextureIDHelperModule.cxx#L71): A VolumeTextureIDHelper.zip is committed, and the helper's module metadata still holds placeholder help, contributor and funding text (John Doe, NIH grant NXNN...). The C++ module also carries an unused FooBar widget. The module's category is 'Examples', and it is hidden. Remove the zip and the unused FooBar widget. Fill in real module metadata.
