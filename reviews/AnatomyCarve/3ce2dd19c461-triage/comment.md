Suggestions for a later update:

- [`AnatomyCarve/AnatomyCarveLogic/Context.py:112`](https://github.com/andrey-titov/SlicerAnatomyCarve/blob/3ce2dd19c461184cf17456bdbbd84a30c6ad8f7b/AnatomyCarve/AnatomyCarveLogic/Context.py#L112): Starting a render silently replaces the slice views' background layer chosen by the user and adds an 'AnatomyCarve Output' vector volume plus a volume-rendering display node to the scene. If the user starts the module again (new scene, or after a failed start that left nodes behind), duplicates accumulate and the user's slice layout is overwritten without a way to undo from the module. Nothing is deleted permanently, but the scene is modified without consent. Reuse an existing output node if present, ask or warn before replacing the slice background, and remove the temporary nodes when rendering stops.
- [`AnatomyCarve/AnatomyCarveLogic/AnatomyCarveLogic.py:48-50`](https://github.com/andrey-titov/SlicerAnatomyCarve/blob/3ce2dd19c461184cf17456bdbbd84a30c6ad8f7b/AnatomyCarve/AnatomyCarveLogic/AnatomyCarveLogic.py#L48-L50): The logic object is created in AnatomyCarveWidget.setup(), i.e. the first time the user opens the module, and it immediately calls glCreateShader/glCompileShader. With no current OpenGL context (and certainly on macOS, where the OpenGL 4.3 compute shaders are unavailable) this raises from ComputeShader.createComputeShader and the module widget fails to appear with a raw driver error, instead of a readable 'OpenGL 4.3 required' message as the README's Windows/Linux prerequisite implies. Defer shader creation to the Render action inside tryWithErrorDisplay, and check the GL version up front to give a clear message.
- [`AnatomyCarve/AnatomyCarveLogic/Texture.py:57-62`](https://github.com/andrey-titov/SlicerAnatomyCarve/blob/3ce2dd19c461184cf17456bdbbd84a30c6ad8f7b/AnatomyCarve/AnatomyCarveLogic/Texture.py#L57-L62): A constant-intensity volume (min == max, e.g. a mask-like or empty volume a user picks by accident) yields an all-NaN texture, so the render appears blank/black with no error shown. Similarly Mask.createTexture (Mask.py:55-58) and Context.createLabelToColorMap (Context.py:56-59) call max(...) over the segmentation's segment IDs, which raises ValueError for a segmentation with no segments; the widget auto-selects the first segmentation node in the scene, which can be empty. Guard max == min (skip normalisation) and validate that the segmentation has at least one segment, reporting a clear message to the user.
- [`AnatomyCarve/AnatomyCarve.py:468`](https://github.com/andrey-titov/SlicerAnatomyCarve/blob/3ce2dd19c461184cf17456bdbbd84a30c6ad8f7b/AnatomyCarve/AnatomyCarve.py#L468): This unittest is registered as a ctest (AnatomyCarve/CMakeLists.txt:38) but only downloads the sample data and prints 'Test passed'; no assertion covers the logic, the OpenGL path or the sample-data checksum, so CI cannot detect regressions and the test may pass even when the module is unusable. Add at least assertions on the sample download, texture/mask bookkeeping (add/remove sphere, radius update) using headless-safe helpers, and clean up node creation.
- [`AnatomyCarve/AnatomyCarve.py:490-502`](https://github.com/andrey-titov/SlicerAnatomyCarve/blob/3ce2dd19c461184cf17456bdbbd84a30c6ad8f7b/AnatomyCarve/AnatomyCarve.py#L490-L502): AnatomyCarveTest.test_AnatomyCarve1 only downloads sample data and calls AnatomyCarveLogic(); all assertions are commented out. The Testing/Python CMake registration is commented out, so the test does not check any behavior. Add real tests (for example mask-row behavior, sphere add/remove, and sample-data load), and enable the registration in Testing/Python/CMakeLists.txt.
- [`AnatomyCarve/AnatomyCarveLogic/Context.py:99-104`](https://github.com/andrey-titov/SlicerAnatomyCarve/blob/3ce2dd19c461184cf17456bdbbd84a30c6ad8f7b/AnatomyCarve/AnatomyCarveLogic/Context.py#L99-L104): For the bundled 441x321x215 sample this allocates roughly 0.5 GB of host RAM in several temporaries while the wait cursor blocks the GUI; a typical 512x512x500 CT needs several GB twice over, which on a 8-16 GB laptop triggers swapping or MemoryError after the user clicked Render. The same full-volume work is repeated per StartEvent in the shaders, but the Python-side copies happen once without progress reporting. Build the RGBA array in one allocation (or reuse the existing VectorVolumeNode's array) and run the setup off the GUI thread or with a progress dialog.
