Please fix these before the extension can be merged:

- [`SegmentLesionsModule/SegmentLesionsModule.py:47-49`](https://github.com/Oncometer/SlicerOncometer/blob/038cee68aa3d2c7d823f192cd346bad4969a4c3c/SegmentLesionsModule/SegmentLesionsModule.py#L47-L49): Installing `lionz` directly via `pip_install` pulls in `nnunetv2`, `torch`, and other scientific Python dependencies directly from PyPI without using `PyTorchUtils` or prompting the user for confirmation. This can corrupt Slicer's shared Python environment by replacing Slicer-bundled packages or existing PyTorch installations. Add `PyTorch` to `EXTENSION_DEPENDS` and `build_dependencies`, use `PyTorchUtils` to manage PyTorch installation, avoid overwriting Slicer's bundled packages when installing `lionz`/`nnunetv2`, and ask the user for confirmation before installing large dependencies.
- [`SegmentOrgansModule/SegmentOrgansModule.py:29-31`](https://github.com/Oncometer/SlicerOncometer/blob/038cee68aa3d2c7d823f192cd346bad4969a4c3c/SegmentOrgansModule/SegmentOrgansModule.py#L29-L31): Installing `moosez` directly via `pip_install` pulls in `nnunetv2`, `torch`, `torchvision`, and transitive dependencies (such as `SimpleITK`, `scipy`, `numpy`, `requests`, and potentially `opencv-python`) directly from PyPI without going through the Slicer PyTorch extension (`PyTorchUtils`) or the `NNUNet` extension's controlled install logic. This installs CPU/mismatched PyTorch wheels from PyPI, can overwrite or downgrade Slicer's bundled core packages, and runs a multi-gigabyte installation without user confirmation. Depend on `PyTorch` (and/or `SlicerNNUNet`) in `CMakeLists.txt` (`EXTENSION_DEPENDS`) and the catalog entry (`build_dependencies`), ensure PyTorch is installed via `PyTorchUtils` before installing `moosez` (or install `nnunetv2`/`moosez` with `--no-deps` or constraints matching Slicer's bundled packages), and prompt the user with `slicer.util.confirmOkCancelDisplay` before downloading and installing large packages.

Smaller suggestions:

- [`RadiomicsModule/RadiomicsModule.py:723-730`](https://github.com/Oncometer/SlicerOncometer/blob/038cee68aa3d2c7d823f192cd346bad4969a4c3c/RadiomicsModule/RadiomicsModule.py#L723-L730): The module's help defines Dmax as the maximum distance between tumor centroids, but the implementation takes the convex hull of every tumor voxel and computes the farthest pair of hull points. A single extended lesion therefore receives a nonzero Dmax and multi-lesion distances include lesion size rather than just separation. Calculate physical centroids per connected component and their maximum pairwise distance; test single and multiple lesions.
- [`RadiomicsModule/RadiomicsModule.py:663-666`](https://github.com/Oncometer/SlicerOncometer/blob/038cee68aa3d2c7d823f192cd346bad4969a4c3c/RadiomicsModule/RadiomicsModule.py#L663-L666): In `RadiomicsModuleLogic.process`, `composantes_connexes = sitk.ConnectedComponent(binaryMask)` assigns distinct integer labels `1, 2, ..., N` to each connected lesion component. However, `_calculate_SUV_max`, `_calculate_SUV_mean`, and `_calculate_TLG` only select voxels where `composantes_connexes == 1`, ignoring all other lesions (`> 1`) when computing global SUVmean, SUVmax, and TLG. Use `sitk.GetArrayFromImage(composantes_connexes) > 0` (or pass `binaryMask`) when computing global `SUVmax`, `SUVmean`, and `TLG` across all segmented lesions.
- [`OrganomicsModule/OrganomicsModule.py:532-538`](https://github.com/Oncometer/SlicerOncometer/blob/038cee68aa3d2c7d823f192cd346bad4969a4c3c/OrganomicsModule/OrganomicsModule.py#L532-L538): Organomics accepts a segmentation node but maps organs solely by digits in segment names. A segmentation with ordinary names such as 'Liver' is treated as missing and the logic emits SUVmean and SUVmax of zero for those organs, presenting plausible measurements rather than warning that mapping failed. Numbers unrelated to labels may also select the wrong organ. Use explicit, validated organ-to-segment mapping or recognized anatomical names, and report missing or ambiguous organs rather than substituting zeros.
- [`RadiomicsModule/RadiomicsModule.py:23-28`](https://github.com/Oncometer/SlicerOncometer/blob/038cee68aa3d2c7d823f192cd346bad4969a4c3c/RadiomicsModule/RadiomicsModule.py#L23-L28): Selecting TMTS or TVSR calls this helper for scikit-image, and Dmax calls it for scipy if absent. These operations modify the shared environment without a confirmation dialog; pip may also change dependencies used by other modules. Check for dependencies before processing, explain the changes and ask for confirmation, while preserving Slicer-bundled packages.
- [`RadiomicsModule/RadiomicsModule.py:632-637`](https://github.com/Oncometer/SlicerOncometer/blob/038cee68aa3d2c7d823f192cd346bad4969a4c3c/RadiomicsModule/RadiomicsModule.py#L632-L637): Despite the comment, _calculate_TMTV returns mm³ divided by 1000, i.e. cm³, while _calculate_TMTS returns surface in mm². The global TVSR result is thus 1000 times smaller than the documented millimeter value. Convert volume or surface to consistent units before division and test with a known-volume phantom.
- [`SegmentLesionsModule/SegmentLesionsModule.py:635-642`](https://github.com/Oncometer/SlicerOncometer/blob/038cee68aa3d2c7d823f192cd346bad4969a4c3c/SegmentLesionsModule/SegmentLesionsModule.py#L635-L642): On Windows Python's selector implementation supports sockets, not subprocess pipe handles, so registration fails when a prediction is launched. The organ module uses the same approach at lines 662-669; its process is started before registration and is not terminated on this failure. The provided inference smoke tests stub out the subprocess and do not exercise this path. Use a cross-platform subprocess reader such as worker threads or Qt's QProcess, and terminate and reap the child on errors.
