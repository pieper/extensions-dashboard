Suggestions for a later update:

- [`NeuropacsScriptedModule/NeuropacsScriptedModule.py:147`](https://github.com/neuropacs/SlicerNeuropacs/blob/93925461f8232b1039c271124e5ce78efcaea225/NeuropacsScriptedModule/NeuropacsScriptedModule.py#L147): `logging.error` is called with two positional arguments and no format placeholder, which raises a logging TypeError and hides the real error; the user only sees 'Failed to run analysis.' with no detail. Use `logging.error("Failed to run neuropacs analysis: %s", e)` and surface the message to the user.
- [`NeuropacsScriptedModule/NeuropacsScriptedModule.py:641-646`](https://github.com/neuropacs/SlicerNeuropacs/blob/93925461f8232b1039c271124e5ce78efcaea225/NeuropacsScriptedModule/NeuropacsScriptedModule.py#L641-L646): The registered unittest contains no assertions, and NeuropacsScriptedModule/Testing/Python/CMakeLists.txt has its only test line commented out, so the extension's CI provides no functional coverage of the module. Add at least a widget-creation test (which would also catch the self.layout problem) and a config-file round-trip test.
- [`NeuropacsScriptedModule/NeuropacsScriptedModule.py:143`](https://github.com/neuropacs/SlicerNeuropacs/blob/93925461f8232b1039c271124e5ce78efcaea225/NeuropacsScriptedModule/NeuropacsScriptedModule.py#L143): Any exception other than 'Bucket not found' (network error, expired API key, server error) falls through with `status` undefined, so populateOrderTable raises UnboundLocalError and the whole table refresh fails instead of reporting the problem. Handle the general exception case (continue with an error status or re-raise with a user-visible message).
- [`NeuropacsScriptedModule/NeuropacsScriptedModule.py:291-302`](https://github.com/neuropacs/SlicerNeuropacs/blob/93925461f8232b1039c271124e5ce78efcaea225/NeuropacsScriptedModule/NeuropacsScriptedModule.py#L291-L302): When downloading a report in PNG format, the code attempts to load it via slicer.util.loadVolume and display it in the red slice viewer. However, `slicer.util.loadVolume` interprets 2D PNG images (such as biomarker reports) as scalar volumes/architectures, which can cause unexpected volume registration, scaling issues, or clutter the MRML scene with non-imaging report artifacts. While not a security concern, it is a soundness/correctness issue in how reports are rendered. Use a suitable document or image viewer widget (or save/display appropriately) rather than loading report PNGs into the 3D Slicer volume hierarchy as anatomical volumes.
- [`NeuropacsScriptedModule/NeuropacsScriptedModule.py:267`](https://github.com/neuropacs/SlicerNeuropacs/blob/93925461f8232b1039c271124e5ce78efcaea225/NeuropacsScriptedModule/NeuropacsScriptedModule.py#L267): When the user cancels, file_path is empty and the code still calls display_png_in_slicer('') / display_text_in_slicer('') (lines 282-285), which fails to load and then reports 'downloaded successfully at ' (line 289). The report is also fetched from the server before the user chooses a destination. Return early when the dialog is cancelled and only fetch/display after a valid path is chosen.
- [`NeuropacsScriptedModule/NeuropacsScriptedModule.py:314-324`](https://github.com/neuropacs/SlicerNeuropacs/blob/93925461f8232b1039c271124e5ce78efcaea225/NeuropacsScriptedModule/NeuropacsScriptedModule.py#L314-L324): Adding a QTextEdit to the main window's central widget layout modifies Slicer's global UI from a module and can leave a stray widget (or a re-parented layout) behind after the module is closed, affecting the whole application session. Show the report in a module-owned dialog or in the module panel instead of the main window layout.
- [`NeuropacsScriptedModule/NeuropacsScriptedModule.py:451-464`](https://github.com/neuropacs/SlicerNeuropacs/blob/93925461f8232b1039c271124e5ce78efcaea225/NeuropacsScriptedModule/NeuropacsScriptedModule.py#L451-L464): `series[0]` and `files[0]` raise IndexError for patients/studies with no series or an empty series, aborting the whole dropdown population. Also only the first series of the first study is listed, so for a diffusion MRI study with several series the user cannot choose which series is uploaded, and the uploaded folder is whatever directory the first file happens to live in. Guard empty lists and list series (with descriptions) rather than a single arbitrary series.
- [`NeuropacsScriptedModule/NeuropacsScriptedModule.py:570`](https://github.com/neuropacs/SlicerNeuropacs/blob/93925461f8232b1039c271124e5ce78efcaea225/NeuropacsScriptedModule/NeuropacsScriptedModule.py#L570): The DICOM upload (line 590) and status polling in populateOrderTable run on the GUI thread with only a wait cursor and processEvents calls; for a multi-hundred-MB diffusion dataset Slicer will appear frozen and cannot be cancelled, and there is no progress reporting. Run the upload in a worker thread (slicer.util.ProgressDialog / qSlicerCLIProgressBar style) and report progress.
