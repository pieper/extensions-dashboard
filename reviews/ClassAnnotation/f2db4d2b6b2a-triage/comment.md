Suggestions for a later update:

- [`ClassAnnotation/CMakeLists.txt:5-9`](https://github.com/lorenaromeo/SlicerClassAnnotation/blob/f2db4d2b6b2a626a7318aa50359fb01cb2538a1d/ClassAnnotation/CMakeLists.txt#L5-L9): The repository contains `ClassAnnotationLib/__init__.py`, but it is not listed in MODULE_PYTHON_SCRIPTS, so it is not installed. Imports such as `from ClassAnnotationLib.ClassAnnotationUIUtils import getMainColor` (ClassAnnotation.py:245) currently work only because the directory is added to `sys.path` and Python treats it as a namespace package; if that `sys.path` hack is removed the imports break. Add `${MODULE_NAME}Lib/__init__.py` to MODULE_PYTHON_SCRIPTS and use package-relative imports.
- [`ClassAnnotation/ClassAnnotation.py:3260-3262`](https://github.com/lorenaromeo/SlicerClassAnnotation/blob/f2db4d2b6b2a626a7318aa50359fb01cb2538a1d/ClassAnnotation/ClassAnnotation.py#L3260-L3262): patientID comes from the CSV 'Patient ID' column. A crafted or corrupted value that resolves outside the output tree would cause recursive deletion of that location.
- [`ClassAnnotation/ClassAnnotationLib/ClassAnnotationUtils.py:9`](https://github.com/lorenaromeo/SlicerClassAnnotation/blob/f2db4d2b6b2a626a7318aa50359fb01cb2538a1d/ClassAnnotation/ClassAnnotationLib/ClassAnnotationUtils.py#L9): `movePatientIfReclassified` iterates over every subdirectory of the user-selected output folder and, if a subdirectory becomes empty, removes it with `shutil.rmtree(currentClassPath)` (line 24). If the user points the output folder at a directory that already contains unrelated (possibly empty) folders, those folders are deleted. Only empty directories are removed, so the harm is limited, but the operation is not restricted to folders the extension created. Restrict the scan to folders matching the `class<N>` naming pattern the module itself creates.
- [`ClassAnnotation/ClassAnnotation.py:345`](https://github.com/lorenaromeo/SlicerClassAnnotation/blob/f2db4d2b6b2a626a7318aa50359fb01cb2538a1d/ClassAnnotation/ClassAnnotation.py#L345): Users are not told when the previous classification could not be read, or when copies failed, so reclassification may silently lose track of earlier assignments.
- [`ClassAnnotation/ClassAnnotation.py:452`](https://github.com/lorenaromeo/SlicerClassAnnotation/blob/f2db4d2b6b2a626a7318aa50359fb01cb2538a1d/ClassAnnotation/ClassAnnotation.py#L452): `generateMultiLabelClassButtons` (line 452) and `setLabelModeFromButtons` (line 778) call `slicer.mrmlScene.Clear(0)` unconditionally, discarding every node in the scene (including unsaved segmentations or measurements the user loaded) without asking. Dataset loading does ask first (line 1635: "Loading a new dataset will clear the scene. Do you want to continue?"), so the inconsistency is easy to hit: a user who has other work open and toggles single/multi-label mode loses it silently. Prompt before clearing, or only remove the nodes this module created (track them and delete those).
- [`ClassAnnotation/ClassAnnotationLib/ClassAnnotationUtils.py:81-92`](https://github.com/lorenaromeo/SlicerClassAnnotation/blob/f2db4d2b6b2a626a7318aa50359fb01cb2538a1d/ClassAnnotation/ClassAnnotationLib/ClassAnnotationUtils.py#L81-L92): `compute_patient_hashes` swallows every read error and returns `[""]` when nothing could be read (line 92). The hash is used for duplicate detection (`isPatientDuplicate`, `markAsDuplicateMulti`), so an unreadable or unsupported file silently yields an empty hash and can make distinct patients look identical or duplicates go undetected, with no message to the user. Report unreadable files to the user (warningDisplay) and skip duplicate comparison when the hash is empty.
- [`ClassAnnotation/ClassAnnotationLib/ClassAnnotationUtils.py:48-51`](https://github.com/lorenaromeo/SlicerClassAnnotation/blob/f2db4d2b6b2a626a7318aa50359fb01cb2538a1d/ClassAnnotation/ClassAnnotationLib/ClassAnnotationUtils.py#L48-L51): `f.read()` loads the entire file into memory, and `compute_patient_hashes` additionally converts each volume to a numpy array (`sitk.GetArrayFromImage`) and hashes it. All of this runs synchronously from the widget (no thread, no progress dialog), so loading a large dataset can freeze the Slicer GUI for a long time and can exhaust memory on big files. Hash in chunks, and move dataset scanning/hashing to a `qt.QTimer`-driven or CLI-thread worker with progress reporting.
- [`ClassAnnotation/ClassAnnotation.py:20-21`](https://github.com/lorenaromeo/SlicerClassAnnotation/blob/f2db4d2b6b2a626a7318aa50359fb01cb2538a1d/ClassAnnotation/ClassAnnotation.py#L20-L21): Importing the module (which Slicer does at startup for every installed scripted module) prepends the module's ClassAnnotationLib directory to the global `sys.path`. This is a process-wide side effect affecting other extensions and can shadow same-named modules; the module is also imported eagerly rather than lazily. Use a relative import (`from .ClassAnnotationLib...`) or `importlib` with an explicit path instead of mutating `sys.path`.
