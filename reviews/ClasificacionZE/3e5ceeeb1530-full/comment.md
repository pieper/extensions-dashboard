Suggestions for a later update:

- [`Visualizacion/Visualizacion.py:91`](https://github.com/juan2812006-arch/SlicerClasificacionZE/blob/3e5ceeeb1530e322769e853b1a90407fcc9122ca/Visualizacion/Visualizacion.py#L91): The processed-patient action calls copiarArchivosSujeto without a confirmation (lines 1598–1649). If either optional electrode input is left empty, lines 1579–1581 unlink an existing EEG or SEEG file in the patient's directory; selecting a different file overwrites the existing copy through shutil.copy2. A user merely visualizing an existing subject can thus permanently lose prior electrode data. Never delete or overwrite existing patient inputs during visualization without explicit file-specific confirmation; use per-run output directories or retain existing inputs when optional fields are blank.
- [`Visualizacion/Visualizacion.py:74-75`](https://github.com/juan2812006-arch/SlicerClasificacionZE/blob/3e5ceeeb1530e322769e853b1a90407fcc9122ca/Visualizacion/Visualizacion.py#L74-L75): The form validation at lines 980–988 accepts both '.' and '..', and lines 1696–1698 join the ID to the chosen results folder. '.' targets the results root and '..' its parent rather than a patient subfolder; copying, deletion, FreeSurfer outputs and prediction writes can then affect pre-existing files outside the intended subject directory. The same join is used in the processed-patient workflow. Reject '.' and '..' explicitly, resolve the resulting path, and require it to be a dedicated child of the selected results directory before any write or deletion.
- [`Inferencia/inferencia_ml.py:23-31`](https://github.com/juan2812006-arch/SlicerClasificacionZE/blob/3e5ceeeb1530e322769e853b1a90407fcc9122ca/Inferencia/inferencia_ml.py#L23-L31): `Inferencia/inferencia_ml.py` pins `scikit-learn==1.9.1`. As of April 2026, scikit-learn 1.9.1 does not exist on PyPI (and if a different version is already installed in Slicer's shared Python environment, `dependenciasFaltantes()` will attempt to replace it with `1.9.1`, or `pip_install` will fail with `No matching distribution found for scikit-learn==1.9.1`). Additionally, installing an exact pin of `scikit-learn` can trigger upgrades or downgrades of `numpy` or `scipy` that Slicer bundles. Verify the exact scikit-learn version on PyPI (e.g. `1.6.1` or `>=1.5`) or relax the hard `==` pin in `DEPENDENCIAS` (relying on the runtime warning in `soz_inferencia.cargar_modelo` if versions differ) so `pip_install` does not fail or alter Slicer's bundled `numpy`/`scipy`.
- [`Visualizacion/Visualizacion.py:2167-2176`](https://github.com/juan2812006-arch/SlicerClasificacionZE/blob/3e5ceeeb1530e322769e853b1a90407fcc9122ca/Visualizacion/Visualizacion.py#L2167-L2176): After a user runs inference, this extension's directory remains first on the process-wide import path, so later imports with the same module names in other extensions can resolve to these files instead.
