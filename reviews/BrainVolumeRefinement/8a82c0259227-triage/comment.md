Suggestions for a later update:

- [`docs/index.md:57`](https://github.com/CSIM-Toolkits/SlicerBrainVolumeRefinement/blob/8a82c02592272537514802b96071e13370b85c81/docs/index.md#L57): The shipped LICENSE is Apache License 2.0 and README.md says Apache 2.0, but the published documentation page tells users the project is MIT and points at the LICENSE of a different extension. Both licenses permit distribution, so this is not a distribution blocker, but users and downstream packagers get contradictory terms. State Apache-2.0 in docs/index.md and link to this repository's own LICENSE file.
- [`BVeR/Testing/Cxx/CMakeLists.txt:25-26`](https://github.com/CSIM-Toolkits/SlicerBrainVolumeRefinement/blob/8a82c02592272537514802b96071e13370b85c81/BVeR/Testing/Cxx/CMakeLists.txt#L25-L26): BVeR.xml defines no 'sigma' parameter, so PARSE_ARGS in the test executable will reject the argument and the test can never pass; the baseline is also a CT head image rather than the brain MRI the method targets. The extension therefore ships a test that fails on every platform, which hides real regressions. Replace --sigma with real BVeR parameters (e.g. --selectionMode Local --iterations 2) and regenerate the baseline.
- [`BVeR/BVeR.cxx:226-236`](https://github.com/CSIM-Toolkits/SlicerBrainVolumeRefinement/blob/8a82c02592272537514802b96071e13370b85c81/BVeR/BVeR.cxx#L226-L236): If actualContour contains no foreground voxels (e.g. an all-zero or fully-zeroed input), minX/minY/minZ stay at NumericTraits<int>::max() while maxX/maxY/maxZ stay 0, so windowSize becomes a large negative number and searchingRegion is built with that size (lines 235-236). The following NeighborhoodIterator construction then throws; the user sees a raw ITK exception rather than a diagnostic such as 'input mask is empty'. Detect the 'no contour voxels found' case (minX > maxX) and return EXIT_FAILURE with a clear message.
- [`BVeR/BVeR.cxx:297`](https://github.com/CSIM-Toolkits/SlicerBrainVolumeRefinement/blob/8a82c02592272537514802b96071e13370b85c81/BVeR/BVeR.cxx#L297): manualThreshold is an integer parameter that is cast to InputPixelType at comparison time (line 297). For an unsigned char input, a value such as 300 wraps to 44 silently, and a negative value wraps as well. The user gets a different threshold than the one they entered, with no warning. Validate manualThreshold against the input type's range and report an error, or compare in double without casting.
- [`BVeR/BVeR.cxx:336-341`](https://github.com/CSIM-Toolkits/SlicerBrainVolumeRefinement/blob/8a82c02592272537514802b96071e13370b85c81/BVeR/BVeR.cxx#L336-L341): BVeR.cxx calls std::sort (line 341) and uses std::vector (line 336) but includes neither <algorithm> nor <vector>. It compiles only because ITK headers include them transitively, which can break with other ITK or compiler versions. Add #include <algorithm> and #include <vector> at the top of BVeR.cxx.
- [`BVeR/BVeR.cxx:374-375`](https://github.com/CSIM-Toolkits/SlicerBrainVolumeRefinement/blob/8a82c02592272537514802b96071e13370b85c81/BVeR/BVeR.cxx#L374-L375): Each iteration masks updatedImage with connectedMask (largest component only, lines 367-375), but newBrainMask is filled from newMask (line 384/402), which is the plain binarization of auxImage and still contains every island. The final output at line 466 masks the input with newBrainMask, so spurious disconnected islands that the algorithm deliberately removed internally reappear in the delivered volume and mask. Copy connectedMask (or the largest-component mask) into newBrainMask instead of newMask.
