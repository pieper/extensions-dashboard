Suggestions for a later update:

- [`BVeR/BVeR.cxx:144-153`](https://github.com/CSIM-Toolkits/SlicerBrainVolumeRefinement/blob/8a82c02592272537514802b96071e13370b85c81/BVeR/BVeR.cxx#L144-L153): `totalVolumeI` (at line 145) and `totalVolumeII` (at line 417) are declared without being initialized to `0.0` before being incremented inside the voxel counting loops (`totalVolumeI++` and `totalVolumeII++`). In C++, local primitive variables have indeterminate values on the stack, causing undefined behavior when incremented and used to compute the convergence ratio `c_i = ((totalVolumeI-totalVolumeII)/totalVolumeI)`. Depending on stack contents, the algorithm may terminate prematurely after 1 iteration, fail to detect convergence, or produce NaN/Inf. Initialize both `double totalVolumeI = 0.0;` (line 145) and `double totalVolumeII = 0.0;` (line 417), and guard against `totalVolumeI == 0.0` before dividing.
- [`BVeR/BVeR.cxx:223-228`](https://github.com/CSIM-Toolkits/SlicerBrainVolumeRefinement/blob/8a82c02592272537514802b96071e13370b85c81/BVeR/BVeR.cxx#L223-L228): If an input image has no contour voxels greater than 0 (or if `actualContour` becomes empty), `minX`, `minY`, `minZ` remain `itk::NumericTraits<int>::max()` and `maxX`, `maxY`, `maxZ` remain `0`. `maxX - minX` then underflows and wraps around when assigned to `unsigned` `SizeValueType` in `windowSize`. Even in the normal case, the bounding box size should be `maxX - minX + 1` (off-by-one excludes the `max` boundary), and when a neighborhood iterator with `radius` steps near the edge of `updatedImage`, `inIt.SetLocation(imageCuttingIt.GetIndex())` on `searchingRegion` assumes at least one valid voxel exists. Check whether any contour voxels were found (`maxX >= minX`, etc.) before constructing `searchingRegion`, and use `maxX - minX + 1` for the inclusive region size.
- [`BVeR/Testing/Cxx/CMakeLists.txt:21-26`](https://github.com/CSIM-Toolkits/SlicerBrainVolumeRefinement/blob/8a82c02592272537514802b96071e13370b85c81/BVeR/Testing/Cxx/CMakeLists.txt#L21-L26): The C++ test `BVeRTest` is left over from the Slicer CLI template and passes `--sigma 2.5`, which is not a valid flag defined in `BVeR.xml`. Running the test will fail argument parsing (`PARSE_ARGS`). Update the test arguments in `BVeR/Testing/Cxx/CMakeLists.txt` to match the parameters in `BVeR.xml` and provide a matching baseline image.
- [`BVeR/BVeR.cxx:401-402`](https://github.com/CSIM-Toolkits/SlicerBrainVolumeRefinement/blob/8a82c02592272537514802b96071e13370b85c81/BVeR/BVeR.cxx#L401-L402): maskIt iterates over newMask, the binary mask before largest-component filtering, whereas updatedImage is filtered using connectedMask. The final output volume is remasked with newBrainMask, so components discarded in the last iteration may reappear in both output mask and volume. Copy the filtered connected mask to newBrainMask and test an input containing disconnected components.
- [`BVeR/BVeR.cxx:266-272`](https://github.com/CSIM-Toolkits/SlicerBrainVolumeRefinement/blob/8a82c02592272537514802b96071e13370b85c81/BVeR/BVeR.cxx#L266-L272): wIntensity is declared as InputPixelType, and Local is the default mode. For common integer images, summing a neighborhood in the original pixel type can wrap or overflow before division, producing an incorrect threshold and therefore an incorrect refinement. Accumulate in a sufficiently wide floating-point type and compare intensities against that mean.
- [`BVeR/BVeR.cxx:337-342`](https://github.com/CSIM-Toolkits/SlicerBrainVolumeRefinement/blob/8a82c02592272537514802b96071e13370b85c81/BVeR/BVeR.cxx#L337-L342): For the odd-sized neighborhood, zero-based index (inN+1)/2 selects the value above the median. Marked voxels can therefore be assigned incorrect values and affect the resulting segmentation. Use inN/2 for the odd-sized neighborhood and add a known-value median test.
