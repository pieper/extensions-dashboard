Suggestions for a later update:

- [`EVARSim/EVARSim.py:438`](https://github.com/rwic/SlicerEVARSim/blob/0568d174ab552f3ff41e42d380e2cfaf80a35e8e/EVARSim/EVARSim.py#L438): _updateSelectedTube, _analyzeBranches, _createBranchLabels, _removeBranchLabels, _extractBranchCenterline, _smoothCenterline, _reduceCenterlinePoints and _applySplineSmoothing all catch Exception and only print to stdout. In a GUI session the user sees nothing when, for example, branch extraction fails, and the module appears to do nothing; the same pattern also hides real bugs from the test suite. Report failures via slicer.util.errorDisplay or logging.warning, and let unexpected exceptions propagate to the tryWithErrorDisplay wrapper in onApplyButton.
- [`README.md:157`](https://github.com/rwic/SlicerEVARSim/blob/0568d174ab552f3ff41e42d380e2cfaf80a35e8e/README.md#L157): The module produces stent geometry from centerlines that users may interpret as sizing information, yet there is no statement that results are not validated for clinical decision making, no accuracy/validation data, and the license pointer names a file that does not exist (the file is LICENSE). Add an explicit research-only / not-for-clinical-use disclaimer, state the intended accuracy and validation status, and fix the license filename reference.
- [`EVARSim/EVARSim.py:1483`](https://github.com/rwic/SlicerEVARSim/blob/0568d174ab552f3ff41e42d380e2cfaf80a35e8e/EVARSim/EVARSim.py#L1483): reducedPoints is the 4-point spline of the already positioned segment for tube 1 (lines 1475-1479). _createAdditionalTubes then distributes positions 0.2-0.8 along that short segment (line 1130), so tubes 2..N are stacked inside tube 1's span instead of being spread along the vessel; with the default length of 10 mm and a long centerline the extra stents overlap almost completely. Pass the full (smoothed) curvePoints to _createAdditionalTubes and let each tube position itself along the whole centerline.
- [`EVARSim/EVARSim.py:1451-1452`](https://github.com/rwic/SlicerEVARSim/blob/0568d174ab552f3ff41e42d380e2cfaf80a35e8e/EVARSim/EVARSim.py#L1451-L1452): The widget applies the selected branch through _extractBranchCenterline, but process() always takes the first line cell of an input model. A headless caller of process() therefore gets a different branch from the GUI for the same input. Pass the branch index into process() and reuse _extractBranchCenterline so both paths match.
- [`EVARSim/EVARSim.py:806-807`](https://github.com/rwic/SlicerEVARSim/blob/0568d174ab552f3ff41e42d380e2cfaf80a35e8e/EVARSim/EVARSim.py#L806-L807): segmentLengths[i] is zero when two consecutive curve points coincide (common in imported polylines), producing inf/nan points; the same risk exists in _addRigidEndCaps (line 904, 909) and _createCircularCap (line 935) where a zero-length direction vector is normalized. In process() this surfaces as a confusing error or an empty/garbage model rather than a clear message. Skip zero-length segments and guard the normalizations with a length check.
- [`EVARSim/EVARSim.py:37-39`](https://github.com/rwic/SlicerEVARSim/blob/0568d174ab552f3ff41e42d380e2cfaf80a35e8e/EVARSim/EVARSim.py#L37-L39): The module simulates endovascular stent placement for EVAR, a clinical procedure. The help text and README do not state that output is not validated for clinical decisions or planning. Users could misread the simulation as clinically accurate. Add an explicit research-only / not-for-clinical-use disclaimer to helpText and README.
- [`README.md:30`](https://github.com/rwic/SlicerEVARSim/blob/0568d174ab552f3ff41e42d380e2cfaf80a35e8e/README.md#L30): The module registers itself under the 'Modeling' category (EVARSim.py line 33) and the UI allows radius 0.1-50, length 0.1-200 and resolution 6-64, while the README says 'Examples', radius 0.1-10.0, length 1.0-200 and resolution 4-32. Users following the README will look in the wrong category and expect different limits. Update the README to match the implemented category and slider ranges.
- [`EVARSim/CMakeLists.txt:11-12`](https://github.com/rwic/SlicerEVARSim/blob/0568d174ab552f3ff41e42d380e2cfaf80a35e8e/EVARSim/CMakeLists.txt#L11-L12): MODULE_PYTHON_RESOURCES lists only the icon and the .ui file, so EVARSim/CL_model.vtk (290 KB) is not copied into the installed extension. README line 122 states 'The extension includes `CL_model.vtk` - a sample branched centerline file of the aorta and the aortic bifurcation.', which is false for users who install from the extension manager; they have no sample data to try the module with. Either install the file (add it to MODULE_PYTHON_RESOURCES / a data directory) or register it as Sample Data, or remove the claim from the README.
