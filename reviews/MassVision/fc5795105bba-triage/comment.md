Suggestions for a later update:

- [`MassVision/MassVisionLib/Logic.py:12-13`](https://github.com/jamzad/SlicerMassVision/blob/fc5795105bba201ac2c5461b31c7eeed8ae87b43/MassVision/MassVisionLib/Logic.py#L12-L13): mpl.use('Agg') changes the matplotlib backend process-wide for every other module and extension in the same Slicer session. MassVision.py:150-153 additionally connects to the global module selector and force-shows the Markups toolbar, altering the main window for users who merely open the module. Use a non-interactive backend only for the specific figures (e.g. matplotlib.figure with Agg canvas) instead of a global mpl.use call, and restore toolbar visibility on cleanup.
- [`ExtensionIndex/MassVision.s4ext:28-41`](https://github.com/jamzad/SlicerMassVision/blob/fc5795105bba201ac2c5461b31c7eeed8ae87b43/ExtensionIndex/MassVision.s4ext#L28-L41): ExtensionIndex/MassVision.s4ext gives category 'Spectral Imagingy' (not matching the CMake category), and points to Screenshot.png, which is not in the repository (the repository has Screenshot1-4.png). This metadata may be shown incorrectly or produce broken images in the Extensions Manager if the legacy file is used. Correct the category string and the screenshot URL, or remove the legacy file if the JSON catalog entry replaces it.
- [`MassVision/MassVisionLib/Logic.py:4128-4130`](https://github.com/jamzad/SlicerMassVision/blob/fc5795105bba201ac2c5461b31c7eeed8ae87b43/MassVision/MassVisionLib/Logic.py#L4128-L4130): Peak m/z values (derived from the user's data, not images or identifiers) are sent to www.lipidmaps.org and rest.kegg.jp when the user runs molecule matching. The curl_cffi 'impersonate="chrome"' option deliberately disguises the client to defeat bot detection, which may conflict with those services' terms; the user is not told that data leaves the machine. Use a plain HTTP client with an identifying User-Agent, and state in the UI/documentation that m/z values are sent to external databases.
- [`MassVision/MassVisionLib/Logic.py:4766-4771`](https://github.com/jamzad/SlicerMassVision/blob/fc5795105bba201ac2c5461b31c7eeed8ae87b43/MassVision/MassVisionLib/Logic.py#L4766-L4771): VisiumVision documents that raster_cube is None when raster['materialize_cube'] is False (VisiumVision.py:274-275, 1220-1221). If a user loads a saved configuration with materialize_cube disabled, this raises AttributeError on None instead of a clear message. Check for None and either force materialization for this path or report that lazy mode is unsupported here.
- [`MassVision/MassVisionLib/VisiumVision.py:433`](https://github.com/jamzad/SlicerMassVision/blob/fc5795105bba201ac2c5461b31c7eeed8ae87b43/MassVision/MassVisionLib/VisiumVision.py#L433): When squidpy is missing, the handler installs scanpy (already a hard dependency) and immediately re-imports squidpy, which raises ModuleNotFoundError again. Spatial gene selection therefore fails with an unhelpful error, and a pip install is performed for nothing. Install "squidpy" (after user confirmation) or raise a clear message telling the user to install squidpy or disable spatial_gene_selection.
- [`MassVision/MassVisionLib/Logic.py:252-253`](https://github.com/jamzad/SlicerMassVision/blob/fc5795105bba201ac2c5461b31c7eeed8ae87b43/MassVision/MassVisionLib/Logic.py#L252-L253): HybridImzMLParser is used with auto_install=True, which suggests it may install packages or fetch code at runtime while reading a user-supplied imzML file. I could not locate its definition in the files I read, so I cannot confirm what it downloads or installs. Document what auto_install does and where HybridImzMLParser comes from, and gate any installation behind explicit user consent.
