Suggestions for a later update:

- [`DRAISegmentation/DRAISegmentation.py:257-261`](https://github.com/DeepReasoningAI/SlicerDRAISegmentation/blob/c23890d156c643b1afa48a3e0854ae9b0e377a09/DRAISegmentation/DRAISegmentation.py#L257-L261): The remote job keeps running and its result is never fetched or deleted, so the server retains a job (and, per the vendor's claim, the uploaded volume until it finishes) after the user believes they cancelled. The timeout path in _pollStatus (lines 300-306) likewise leaves _currentJobId set. Send a cancel/delete request to the API on cancel and on timeout, and clear _currentJobId in all terminal paths.
- [`DRAISegmentation/DRAISegmentation.py:465-466`](https://github.com/DeepReasoningAI/SlicerDRAISegmentation/blob/c23890d156c643b1afa48a3e0854ae9b0e377a09/DRAISegmentation/DRAISegmentation.py#L465-L466): The job_id returned by the server is inserted directly into the URL path. A malformed or hostile server response could inject path segments or query characters. The impact is limited because the server is the only source, but the value should be validated or URL-encoded.
- [`README.md:5-16`](https://github.com/DeepReasoningAI/SlicerDRAISegmentation/blob/c23890d156c643b1afa48a3e0854ae9b0e377a09/README.md#L5-L16): The module produces anatomical labels and 3D models that a clinician may act on, but neither README nor the module help text states that output is for research/visualization only, nor gives any accuracy/validation data, training data description, or regulatory clearance status. Users cannot judge whether the output is fit for clinical decisions. Add a clear intended-use statement (e.g. research use only unless cleared), a pointer to validation results, and a note that results must be reviewed by a qualified clinician.
- [`DRAISegmentation/DRAISegmentation.py:505-512`](https://github.com/DeepReasoningAI/SlicerDRAISegmentation/blob/c23890d156c643b1afa48a3e0854ae9b0e377a09/DRAISegmentation/DRAISegmentation.py#L505-L512): The usual Slicer pattern is to set the reference image geometry before importing the label map so the imported segments are placed in the reference frame. Setting it afterwards can leave the segmentation in the label map's own geometry while the node claims the volume's geometry, producing a mask that does not overlay the CT. Also, loadLabelVolume's return value is not checked, so a failed load passes None into ImportLabelmapToSegmentationNode. Set the reference geometry on the segmentation node before importing, and raise a user-visible error if loadLabelVolume returns None.
- [`DRAISegmentation/DRAISegmentation.py:678-683`](https://github.com/DeepReasoningAI/SlicerDRAISegmentation/blob/c23890d156c643b1afa48a3e0854ae9b0e377a09/DRAISegmentation/DRAISegmentation.py#L678-L683): The generic test exercises none of the module's real logic (volume export, multipart encoding, error parsing, segmentation import), so regressions in those paths would go unnoticed; there is also no sample volume for users to try the module without their own patient data. Add offline unit tests for exportVolume, _postMultipart body construction and _extractApiErrorMessage, and ship a small public sample CT for a tutorial.
