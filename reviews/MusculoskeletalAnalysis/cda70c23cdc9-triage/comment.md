Suggestions for a later update:

- [`Scripted/MusculoskeletalAnalysis/MusculoskeletalAnalysis.py:762-767`](https://github.com/WashUMusculoskeletalCore/Slicer-MusculoskeletalAnalysis/blob/cda70c23cdc9563aa09bd6148c10d0b3c65b8aeb/Scripted/MusculoskeletalAnalysis/MusculoskeletalAnalysis.py#L762-L767): The install happens only after an explicit user confirmation and only when the user runs an analysis, and it never pins or downgrades numpy/scipy/etc. But `skimage` and `pynrrd`/`trimesh` are installed unpinned from PyPI, so their transitive requirements could upgrade/downgrade packages Slicer bundles; and because `scipy` is often present in Slicer, the check can silently skip a version check. This is the standard pattern but worth noting for a shared environment. Prefer declaring these in the extension's packaging or use version compatibility checks; at minimum mention the installed packages/versions in the log after install.
- [`Scripted/MusculoskeletalAnalysis/MusculoskeletalAnalysis.py:468-473`](https://github.com/WashUMusculoskeletalCore/Slicer-MusculoskeletalAnalysis/blob/cda70c23cdc9563aa09bd6148c10d0b3c65b8aeb/Scripted/MusculoskeletalAnalysis/MusculoskeletalAnalysis.py#L468-L473): `UseDICOM` is set nowhere in the module (only `UseAlt`/`UseMan` are managed), so the condition always relies on the DICOMNode reference being present. Because initializeParameterNode() always fills DICOMNode from the first scalar volume, the Apply button is enabled even when the user has selected "Use another node for DICOM tags" with no meaningful node, and conversely a scene without any volume reference keeps Apply disabled. The stated gating (require a DICOM source when alternate tags are chosen) is not actually enforced in the GUI. Gate on `UseAlt`/`UseMan` (as process() does) and drop the stale `UseDICOM` check.
- [`CLI/MusculoskeletalAnalysisCLITools/reader.py:11-13`](https://github.com/WashUMusculoskeletalCore/Slicer-MusculoskeletalAnalysis/blob/cda70c23cdc9563aa09bd6148c10d0b3c65b8aeb/CLI/MusculoskeletalAnalysisCLITools/reader.py#L11-L13): readImg() forces SPL orientation and everything downstream uses a single scalar `voxSize`, so slice-wise areas, PMOI, and disc height computed along the third axis are wrong for anisotropic (typical clinical thick-slice) DICOM series. The GUI's manual voxel-size field is one value only, with no warning. Users could obtain silently incorrect morphometry for such scans. Read the spacing vector from the image header and use per-axis spacing, or validate that the series is isotropic and warn/refuse otherwise.
- [`CLI/MusculoskeletalAnalysisCLITools/thickness.py:11`](https://github.com/WashUMusculoskeletalCore/Slicer-MusculoskeletalAnalysis/blob/cda70c23cdc9563aa09bd6148c10d0b3c65b8aeb/CLI/MusculoskeletalAnalysisCLITools/thickness.py#L11): For every bone voxel the code builds an mgrid sphere mask and does an elementwise maximum; on a typical 512x512xN micro-CT mask this is millions of Python iterations inside the CLI process. The CLI runs without wait_for_completion (MusculoskeletalAnalysis.py:734) so Slicer stays alive, but progress only advances at fixed 20/40/60/80% steps and users see an apparently frozen analysis for a long time, with no way to cancel it. Vectorize with a max-filter / distance-transform-based local thickness implementation, and/or register the CLI node so the user can cancel it.
- [`Scripted/MusculoskeletalAnalysis/MusculoskeletalAnalysis.py:204`](https://github.com/WashUMusculoskeletalCore/Slicer-MusculoskeletalAnalysis/blob/cda70c23cdc9563aa09bd6148c10d0b3c65b8aeb/Scripted/MusculoskeletalAnalysis/MusculoskeletalAnalysis.py#L204): Resources/Icons contains Cancellous1/2, CancellousMask1/2, Cortical1/2, CorticalMask1/2, MusculoskeletalAnalysis.png and Screenshot.png, but no Intervertebral1.png or IntervertebralMask1.png (referenced at lines 204 and 220). Also `IntervertebralMaskSample1.seg.nrrd` is registered with `fileNames='IntervertebralMaskSample1.seg.nrrd'` while nodeNames is IntervertebralMask1, which is fine, but the missing thumbnails mean the tutorial's sample nodes appear without images. Cosmetic, not blocking. Add the two Intervertebral thumbnails to Resources/Icons or remove the thumbnailFileName arguments.
- [`Scripted/MusculoskeletalAnalysis/MusculoskeletalAnalysis.py:825`](https://github.com/WashUMusculoskeletalCore/Slicer-MusculoskeletalAnalysis/blob/cda70c23cdc9563aa09bd6148c10d0b3c65b8aeb/Scripted/MusculoskeletalAnalysis/MusculoskeletalAnalysis.py#L825): The only scripted test writes to os.path.expanduser("~\\Documents\\MusculoskeletalAnalysisTest"), which on Linux/macOS produces a literal backslash filename in the home directory and fails. The CTest registration in Testing/Python is commented out, so the CLI-level behaviour is not covered by build-time tests. Use tempfile.mkdtemp() or a path under slicer.app.temporaryPath, and enable the Python test in Testing/Python.
- [`CLI/MusculoskeletalAnalysisCLITools/writeReport.py:9-18`](https://github.com/WashUMusculoskeletalCore/Slicer-MusculoskeletalAnalysis/blob/cda70c23cdc9563aa09bd6148c10d0b3c65b8aeb/CLI/MusculoskeletalAnalysisCLITools/writeReport.py#L9-L18): Reports are appended to fixed names (cortical.txt, cancellous.txt, density.txt, intervertebral.txt) in the user-chosen directory. Repeated analyses accumulate rows, and if a directory already holds a template file with different columns the data rows are appended under an unrelated header. This is documented in the README but can mix unrelated patients' results in one file; no identifier is written per row except the volume name and date. Offer unique filenames or write a per-run timestamp/patient column and verify the header matches before appending.
