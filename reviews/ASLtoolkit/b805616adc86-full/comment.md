Suggestions for a later update:

- [`Multi_Echo_ASL/Multi_Echo_ASL.py:127-134`](https://github.com/LOAMRI/Slicer-ASLtoolkit/blob/b805616adc86eb902505f27dd58764d83647228c/Multi_Echo_ASL/Multi_Echo_ASL.py#L127-L134): `t2b` and `t2gm` are exposed in the GUI with defaults and ranges, but they are only printed in verbose output. They are not passed to `MultiTE_ASLMapping` or `create_map`. Changing them therefore has no effect on the result, which misleads users. Pass the T2 values to asltk, for example via its setter or constructor options, or remove the parameters from the XML.
- [`Multi_Echo_ASL/Multi_Echo_ASL.py:107-110`](https://github.com/LOAMRI/Slicer-ASLtoolkit/blob/b805616adc86eb902505f27dd58764d83647228c/Multi_Echo_ASL/Multi_Echo_ASL.py#L107-L110): In `Multi_Echo_ASL/Multi_Echo_ASL.py`, the `t2b` (T2 Blood) and `t2gm` (T2 Gray Matter) parameters exposed in `Multi_Echo_ASL.xml` are parsed into `args.t2b` and `args.t2gm` (lines 245-246) and printed in verbose output (lines 108-109), but are never passed to `ASLData`, `MultiTE_ASLMapping`, or `recon.create_map`. Any changes the user makes to `T2 Blood (ms)` or `T2 Gray Matter (ms)` in the UI have no effect on the computed map. Pass `args.t2b` and `args.t2gm` to `MultiTE_ASLMapping` or `recon.create_map` (e.g., via its `t2b` / `t2gm` parameters or setter methods in `asltk`).
- [`CBF_ATT_ASL/CBF_ATT_ASL.py:32-37`](https://github.com/LOAMRI/Slicer-ASLtoolkit/blob/b805616adc86eb902505f27dd58764d83647228c/CBF_ATT_ASL/CBF_ATT_ASL.py#L32-L37): If `asltk` is missing, the CLI script calls `slicer.util.pip_install("asltk==1.1.3")` straight away. This installs asltk and all its transitive dependencies into Slicer's shared Python with no prompt, even though the download may be large. Those dependencies may pin or replace packages Slicer bundles (numpy, scipy, SimpleITK, pydicom), and I did not verify them. The install happens inside a `python-real` subprocess, so the user sees nothing in the UI. The README mentions it only in a note. The `slicer` package may also not be fully usable from `python-real`, so the fallback may simply fail. Add a scripted module with a GUI that tells the user which packages will be installed and asks for confirmation before calling `pip_install`. Check that asltk's dependency requirements do not pin or downgrade Slicer-bundled packages. Apply the same change to the Multi_Echo_ASL script.
- [`CBF_ATT_ASL/CBF_ATT_ASL.py:187-192`](https://github.com/LOAMRI/Slicer-ASLtoolkit/blob/b805616adc86eb902505f27dd58764d83647228c/CBF_ATT_ASL/CBF_ATT_ASL.py#L187-L192): Valid methods are 'Gaussian' and 'Median', but the checks compare against lowercase 'gaussian' and 'median'. Invalid sigma or kernel sizes, such as an even median size, therefore pass validation and fail later inside asltk or give wrong results. The Multi_Echo module uses the correct case. Compare against 'Gaussian' and 'Median', matching the Multi_Echo module.
- [`CBF_ATT_ASL/CBF_ATT_ASL.py:127-133`](https://github.com/LOAMRI/Slicer-ASLtoolkit/blob/b805616adc86eb902505f27dd58764d83647228c/CBF_ATT_ASL/CBF_ATT_ASL.py#L127-L133): The XML's command-line example specifies --outputFolder and relative output names, but the script only checks that folder exists and saves directly to the output arguments. Relative names thus resolve against the process working directory, not the selected output folder. The multi-echo script has the same issue. Join relative output paths to the chosen output folder, or remove the option and correct the documentation.
- [`CBF_ATT_ASL/CBF_ATT_ASL.py:28`](https://github.com/LOAMRI/Slicer-ASLtoolkit/blob/b805616adc86eb902505f27dd58764d83647228c/CBF_ATT_ASL/CBF_ATT_ASL.py#L28): If one timing vector is space-separated and another is comma-separated, conversion of the first triggers the fallback, which reads only element zero of both vectors. For example, a comma-separated LD list loses all but its first value. The multi-echo module uses the same fallback for three vectors. Parse each vector independently, supporting the documented separators without discarding elements, and validate its length against the acquisition.
- [`CBF_ATT_ASL/CBF_ATT_ASL.py:39-40`](https://github.com/LOAMRI/Slicer-ASLtoolkit/blob/b805616adc86eb902505f27dd58764d83647228c/CBF_ATT_ASL/CBF_ATT_ASL.py#L39-L40): Both CLI scripts override Python's built-in `print` with `rich.print`. Slicer's CLI process runner parses standard output for XML progress tags such as `<filter-start>`, `<filter-progress>0.1</filter-progress>`, and `<filter-end>`. Because `rich.print` interprets angle-bracket tags as Rich console markup and applies terminal formatting/word wrapping, it can strip or alter the XML progress tags expected by Slicer. Use Python's built-in `print` (and `sys.stdout.flush()`) for Slicer `<filter-...>` XML progress reporting.
- [`Multi_Echo_ASL/Multi_Echo_ASL.py:33-37`](https://github.com/LOAMRI/Slicer-ASLtoolkit/blob/b805616adc86eb902505f27dd58764d83647228c/Multi_Echo_ASL/Multi_Echo_ASL.py#L33-L37): The identical pattern is repeated, so either module can trigger a silent installation into the shared environment. Centralize and gate the installation behind a user confirmation.
