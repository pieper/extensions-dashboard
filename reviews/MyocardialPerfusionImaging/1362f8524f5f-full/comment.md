- [`MyocardialPerfusionImaging/CMakeLists.txt:25-29`](https://github.com/4burakfe/SlicerMyocardialPerfusionImaging/blob/1362f8524f5fb6be045df440c5c2dce4db77467e/MyocardialPerfusionImaging/CMakeLists.txt#L25-L29): `MyocardialPerfusionImaging/CMakeLists.txt` lists `Resources/Images/banner.jpg` (lowercase `b`) in `MODULE_PYTHON_RESOURCES`, and `MyocardialPerfusionImaging/MyocardialPerfusionImaging.py` line 50 looks up `Resources/Images/banner.jpg`. However, the file committed in the repository is `MyocardialPerfusionImaging/Resources/Images/Banner.jpg` (uppercase `B`). On case-sensitive filesystems (such as Linux, where Slicer extensions are built and packaged on the Linux factory), CMake's `slicerMacroBuildScriptedModule` will fail to find `Resources/Images/banner.jpg` during configuration/installation, breaking the Linux build. Rename `MyocardialPerfusionImaging/Resources/Images/Banner.jpg` to `MyocardialPerfusionImaging/Resources/Images/banner.jpg` (or update both `MyocardialPerfusionImaging/CMakeLists.txt` and `MyocardialPerfusionImaging/MyocardialPerfusionImaging.py` to match the exact filename case).

Smaller suggestions:

- [`MyocardialPerfusionImaging/MyocardialPerfusionImagingLib/dicomexport.py:389-394`](https://github.com/4burakfe/SlicerMyocardialPerfusionImaging/blob/1362f8524f5fb6be045df440c5c2dce4db77467e/MyocardialPerfusionImaging/MyocardialPerfusionImagingLib/dicomexport.py#L389-L394): The exporter packs the entire Slicer scene but selects one reference patient's DICOM identity. The mixed-patient scan in case.py explicitly excludes studies assigned role None, whereas those nodes remain in the scene. If an unrelated patient's study is present or excluded, exporting the scene and sending it from the DICOM browser can disclose that patient's images and identifiers inside a bundle filed under the selected patient, without a specific warning about the excluded data. Export a patient-scoped scene or inspect all scene contents, including excluded and unidentifiable nodes, and block or obtain explicit informed confirmation before writing a mixed-patient DICOM bundle.
- [`MyocardialPerfusionImaging/MyocardialPerfusionImagingLib/dicomexport.py:545-550`](https://github.com/4burakfe/SlicerMyocardialPerfusionImaging/blob/1362f8524f5fb6be045df440c5c2dce4db77467e/MyocardialPerfusionImaging/MyocardialPerfusionImagingLib/dicomexport.py#L545-L550): The save dialog only selects and checks the first path. When a second monitor window is captured, the automatically constructed _2.png path can already exist, and saving it overwrites that unrelated prior screenshot without an overwrite confirmation. Check every generated output path before writing and ask before replacing any existing file, or use collision-free filenames.
- [`MyocardialPerfusionImaging/MPIGatedQC.py:243-249`](https://github.com/4burakfe/SlicerMyocardialPerfusionImaging/blob/1362f8524f5fb6be045df440c5c2dce4db77467e/MyocardialPerfusionImaging/MPIGatedQC.py#L243-L249): The UI's show() calls gatedStudy().build() synchronously, fitting and reslicing each frame before returning to the event loop. For large gated sequences the interface can appear frozen, with no per-frame progress or cancellation. Move computation off the GUI thread where safe, or provide responsive per-frame progress and cancellation.
- [`MyocardialPerfusionImaging/MyocardialPerfusionImaging.py:34-36`](https://github.com/4burakfe/SlicerMyocardialPerfusionImaging/blob/1362f8524f5fb6be045df440c5c2dce4db77467e/MyocardialPerfusionImaging/MyocardialPerfusionImaging.py#L34-L36): Loading the extension changes import precedence for the whole Slicer process, including other extensions, and can cause name collisions if another module uses the same top-level names. Use Slicer's normal module paths and uniquely named packages without prepending to sys.path, where possible.
- [`MyocardialPerfusionImaging/MPIGated.py:630-634`](https://github.com/4burakfe/SlicerMyocardialPerfusionImaging/blob/1362f8524f5fb6be045df440c5c2dce4db77467e/MyocardialPerfusionImaging/MPIGated.py#L630-L634): DEFAULT_EF_REFERENCE is actually 'fixed', and the combo selects that constant. A user relying on the tooltip may believe whole-heart motion is removed when the selected fixed reference instead incorporates that motion into regional EF. Align the displayed default, the constant, and the documented interpretation.
- [`MyocardialPerfusionImaging/MyocardialPerfusionImaging.py:78-79`](https://github.com/4burakfe/SlicerMyocardialPerfusionImaging/blob/1362f8524f5fb6be045df440c5c2dce4db77467e/MyocardialPerfusionImaging/MyocardialPerfusionImaging.py#L78-L79): Every module in this extension (`MyocardialPerfusionImaging.py` and the step modules) connects `_installToolbar` to `startupCompleted()`, which instantiates `WorkflowToolbar` (`MyocardialPerfusionImagingLib/toolbar.py` lines 278-324) at Slicer startup for all users, even if the user never opens the Myocardial Perfusion Imaging module. While the toolbar hides itself when another module is active, `WorkflowToolbar.__init__` also attaches persistent `EndCloseEvent` and `EndImportEvent` observers to `slicer.mrmlScene` that call `resetToStart()`. `resetToStart()` creates/modifies a singleton `vtkMRMLScriptedModuleNode` (`MPISession`) in the scene on every scene import or close across the entire Slicer session. Creating toolbar widgets and scene observers should be deferred until the user actually enters the module. Install the workflow toolbar and register scene observers lazily when `MyocardialPerfusionImagingWidget.enter()` (or `setup()`) is first called rather than on Slicer's `startupCompleted()` signal.
