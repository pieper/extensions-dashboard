- [`FiducialsToModelDistance/FiducialsToModelDistance.py:135-143`](https://github.com/ReynoldsJ20/SlicerFiducialsToModelDistance/blob/9ba774a39460fac85da215c5cfbbb19881094d6b/FiducialsToModelDistance/FiducialsToModelDistance.py#L135-L143): compute() is called directly from the button slot; the nested loops in pointDistancesLabelsFromPoints (lines 177-191) are O(n*m) and the surface path builds a vtkImplicitPolyDataDistance over the full mesh. With large fiducial sets or dense models Slicer freezes with no progress bar and no way to cancel, which looks like a crash to the user. Use slicer.util.ProgressDialog / a CLI-style progress callback, or run the computation in a worker thread with progress and cancellation.
- [`FiducialsToModelDistance/FiducialsToModelDistance.py:252`](https://github.com/ReynoldsJ20/SlicerFiducialsToModelDistance/blob/9ba774a39460fac85da215c5cfbbb19881094d6b/FiducialsToModelDistance/FiducialsToModelDistance.py#L252): The distances table is cleared with RemoveAllColumns() (line 247) but the metrics table is only passed to slicer.util.updateTableFromArray, which adds/overwrites the named columns without removing others. If a user first computes fiducial-to-model metrics (Mean Absolute Distance, Maximum Absolute Distance, ...) and then fiducial-to-fiducial metrics into the same table, the absolute-distance columns remain and the table mixes results from two different runs. Call outputMetricsTable.RemoveAllColumns() (or reset the table) before writing the new metrics.
- [`FiducialsToModelDistance/FiducialsToModelDistance.py:228-233`](https://github.com/ReynoldsJ20/SlicerFiducialsToModelDistance/blob/9ba774a39460fac85da215c5cfbbb19881094d6b/FiducialsToModelDistance/FiducialsToModelDistance.py#L228-L233): compute() dereferences inputReference and inputPoints without None checks; the GUI selectors have noneEnabled=false so the normal path is safe, but the logic class is public API and the test calls it directly. A None input produces an AttributeError that is only caught by the generic handler in onApplyButton, giving a confusing message. Validate that inputPoints and inputReference are not None and raise a clear ValueError.
- [`README.md:8-15`](https://github.com/ReynoldsJ20/SlicerFiducialsToModelDistance/blob/9ba774a39460fac85da215c5cfbbb19881094d6b/README.md#L8-L15): README.md only describes the purpose and shows two screenshots; there is no step-by-step tutorial, no sample scene, and no statement about intended (research) use. - [`FiducialsToModelDistance/FiducialsToModelDistance.py:263-264`](https://github.com/ReynoldsJ20/SlicerFiducialsToModelDistance/blob/9ba774a39460fac85da215c5cfbbb19881094d6b/FiducialsToModelDistance/FiducialsToModelDistance.py#L263-L264): 'Minimum Distance' is computed from signed values (line 264) while 'Maximum Absolute Distance' is used for the surface case, so users get a negative minimum that is not explained in the UI or README. This is confusing for clinical error reporting. Document the sign convention in the help text, or report absolute values consistently.
- [`FiducialsToModelDistance/FiducialsToModelDistance.py:200-213`](https://github.com/ReynoldsJ20/SlicerFiducialsToModelDistance/blob/9ba774a39460fac85da215c5cfbbb19881094d6b/FiducialsToModelDistance/FiducialsToModelDistance.py#L200-L213): vtkImplicitPolyDataDistance returns signed distances whose sign depends on surface orientation, so for open or inconsistently oriented meshes the 'Mean Distance'/'Minimum Distance' values can be misleading while the absolute variants are fine. This is a documented-behaviour caveat rather than a crash, but the module presents signed values without any note. Document that signed distances depend on mesh orientation and that absolute metrics should be used for open surfaces.
