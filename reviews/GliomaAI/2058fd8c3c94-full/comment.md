Please fix these before the extension can be merged:

- [`GliomaClassifier/CMakeLists.txt:35-39`](https://github.com/xristosand/SlicerGliomaAI/blob/2058fd8c3c9473112ca8c52721a00865672b0b35/GliomaClassifier/CMakeLists.txt#L35-L39): The install rule puts models beneath GliomaClassifier/Resources, whereas GliomaClassifier.py lines 949–966 resolves them as Resources/Models relative to the script directory. In a standard scripted-module installation the script is in the parent qt-scripted-modules directory, so the bundled default classifier and skull-strip model are not found. The same lookup also places optional downloads outside the module resource directory. Resolve models using Slicer's module resource path, and put optional downloaded models in a writable user cache; test an installed package.

Smaller suggestions:

- [`GliomaClassifier/PreProcessing/apply_classification.py:17`](https://github.com/xristosand/SlicerGliomaAI/blob/2058fd8c3c9473112ca8c52721a00865672b0b35/GliomaClassifier/PreProcessing/apply_classification.py#L17): When the user runs classification with the default H5 model (`proposed_model_final.h5`), `ensure_tensorflow_installed()` immediately calls `slicer.util.pip_install("tensorflow==2.19.1")` without asking the user for confirmation. TensorFlow is a very large download (hundreds of megabytes) that also pulls in or updates shared Python packages in Slicer's environment (such as `numpy`, `h5py`, `protobuf`, etc.), which can block the GUI thread for a long time and potentially alter packages bundled by Slicer. Prompt the user with `slicer.util.confirmOkCancelDisplay` before installing `tensorflow==2.19.1` (and `nipreps-synthstrip` in `apply_skull.py`), or consider converting `proposed_model_final.h5` to PyTorch/TorchScript or ONNX so the extension only needs the declared `PyTorch` dependency.
- [`GliomaClassifier/GliomaClassifier.py:1022-1034`](https://github.com/xristosand/SlicerGliomaAI/blob/2058fd8c3c9473112ca8c52721a00865672b0b35/GliomaClassifier/GliomaClassifier.py#L1022-L1034): In `GliomaClassifierLogic.process()`, `suffix` is only initialized if `applyRAS` is `True`. If the user runs preprocessing with `applyRAS` unchecked (whether or not other options are checked), `suffix += ...` or `inputVolume.GetName() + suffix` raises `UnboundLocalError: cannot access local variable 'suffix' where it is not associated with a value`. Initialize `suffix = ""` before the `if applyRAS:` block.
- [`GliomaClassifier/GliomaClassifier.py:748-752`](https://github.com/xristosand/SlicerGliomaAI/blob/2058fd8c3c9473112ca8c52721a00865672b0b35/GliomaClassifier/GliomaClassifier.py#L748-L752): If a scene already contains an unrelated scalar volume with the derived name, it is reused; lines 754–757 replace its image array and orientation with the heatmap. This can destroy unsaved image data or lead the user to save the replacement over their data. Create a new uniquely named output node, or reuse only a node explicitly recorded as this module's own generated heatmap.
- [`GliomaClassifier/PreProcessing/apply_skull.py:12-17`](https://github.com/xristosand/SlicerGliomaAI/blob/2058fd8c3c9473112ca8c52721a00865672b0b35/GliomaClassifier/PreProcessing/apply_skull.py#L12-L17): First use of skull stripping installs an unpinned package and its dependencies into the shared environment without a user confirmation. Its dependency metadata was not available here, so effects on PyTorch or Slicer-bundled packages cannot be established. Ask before installation and verify the package's dependency requirements do not install PyTorch outside PyTorchUtils or disrupt bundled packages.
- [`GliomaClassifier/GliomaClassifier.py:1295-1300`](https://github.com/xristosand/SlicerGliomaAI/blob/2058fd8c3c9473112ca8c52721a00865672b0b35/GliomaClassifier/GliomaClassifier.py#L1295-L1300): `GliomaClassifierTest.test_GliomaClassifier1` still contains the boilerplate threshold test from the Slicer module template. It calls `logic.process(inputVolume, outputVolume, threshold, True)` where the boolean parameters `applyRAS`, `applySkullStrip`, and `applyN4` receive `outputVolume`, `100`, and `True`, and then asserts that `outputVolume` (which `process()` does not write to) was thresholded to `100`. This test will fail when run. Update `test_GliomaClassifier1` to call `logic.process()` with boolean flags and check the returned volume node.
- [`GliomaClassifier/GliomaClassifier.py:969-974`](https://github.com/xristosand/SlicerGliomaAI/blob/2058fd8c3c9473112ca8c52721a00865672b0b35/GliomaClassifier/GliomaClassifier.py#L969-L974): Optional models downloaded at runtime by `model_manager.ensure_model()` are saved directly into `moduleDir/Resources/Models`. When Slicer is installed in a system or read-only directory (e.g. `/opt` or `C:\Program Files`), writing into the installed module folder can fail with `PermissionError`, and any downloaded models will be wiped when the extension is updated. Store downloaded models in a user-writable cache directory (for example under `slicer.app.cachePath`) rather than the installed module's `Resources/Models` directory.
- [`GliomaClassifier/GliomaClassifier.py:38-40`](https://github.com/xristosand/SlicerGliomaAI/blob/2058fd8c3c9473112ca8c52721a00865672b0b35/GliomaClassifier/GliomaClassifier.py#L38-L40): The module sets `self.parent.categories` to `"Examples"`, whereas `CMakeLists.txt` and the catalog entry use `"Neuroimaging"` and `README.md` instructs users to open `Informatics > GliomaAI`. Users following the README or looking under Neuroimaging will not find the module there. Set `self.parent.categories = [translate("qSlicerAbstractCoreModule", "Neuroimaging")]` (or `"Informatics"`) to match the documentation and catalog entry.
