Please fix these before the extension can be merged:

- [`GliomaClassifier/PreProcessing/apply_classification.py:15`](https://github.com/xristosand/SlicerGliomaAI/blob/3ff5b4b649f46e36de1dac42eadc9349e09a9ff8/GliomaClassifier/PreProcessing/apply_classification.py#L15): Instead of using the Slicer `PyTorch` extension (`PyTorchUtils`) to check and install PyTorch with hardware-appropriate wheels and user confirmation, `ensure_torch_installed()` directly calls `slicer.util.pip_install("torch")` from PyPI without user confirmation. Additionally, `nipreps-synthstrip` (`apply_skull.py` line 16) also declares `torch` as a pip dependency and can pull PyPI `torch` if PyTorch is not yet installed. Per the Slicer Extensions Index review policy, PyTorch must be installed exclusively via `PyTorchUtils` from the `PyTorch` extension. Use `PyTorchUtils.PyTorchUtilsLogic()` from the Slicer `PyTorch` extension to check for and install PyTorch (and ensure PyTorch is installed via `PyTorchUtils` before installing `nipreps-synthstrip`). Add `"PyTorchUtils"` to `self.parent.dependencies` in `GliomaClassifier`.
- [`GliomaClassifier/PreProcessing/apply_classification.py:15-20`](https://github.com/xristosand/SlicerGliomaAI/blob/3ff5b4b649f46e36de1dac42eadc9349e09a9ff8/GliomaClassifier/PreProcessing/apply_classification.py#L15-L20): When TensorFlow is not installed, `ensure_tensorflow_installed()` runs `slicer.util.pip_install("tensorflow==2.13.0")` without asking the user for confirmation before downloading hundreds of megabytes. Furthermore, `tensorflow==2.13.0` strictly pins `numpy<=1.24.3` and `typing-extensions<4.6.0`, which downgrades Slicer's bundled `numpy` and conflicts with PyTorch's requirement (`typing_extensions>=4.10.0` in the same file at line 42), breaking Slicer's shared Python environment and Note: `tensorflow==2.13.0` also has no wheels for Python 3.12 (used in Slicer 5.9+). Prompt the user via `slicer.util.confirmOkCancelDisplay` before installing large packages like TensorFlow or SynthStrip, avoid hard-pinning old TensorFlow versions (`tensorflow==2.13.0`) that downgrade Slicer's bundled `numpy` or conflict with `typing_extensions`, and ensure compatibility with Slicer's Python version.

Smaller suggestions:

- [`GliomaClassifier/CMakeLists.txt:5-18`](https://github.com/xristosand/SlicerGliomaAI/blob/3ff5b4b649f46e36de1dac42eadc9349e09a9ff8/GliomaClassifier/CMakeLists.txt#L5-L18): `GliomaClassifier.py` imports `from PreProcessing import model_manager` (line 636) when running classification, and `model_manager.ensure_model` is used to download and verify the ResNet10, ResNet50, and DenseNet121 models. However, `PreProcessing/model_manager.py` is omitted from `MODULE_PYTHON_SCRIPTS` in `GliomaClassifier/CMakeLists.txt`, so it will not be installed in packaged builds and classification will fail with `ImportError: cannot import name 'model_manager' from 'PreProcessing'`. Add `PreProcessing/model_manager.py` to `MODULE_PYTHON_SCRIPTS` in `GliomaClassifier/CMakeLists.txt`.
- [`GliomaClassifier/CMakeLists.txt:34-38`](https://github.com/xristosand/SlicerGliomaAI/blob/3ff5b4b649f46e36de1dac42eadc9349e09a9ff8/GliomaClassifier/CMakeLists.txt#L34-L38): GliomaClassifierLogic constructs its model paths relative to the directory containing GliomaClassifier.py, under Resources/Models (GliomaClassifier.py:947-965), but this rule installs them under an additional GliomaClassifier/Resources directory. Thus the installed default classifier and skull stripping cannot find their bundled models at their expected paths; optional models are also cached under the script directory, which may not be writable. Install bundled models where the module resolves them, or consistently resolve the actual install location, and use a writable user cache for optional downloads.
- [`GliomaClassifier/GliomaClassifier.py:633-636`](https://github.com/xristosand/SlicerGliomaAI/blob/3ff5b4b649f46e36de1dac42eadc9349e09a9ff8/GliomaClassifier/GliomaClassifier.py#L633-L636): GliomaClassifier/CMakeLists.txt:5-18 lists the other PreProcessing files but not model_manager.py, and its only separate install rule copies Resources/Models. Consequently a packaged installation cannot import this helper when any classification is run, even if the included model is selected. This is a runtime packaging bug, not a failure to configure the catalog entry. Add PreProcessing/model_manager.py to MODULE_PYTHON_SCRIPTS and test the installed package, not only the source checkout.
- [`GliomaClassifier/GliomaClassifier.py:1020-1032`](https://github.com/xristosand/SlicerGliomaAI/blob/3ff5b4b649f46e36de1dac42eadc9349e09a9ff8/GliomaClassifier/GliomaClassifier.py#L1020-L1032): In `GliomaClassifierLogic.process()`, `suffix` is only initialized if `applyRAS` is `True`. If the user runs preprocessing with `applyRAS` unchecked (for example, selecting only Skull Stripping, N4, or Normalization, or none of them), accessing `suffix` raises `UnboundLocalError: cannot access local variable 'suffix' where it is not associated with a value`. Initialize `suffix = ""` before `if applyRAS:`.
- [`GliomaClassifier/GliomaClassifier.py:746-754`](https://github.com/xristosand/SlicerGliomaAI/blob/3ff5b4b649f46e36de1dac42eadc9349e09a9ff8/GliomaClassifier/GliomaClassifier.py#L746-L754): If an unrelated loaded scalar volume is already named like the input plus _GradCAM, requesting XAI replaces its image data without confirmation.
