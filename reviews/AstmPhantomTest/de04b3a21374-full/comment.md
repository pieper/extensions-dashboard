Suggestions for a later update:

- [`AstmPhantomTest/AstmPhantomTestClasses/Pointer.py:183`](https://github.com/Atracsys/SlicerAstmPhantomTest/blob/de04b3a2137407f38eff5f468a1331975a364b5e/AstmPhantomTest/AstmPhantomTestClasses/Pointer.py#L183): After the initial connection check, a pointer-to-phantom update is accepted based only on PointerToTracker status. If the phantom is missing while the pointer remains tracked, an invalid or stale relative transform can enter the acquisition queue and affect measured points; the red status display does not itself halt acquisition. This is non-blocking correctness feedback. Require valid status for the phantom and relative transforms as well, and abort or pause an active acquisition on tracking loss.
- [`AstmPhantomTest/AstmPhantomTestClasses/Phantom.py:193-199`](https://github.com/Atracsys/SlicerAstmPhantomTest/blob/de04b3a2137407f38eff5f468a1331975a364b5e/AstmPhantomTest/AstmPhantomTestClasses/Phantom.py#L193-L199): Similarity registration permits scale as well as rigid alignment. The resulting transform is applied to all CMM ground-truth points, and the scaled points are subsequently used for multi-point distance comparisons; a tracker scale error can therefore be partly absorbed into the reference and underreported. This is non-blocking correctness feedback. Use rigid registration for the physical phantom reference, or justify and validate scaling separately and compare distances against the original CMM geometry.
- [`AstmPhantomTest/AstmPhantomTestClasses/Phantom.py:28-34`](https://github.com/Atracsys/SlicerAstmPhantomTest/blob/de04b3a2137407f38eff5f468a1331975a364b5e/AstmPhantomTest/AstmPhantomTestClasses/Phantom.py#L28-L34): Opening the module initializes Phantom and removes the first existing node named phantCalibTransfo, even if it belongs to the user's current scene. Unsaved transform data can be lost. Similar name-based deletion occurs for model and connector nodes. Keep references to nodes created by this module and remove only those it owns; let Slicer assign unique names when existing nodes conflict.
- [`AstmPhantomTest/AstmPhantomTest.py:121-131`](https://github.com/Atracsys/SlicerAstmPhantomTest/blob/de04b3a2137407f38eff5f468a1331975a364b5e/AstmPhantomTest/AstmPhantomTest.py#L121-L131): When the module widget is initialized (`setup`), it immediately blocks on a modal `QFileDialog.exec()`, resizes and maximizes the Slicer main window (lines 73-75), attaches a `FileHandler` to the root Python logger (`logging.getLogger().addHandler(fh)`) without removing it on cleanup, and starts an OpenIGTLink client connector on the default localhost port (`self.cnode.Start()`). Furthermore, if the user cancels the file dialog (`self.saveDialog.exec()` returns 0), `self.logic`, UI signal connections, and the OpenIGTLink connector are never initialized, leaving the module UI in a broken/unresponsive state for the rest of the Slicer session. Avoid blocking modal dialogs, root logger mutations, and main window resizing inside `setup()`. Provide a directory selector widget (e.g., `ctkDirectoryButton`) in the module UI to choose the output folder and start the session explicitly.
- [`AstmPhantomTest/AstmPhantomTestClasses/Pointer.py:279-285`](https://github.com/Atracsys/SlicerAstmPhantomTest/blob/de04b3a2137407f38eff5f468a1331975a364b5e/AstmPhantomTest/AstmPhantomTestClasses/Pointer.py#L279-L285): In `Pointer.staticTimerCallback`, when no samples were collected during the point-acquisition timer duration, the code instantiates `msgBox` but then references `msgBoxsgBox` on the next three lines, raising a `NameError` instead of displaying the warning dialog to the user. Replace `msgBoxsgBox` with `msgBox` on lines 282-284.
