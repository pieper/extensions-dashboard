Suggestions for a later update:

- [`README.md:3-6`](https://github.com/4burakfe/SlicerDICOMCBCTRecon/blob/fdc8d856a39562bd282e1d204896297b070ec05f/README.md#L3-L6): The README documents the workflow, the DICOM tags used for geometry, the GE private calibration, the reconstruction methods with literature references, the vendor-orientation troubleshooting steps and how to run the tests, and the module ships a synthetic phantom plus a self test. What is missing is any statement that the output is not validated for clinical use: the module produces HU-like volumes from vendor data and offers no accuracy claim or disclaimer, which matters for a tier-1 tool that will be used on patient studies. Add a short research-use / not-for-clinical-decisions disclaimer and state what validation exists (synthetic phantom only).
- [`DICOMCBCTRecon/DICOMCBCTRecon.py:42-44`](https://github.com/4burakfe/SlicerDICOMCBCTRecon/blob/fdc8d856a39562bd282e1d204896297b070ec05f/DICOMCBCTRecon/DICOMCBCTRecon.py#L42-L44): Importing the module mutates the shared interpreter's sys.path for the whole Slicer session, inserting the module directory at position 0. Any file in that directory would then shadow a stdlib or site-packages module of the same name for every other extension. The directory currently holds only DICOMCBCTRecon.py and DICOMCBCTReconLib/, so the practical risk is low, and Slicer already puts scripted-module directories on sys.path, making this largely redundant. Drop the sys.path manipulation and rely on Slicer's scripted-module path handling, or append instead of insert at position 0.
- [`DICOMCBCTRecon/DICOMCBCTRecon.py:259-262`](https://github.com/4burakfe/SlicerDICOMCBCTRecon/blob/fdc8d856a39562bd282e1d204896297b070ec05f/DICOMCBCTRecon/DICOMCBCTRecon.py#L259-L262): When the user presses Cancel, or when ensureDependencies() fails, the DICOM plugin's load() returns None. Slicer's DICOM browser treats a None return as a failed load and typically reports an error to the user, so a deliberate cancellation is presented as a load failure. The dependency-missing path already shows its own message, so the extra browser error is redundant and confusing. Return a sentinel the browser accepts, or suppress the browser's error for the deliberate-cancel path.
- [`DICOMCBCTRecon/DICOMCBCTReconLib/reconstruction.py:85-86`](https://github.com/4burakfe/SlicerDICOMCBCTRecon/blob/fdc8d856a39562bd282e1d204896297b070ec05f/DICOMCBCTRecon/DICOMCBCTReconLib/reconstruction.py#L85-L86): A user who selects "Fixed value" and enters 0 (or a value that evaluates falsy) silently falls through to the 99.9th-percentile estimate instead of using the entered value, so the log line "I0 = ..." reports a number the user did not choose. The spin box minimum is 1.0 so 0 is not reachable through the UI, which keeps the practical impact small. Test `manualValue is not None` instead of truthiness.
- [`DICOMCBCTRecon/DICOMCBCTRecon.py:46-49`](https://github.com/4burakfe/SlicerDICOMCBCTRecon/blob/fdc8d856a39562bd282e1d204896297b070ec05f/DICOMCBCTRecon/DICOMCBCTRecon.py#L46-L49): Both caches are module-level dicts that are written in examineFiles and never cleared, so they grow for the lifetime of the Slicer session and keep geometry dicts (per-frame numpy arrays) alive for every run ever examined. The sweep lookup is keyed by (filePath, loadable.name), and the name is built from series description plus run label, so two files with the same description and instance number would collide and the wrong sweep could be reconstructed. The comment shows the author knows Qt-wrapped loadables lose attributes, which is why the side table exists. Clear both dicts at the start of each examine() pass, or key the sweep on the loadable object identity / a per-examine token instead of a name string.
- [`DICOMCBCTRecon/DICOMCBCTReconLib/dialog.py:543-544`](https://github.com/4burakfe/SlicerDICOMCBCTRecon/blob/fdc8d856a39562bd282e1d204896297b070ec05f/DICOMCBCTRecon/DICOMCBCTReconLib/dialog.py#L543-L544): FDK and SART run on the GUI thread and pump the Qt event loop from the progress and log callbacks. The modal dialog plus the BusyDialogGuard and the `if self.busy: return` guard in onApply limit re-entrancy, but any other queued event (scene changes, other module callbacks, timers) is still dispatched while a multi-minute reconstruction holds the interpreter, and a second Reconstruct click is only prevented by the disabled button. This is a common Slicer pattern but is the weakest point for responsiveness and re-entrancy. Consider running the reconstruction in a worker thread (or at least a slicer.util.ProgressDialog with a queued abort flag) so the event loop is not re-entered from inside the computation.
- [`DICOMCBCTRecon/DICOMCBCTRecon.py:180-181`](https://github.com/4burakfe/SlicerDICOMCBCTRecon/blob/fdc8d856a39562bd282e1d204896297b070ec05f/DICOMCBCTRecon/DICOMCBCTRecon.py#L180-L181): For every candidate sweep, examineFiles calls _matchingRuns, which enumerates every file of every series in the study and, for each one that passes the cheap modality/numberOfFrames check, parses its header with pydicom to look for a matching trajectory. On a study with many series (or many single-frame XA objects) this makes the DICOM browser's examine step read a large number of headers synchronously, which can stall the browser. Results are memoised in the `summaries` dict within one examineFiles call, which limits but does not remove the cost. Restrict the scan to series whose modality is XA/XRF/RF and whose NumberOfFrames is large, using the DICOM database before reading any header.
- [`DICOMCBCTRecon/CMakeLists.txt:30-33`](https://github.com/4burakfe/SlicerDICOMCBCTRecon/blob/fdc8d856a39562bd282e1d204896297b070ec05f/DICOMCBCTRecon/CMakeLists.txt#L30-L33): Only the in-module self test (DICOMCBCTReconTest) is registered with CTest. The 300-line unittest suite in Testing/Python/test_cbct_reconstruction.py, which covers FDK accuracy, Parker weights, the GE calibration fit and SART, is never run by the extension build, so regressions in the reconstruction maths would not be caught by CI. Add a second slicer_add_python_unittest (or a plain add_test) for Testing/Python/test_cbct_reconstruction.py so the numeric tests run in the extension build.
